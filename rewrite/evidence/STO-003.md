# STO-003 Evidence

## Functional Substitution And Correctness

Eight focused STO-003 tests, six INT-001 tests, and all 163 accumulated rewrite
tests pass. The reference array reader/writer adapters agree bitwise with direct
STO-001 gather/scatter for translated regions and reordered selectors. Frozen
descriptors validate shape, callable, alias-array, writability, and callback
return behavior, including descriptors constructed without the factories.

A `CountingStorage` object proves that backend state need not itself be an
ndarray. Its explicit functions delegate selected transfers while the
descriptor exposes the underlying arrays for alias checks. The complete M0
executor runs through those functions with a read-only memmap source and
functional result writers.

The retained integration comparison uses 128 level-1 blocks, repeated local
fields, physical/sibling halos, and all five M0 outputs. The existing bounded
array path at capacity 27 and the functional full-capacity resident strategy at
capacity 128 produce bit-identical pointwise, stencil, native, zero-order, and
trilinear arrays plus a bit-identical reduction. Full capacity makes exactly one
real reader call in each of the two passes, in addition to empty preflight; each
writer receives one empty and one real call. Source data is unchanged.

The stable `execute_level1_m0(...)` array operation now constructs the
reference descriptors and delegates to `execute_level1_m0_from_blocks(...)`.
All previous invalid-input, overlap, preflight, overwrite, capacity, and
numerical INT tests still pass.

## Adapter Overhead And End-To-End Preservation

The retained Apple M1 adapter benchmark uses 31 repetitions. Direct STO-001 and
the array reader adapter both execute the same checked Cython transfer; the
additional functional dispatch is at the Python chunk boundary.

| Transfer | Direct | Adapter | Result |
| --- | ---: | ---: | ---: |
| one block, three fields, `8^3` | 15.62 us | 16.96 us | +1.33 us |
| 32 blocks, three fields, `8^3` | 22.71 us | 27.04 us | +4.33 us |
| 32 blocks, three fields, `16^3` | 111.46 us | 109.75 us | within timing noise, 28.66 GB/s |
| 32 blocks, three fields, `32^3` | 980.08 us | 903.71 us | within timing noise, 27.85 GB/s |

Adapter calls retain zero traced bytes and have the same fixed 1,536-byte traced
peak as the checked STO-001 boundary. The adapter allocates no payload-sized
temporary. Small transfers expose a low-microsecond dispatch cost; useful
transfers remain bandwidth dominated. No callback occurs in a Cython cell,
stencil, or block hot loop.

The repaired INT profiler now measures `read_blocks_into` and
`write_blocks_from` rather than assuming array gather/scatter symbols. A
three-repeat reproduction after integration measured warm runtimes of 10.66,
59.09, 17.53, and 12.33 ms for capacities 192, 27, 64, and 128 respectively;
all result-array comparisons and reduction-bit comparisons were true. These
values remain consistent with INT-001 evidence, so the new substitution
boundary introduces no material composed regression.

## Architectural Result

`numpy.memmap` is now one reference array backend rather than an executor
semantic dependency. Resident, mapped, native file, cached, or future framework
adapters can supply canonical chunks through explicit functions and state.
Numerical kernels, chunk plans, and halo functions remain unchanged.

HAL-001 and HAL-002 remain validated M0 primitives. The new durable functional
composition rules require M1 to add separate access requirements, support
planning, relation classification, same-level transfer, prolongation,
restriction, and periodic functions instead of extending HAL-002 into a hidden
mode dispatcher.
