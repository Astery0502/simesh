# STO-002 Evidence

## Correctness

Twelve focused tests and all accumulated rewrite tests pass. Exact budget tests
cover byte-boundary capacities. No-closure, direct-face-closure, and complete
one-block halo-closure plans match independent list or coordinate references for
counts, primary prefix, canonical support order, promotion, maximality,
uniqueness, suffix preservation, first-fit errors, clipped boundaries, and
exactly-once traversal. Boundary, singleton-axis, end-of-stream, invalid bool/
range/layout/writability/overlap, and insufficient-capacity cases are covered.

Independent review exhaustively checked 30,130 valid topology/start/capacity
combinations and found exact agreement and atomic behavior. TOP relation values
are required only for closure-enabled plans; no-closure streaming uses the table
only for its block count.

HAL-002 integration established that face-only closure omits the 20 diagonal
interiors needed by padded edge and corner cells. An independently reviewed
stable extension therefore retained the original planner and added complete
clipped `3x3x3` halo closure. A separate coordinate-based audit checked 99,738
valid shape/start/capacity cases through `6x5x4` and confirmed exact membership,
`dz/dy/dx` discovery, x/y/z face walking, promotion, maximality, atomicity,
suffix preservation, minimum capacity, and exactly-once traversal. No defect was
found. Capacity 27 is both the proven global maximum and a progress guarantee.

The out-of-core test creates canonical data directly in a `.npy` memory map,
reopens it read-only, and streams every block through one seven-slot payload and
ID workspace. The mapped payload is larger than the managed budget, the same
workspace object is reused, and the streamed exact sum matches the analytic
whole-dataset result without creating a resident full-payload ndarray.

## Planner Scaling

The planner benchmark traverses a `32^3` topology five times per result.

| Capacity | Closure | Chunks | Load amplification | Utilization | Mprimary/s |
| ---: | --- | ---: | ---: | ---: | ---: |
| 64 | no | 512 | 1.000 | 100% | 49.3 |
| 64 | faces | 1,797 | 3.457 | 98.5% | 3.86 |
| 64 | halo | 3,952 | 7.371 | 95.5% | 0.914 |
| 256 | no | 128 | 1.000 | 100% | 207.6 |
| 256 | faces | 293 | 2.279 | 99.6% | 2.24 |
| 256 | halo | 454 | 3.517 | 99.2% | 0.417 |
| 1,024 | no | 32 | 1.000 | 100% | 727.5 |
| 1,024 | faces | 55 | 1.702 | 99.0% | 0.950 |
| 1,024 | halo | 64 | 1.983 | 99.2% | 0.205 |

Face support amplification falls as neighboring primary closures overlap. The
initial planner scanned the entire selected prefix for membership; recognizing
the contiguous primary ID interval in O(1) and scanning only closure support
reduced full traversal time from 11.06 to 8.18 ms at capacity 64, 27.30 to
14.20 ms at 256, and 98.94 to 33.60 ms at 1,024 (up to 2.9x). A dense marker or
hash is therefore unnecessary for this direct-face policy. The complete halo
policy traverses the same 32,768 primaries in 35.87, 78.61, and 159.76 ms at
capacities 64, 256, and 1,024. Larger capacities reduce transfer amplification
but increase linear membership work; this simple caller-buffered planner is
already negligible beside the composed halo payload path, so no extra indexing
structure is justified.

## Out-Of-Core Runtime And Memory

The retained warm-cache benchmark maps 2,048 blocks with two `16^3` fields:

```text
mapped payload bytes = 134,217,728
budget bytes         =   2,097,152
slot capacity        =          31
managed array bytes  =   2,031,864
stream time          =      19.96 ms
payload throughput   =       6.73 GB/s
```

Managed bytes exactly equal the reusable payload plus ID array and stay below
budget; the mapped payload is about 66 times larger. Loop-only `tracemalloc`
shows a 3,176-byte peak and 1,568-byte retained increase. On this Darwin run the
warm traversal incurred 8,331 minor and zero major faults; raw process peak RSS
was 170,622,976 bytes.

RSS includes interpreter state, topology, workspace, file creation, and OS page
cache, so it is reported rather than claimed as a hard cap. `tracemalloc` also
does not observe NumPy buffers or mapped pages. The hard claim is limited to
exact managed-array bytes and absence of an eager full-payload allocation;
native pread can strengthen resident-set control later without changing plans.

Benchmark command:

```text
PYTHONPATH=rewrite/src .venv/bin/python rewrite/benchmarks/sto_002.py --capacities 64,256,1024 --memmap-blocks 2048 --budget-mib 2
```
