# RSL-001 Evidence

## Boundary And Correctness

RSL-001 owns one identity conversion: every active global source leaf in
accepted REL rows maps to its unique position in the STO-selected vector, while
inactive columns become exact `-1`.  It preserves `[P,D,4]` shape and source
order, requires accepted-row provenance `P<=S`, and fails atomically on the
first missing active source.  Kinds, masks, action filtering, target boxes,
geometry/reach, RST/PRL choice, workspace, payload, and scheduling remain
outside.  The five-question result is Green, and the shaped no-policy contract
passed independent review before implementation.

The production path uses two allocation-free linear passes after complete
validation: membership preflight, then full output fill.  Selected uniqueness
makes the first match exact.  The independent reference uses Python lists and
`.index`; neither implementation uses a hash, dense inverse, sort, bitmap, or
in-place REL conversion.

Ten focused tests cover selected permutations and primary/support slots;
repeated sources and exact trailing columns; all REL kinds without interpreting
them; `P<=S` including `D=0`; first/late missing-source atomicity; selected,
count, active/trailing corruption; empty/read-only/overlap behavior; random
balanced REL/STO windows; level-one HPL reduction; FINER/COARSER consumer probes;
and WENO bounded active roundtrip.

Independent implementation review approved validation/atomicity, the bounded
WENO lifecycle, no-hash reference/production paths, native consumer comparison,
and complete checked comparison accounting after two benchmark corrections.
Final runs pass 10 focused tests, 83 REL/STO/HPL integration tests, and all 523
accumulated rewrite tests.

## Kernel Scaling And Allocation

The only local optimization disables already-prevalidated Cython bounds and
wrap checks; it changes the large mixed baseline by about 3% and adds no state.
The standard synthetic case has `S=256`, `P=128`, `D=26`, 6,653 active sources,
13,312 tensor entries, and a 106,496-byte output.

| Path | Runtime ms | M active lookups/s | M tensor entries/s |
| --- | ---: | ---: | ---: |
| Checked | 0.817 | 8.140 | 16.287 |
| Unchecked fill | 0.389 | 17.088 | 34.192 |
| List reference | 17.406 | 0.382 | 0.765 |

Checked time is 2.10x unchecked because atomicity requires a complete membership
preflight and uniqueness/value validation before fill.  It is still 21.3x
faster than the reference.  All complete output arrays are exactly equal before
and after interleaved timing.  A checked call retains zero traced bytes and
peaks at 848 bytes.

The C counter records 854,305 selected comparisons in one lookup pass, 128.41
per active lookup per pass.  Checked execution performs 1,708,610 lookup
comparisons plus 32,640 selected-uniqueness comparisons, 1,741,250 identity
comparisons total.
At fixed mixed positions, increasing `S=57/64/128/512/1024` reduces unchecked
throughput from 77.4/65.2/32.9/10.3/5.55 million active lookups/s as comparisons
grow 29.0/32.5/64.4/256.8/513.6.  Accepted-row and direction/count scaling are
otherwise nearly flat.  First/middle/last/mixed source positions take
1.5/129.5/255.5/128.7 comparisons and 335.6/17.7/10.1/18.0 million lookups/s.
Linear selected position is the governing cost.

## Immediate Consumer And WENO

On the standard tensor, one unchecked materialization takes 0.400 ms and a
native copy across ten identity-only scans takes 0.021 ms.  Ten repeated native
unchecked resolutions take 3.919 ms.  The complete action-slot arrays are
equal, so one 106,496-byte bounded RSL artifact plus native reuse is 9.31x
faster for this immediate consumer without deciding kinds, targets, regions,
or values.

The WENO traversal uses sliding REL windows and accepted STO rows; no full REL
or RSL table is retained.  Every leaf is covered as primary, every relation row
is generated once, all 603,468 active sources roundtrip exactly, and cumulative
RSL writes equal 18,814,848 bytes at every capacity:

Larger chunks reduce support/load amplification but deepen linear lookup and
checked uniqueness work.  That capacity trade-off is handed to transfer
planning.  The fixed tensor already materially beats repeated lookup; compact
active offsets, inverse tables, slope/value fusion, and parallelism would add
new policy or memory without present evidence.  Optimization stops here.
