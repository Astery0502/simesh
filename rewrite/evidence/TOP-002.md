# TOP-002 Evidence

## Exact Contact Semantics And Lifecycle

TOP-002 implements only raw adjacent target-node lookup.  It accepts balanced
or unbalanced forests, assigns no relation kind, and retains no global topology
cache.  FST-002 runs first for each unchanged artifact lifecycle.

Eleven focused tests and all 232 accumulated rewrite tests pass.  All-level-1
faces reduce exactly to TOP-001.  Balanced fixtures freeze same, one-level
coarser, and subdivided/internal targets; an intentionally unbalanced fixture
returns a leaf two levels coarser without rejection.  All 26 directions over a
mixed multilevel forest agree exactly with an independent
`(level,coordinate)->node` dictionary/ancestor reference that never follows
production child pointers.

Tests cover root crossings, every child phase, faces/edges/corners, singleton
axes, repeated/reordered and empty queries, caller-owned fill, and mixed
physical directions.  A direction with one exterior component returns `-1`;
neutralizing that component produces the in-domain source, leaving mixed
operation planning to REL-001.  Late invalid source/direction rows, center,
dtype/shape, read-only output, and overlap all fail before mutation.

A maximum-level-63 fixture exercises the largest legal scale shift and complete
child descent; its positive neighbor and negative physical query match the
independent reference exactly.  Every test/benchmark artifact is validated by
FST-002 before lookup.

Current synthetic face kinds and one-based leaf IDs agree exactly for physical,
coarser, same, and finer cases.  On the real 22,614-leaf tree, all 135,684 face
queries match current kind classification with exact distribution:

```text
physical 3,430; coarser 11,488; same 117,894; subdivided 2,872.
```

The real header is staggered, so this remains topology metadata evidence only.

## Runtime, Memory, And Cache Boundary

Final Apple arm64 measurements use 15 repetitions and all 26 directions on one
uniformly refined root.

| Max level | Leaves | Queries | Lookup | Mcontact/s | FST→lookup lifecycle | Output bytes |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 1 | 1 | 26 | 9.37 us | 2.77 | 14.92 us | 208 |
| 2 | 8 | 208 | 8.79 us | 23.66 | 15.17 us | 1,664 |
| 3 | 64 | 1,664 | 16.87 us | 98.61 | 23.79 us | 13,312 |
| 4 | 512 | 13,312 | 98.38 us | 135.32 | 108.54 us | 106,496 |
| 5 | 4,096 | 106,496 | 0.910 ms | 117.03 | 0.949 ms | 851,968 |

Independent reference equality is retained through level four.  Caller output
is exactly `8*Q` bytes.  Checked lookup has a fixed 2,232--2,296-byte traced
peak and a fixed 120/184-byte allocator observation after return; the Cython
kernel allocates no scratch or leaf-sized state.

The real tree validates in 0.184 ms, answers faces in 1.634 ms at 83.06 million
contacts/s, and measures 1.804 ms for the actual validate-then-lookup lifecycle.
Its query output is 1,085,472 bytes.  Descriptive current construction is
17.61 ms; copying its already cached six type and ID columns takes 0.218 ms and
copies the same 1,085,472 bytes, while the complete current 27/64 topology
tables retain 10,673,808 bytes.

This quantifies the intended separation: on-demand TOP-002 avoids retained
leaf topology and is fast for one/few consumers; repeated face use can justify
optional TOP-003 only after comparing its exact `54*L` cache with this measured
lookup.  BAL-001 next consumes on-demand all-direction contacts and owns only
the level-gap policy.
