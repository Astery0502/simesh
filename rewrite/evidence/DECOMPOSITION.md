# Capability Decomposition Rule Evidence

## Review Result

Independent review agreed that every non-trivial capability needs a mandatory
five-question gate covering singular semantics, independent validation,
independent substitution, meaningful measurement, and separation of semantic
meaning from policy/execution. It also agreed that every independently variable
decision outside the stated responsibility belongs in an explicit semantic,
planning, policy, adapter, or execution boundary.

The rule deliberately preserves performance: conceptual function boundaries do
not require Python runtime calls, payload temporaries, or removal of Cython
inline/fused kernels. Large executors may own orchestration/resource strategy,
and fused kernels may implement already contracted semantics, provided the
simple composition remains available for conformance and benchmark comparison.

## Existing And In-Progress Work

FST-001 was audited as broadly conforming and is not reopened wholesale. Its
validation/fill phases support atomicity within one forest-reconstruction
meaning. A reusable artifact-conformance boundary should be added only when
multiple consumers demonstrate that need.

The untracked TOP-002 design/contract was created under the earlier rules and
must pass the new gate before implementation. Review identified full FST
artifact revalidation, contact location/classification, global 26-direction
two-to-one balance, and retained six-face topology materialization as candidate
independently variable decisions. The resumed capability must preserve the
draft work, decide which boundaries split (such as BAL-001 versus TOP-002), and
update the ledger/checkpoint before code begins.

Earlier nonconforming implementations use the progressive sequence in
`DECOMPOSITION.md`: freeze behavior, inventory decisions, extract one boundary
at a time, retain compatibility, prove equivalence, measure, migrate consumers,
then retire the mixed wrapper. This avoids both permanent coupled designs and a
big-bang rewrite of completed work.
