# PRI-001 Evidence

## Incremental STO-002 Refinement

PRI-001 extracts the topology-free dense ascending primary prefix from
STO-002's no-closure mode.  The legacy false-mode planner preserves its complete
face-table/output/first/bool/overlap/capacity validation order and returns
`(count,count)` after delegating the fill.  The direct-face `True` path and the
full-halo planner are unchanged for later capability boundaries.

The M0 pipeline's dry preflight and pass one now consume PRI directly from
`block_count` and the reusable ID vector.  Pass two remains on the full-halo
planner.  This is the first production consumer migration; existing RED/SAM/
OPR callers continue to exercise the compatibility wrapper.

Thirty-three focused tests, 62 PRI/STO/RED/INT integration tests, and all 381
accumulated rewrite tests pass.  Coverage includes exact maximal prefixes,
prior-buffer independence, bitwise suffix preservation, end no-op, unfinished
zero-capacity atomic error, Python/NumPy scalar kinds, exact validation
precedence/messages, output layout/writability, signed-int64 tail IDs,
exhaustive and randomized complete traversals, arbitrary ignored face values,
500 old/new conformance cases, WSP-derived capacity, and topology-free
STO-001+RED streaming with bit-identical ascending accumulation across six
capacities.

The independent Python-range reference covered 18,704 traversal chunks for
block counts through 100 and capacities through 19.  It also emits the final
signed-int64 IDs exactly.

## Runtime And Allocation

Final Apple arm64 measurements traverse 32,768 dense IDs with 15 repetitions:

| Capacity | Calls | Canonical M-ID/s | Compatibility M-ID/s | Canonical traversal |
| ---: | ---: | ---: | ---: | ---: |
| 1 | 32,768 | 1.74 | 1.11 | 18.86 ms |
| 8 | 4,096 | 14.11 | 8.82 | 2.32 ms |
| 64 | 512 | 110.49 | 71.26 | 0.297 ms |
| 256 | 128 | 438.12 | 279.07 | 74.79 us |
| 1,024 | 32 | 1,404.36 | 967.32 | 23.33 us |
| 32,768 | 1 | 7,281.72 | 6,780.08 | 4.50 us |

The retained STO benchmark, which includes its surrounding mode dispatch,
improves no-closure throughput from the pre-extraction 49.3/207.6/727.5 to
58.2/272.4/897.8 million IDs/s at capacities 64/256/1,024.  Face and full-halo
planner rates, chunk counts, amplification, and ordering are unchanged.

The checked PRI call retains zero traced bytes and has a fixed 248-byte traced
peak.  The kernel performs one sequential int64 store per ID and no
size-dependent scratch.  One full 32,768-ID call writes exactly 262,144 bytes.
Wrapper overhead is expected compatibility validation, while direct consumers
avoid the dummy 48-byte-per-block face descriptor.

## Composed Result

WSP's retained 2 MiB example supplies capacity 31, requiring 1,058 exact PRI
calls for 32,768 blocks.  The M0 INT benchmark reports the same capacities,
chunk counts, all five bitwise-equal result arrays, and bitwise-equal reduction
after migration.  PRI accounts for only microseconds in preflight/pass one;
warm executor times remain governed by unchanged full-halo pass two.

The canonical loop is already the minimal sequential fill, and the compatibility
path improved without altering behavior.  No further credible variant can
materially improve the runtime-memory-complexity trade-off without introducing
scheduling or arbitrary-ID machinery outside PRI's responsibility.
