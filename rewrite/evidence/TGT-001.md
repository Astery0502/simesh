## Performance, Memory, And Reuse

The standard asymmetric canonical-26 case writes exact `48*26 = 1,248` bytes:

| Path | Runtime us | Million directions/s |
| --- | ---: | ---: |
| Checked | 5.708 | 4.555 |
| Unchecked | 1.000 | 26.001 |
| Allocating Python reference | 29.333 | 0.886 |

Checked validation is 6.0x the sub-microsecond fill but remains 5.2x faster than
the allocating reference.  Complete lower/upper arrays remain exact before and
after interleaved timing.  A checked call retains zero traced bytes and peaks at
1,360 bytes.

`D=0/1/6/26` writes 0/48/288/1,248 bytes exactly; unchecked throughput reaches
1.143/6.857/26.001 million directions/s for nonempty cases.  Reversed canonical,
repeated/reordered `D=10`, and repeated canonical `D=52` remain exact at
29.715/11.429/54.281 million directions/s.

The native reuse comparison performs one unchecked materialization, then
100,000 `np.copyto` scans of both box arrays, versus 100,000 unchecked native
derivations into identically shaped outputs.  Creation takes 10.88 us; artifact
bytes are 1,248; creation plus scans takes 38.394 ms versus 80.378 ms repeated
derivation.  Full action arrays are equal, so materialize-once reuse is 2.09x
faster under equivalent native execution.

The artifact is tiny, exact, and already pays for reuse.  Further fusion with
phases/actions, predeclared full source boxes, dynamic dispatch, or parallelism
would broaden ownership without a credible benefit.  Optimization stops at the
bounded unchecked fill behind one checked lifecycle call.
