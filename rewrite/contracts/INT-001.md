# INT-001 Contract: Bounded Cartesian Level-1 Execution

## Responsibility

INT-001 is the concrete M0 executor. It composes the completed level-1
topology/storage/halo/sampling/operator/reduction contracts over a read-only
resident or memory-mapped source under an exact temporary-array budget. It
defines no new numerical kernel, file parser, field-name adapter, refinement,
2D behavior, periodicity, concurrency, or persistent object model.

## Stable Operation

```text
execute_level1_m0(
    backing,
    field_ids,
    domain_lower,
    domain_upper,
    domain_cell_counts,
    block_cell_counts,
    coord_to_rank,
    rank_to_coord,
    face_neighbor_ids,
    boundary_modes,
    normal_field_slots,
    pointwise_left_field,
    pointwise_right_field,
    pointwise_scale,
    stencil_field,
    stencil_axis,
    reduction_field,
    sample_lower,
    sample_upper,
    budget_bytes,
    pointwise_backing,
    stencil_backing,
    native_grid,
    zero_grid,
    trilinear_grid,
) -> (reduction_value, slot_capacity)
```

- `backing` is borrowed read-only C-contiguous
  `float64[N,nbacking,bx,by,bz]`; row is global block ID and its spatial shape
  equals `block_cell_counts`. A read-only `numpy.memmap` is supported directly.
- `field_ids` is borrowed C-contiguous `int64[F]` with `F>0` and defines local
  field order in all grids/workspaces. IDs may be reordered or repeated.
  Operator/reduction positions, `boundary_modes[F,6]`, and normal slots refer to
  this local order. Repeated backing fields may intentionally use different
  local boundary rows and therefore different near-boundary trilinear results.
- Geometry/maps/topology and sample/HAL inputs have their completed M0 contract
  representations.
- `pointwise_backing` and `stencil_backing` are caller-owned writable
  `float64[N,1,bx,by,bz]` result sinks.
- Native, zero-order, and trilinear outputs are caller-owned writable
  C-contiguous `float64[F,...]` arrays with SAM-001/SAM-002/SAM-003 shapes.
- `budget_bytes` is a nonnegative scalar integer covering temporary raw data
  buffers and the scalar reduction state.

All five result arrays are pairwise nonoverlapping and do not overlap backing or
metadata. Inputs are borrowed and retained nowhere. The returned capacity is a
Python integer; reduction is RED-001 final binary64 as a Python float.

## Exact Managed Budget

INT-001 uses symmetric one-cell padded shape `P = block_cell_counts + 2`. For
capacity `S`, managed temporaries are exactly:

```text
block_ids       int64[S]
payload         float64[S,F,Px,Py,Pz]
output_workspace float64[S,1,bx,by,bz]
sum_state       float64[1]
```

Therefore

```text
managed_bytes = 8*S*(F*product(P) + product(block_cell_counts) + 1) + 8.
```

Capacity is the largest `min(N, floor((budget_bytes-8)/bytes_per_slot))` that
fits, with zero when the state itself does not fit. Before allocation/mutation,
it must be at least `minimum_halo_closed_slots(face_neighbor_ids)`; otherwise
the call raises `ValueError`. Allocated bytes equal the formula and never exceed
the budget. Maps, topology, source mapping/page cache, caller-owned final
outputs, NumPy headers, fixed-size triplets, Python views, and validation call
objects are outside raw managed bytes. Those fixed/control allocations are
measured separately with traced peak/retained memory.

## Pass One: Zero-Reach And Streaming Work

PRI-001 ascending prefixes visit unique primary IDs exactly once. For each
prefix:

1. STO-001 gathers `field_ids` interiors into
   `payload[:primary_count, :, 1:1+B]` (no-closure selected equals primary).
2. OPR-001 computes the selected local fields into the reusable output workspace
   and STO-001 scatters it to `pointwise_backing`.
3. SAM-001 places all gathered local fields into `native_grid`.
4. SAM-002 writes each primary's canonical zero-order output ownership.
5. RED-001 updates one persistent `+0.0` state from the selected reduction field
   over the interior.

The reduction runs after only nonmutating consumers of the gathered payload and
visits the original selected local field over `[1,1+B)`. The state is initialized
once and no per-chunk partial or merge is used, so global block/x/y/z addition
order and result are capacity-invariant despite padded workspace storage.

## Pass Two: Halo-Dependent Work

STO-002 full-halo chunks select a primary prefix plus complete support closure.
For each chunk:

1. gather every selected interior into `payload[:selected_count]`;
2. apply HAL-001 to `payload[:selected_count]` physical envelopes;
3. apply HAL-002 to that selected array with `primary_count`, completing only
   the primary prefix;
4. OPR-002 computes over `payload[:primary_count]` into the reusable output
   workspace, and scatter uses only `block_ids[:primary_count]`;
5. SAM-003 samples only `payload[:primary_count]` and matching primary IDs.

Support slots are never scattered, sampled, placed, or reduced.

## Validation, Mutation, And Failure

Before allocating bulk workspaces or mutating a result, validate budget scalar
kind/range and exact arithmetic, source/output pairwise nonoverlap, and fixed
lower-capability type/layout/shape/field/mode/sample/region requirements.

Preflight then proceeds in this exact order:

1. an allocation-free full MOR inverse and face-table scan proving every row,
   physical sentinel, displacement, and reciprocal relation equals TOP-001;
2. capacity computation and closure sizing only after that topology proof;
3. allocation of the exact managed ID/payload/output/state raw buffers;
4. an actual-ID dry traversal of every PRI-001 prefix, invoking selected map/
   geometry validation on each primary set;
5. an actual-ID dry traversal of every full-halo chunk, validating unique full
   closure, selected primary geometry, and SAM-003 endpoint stencils.

Zero-slot lower public calls validate the remaining non-ID-dependent boundaries.
No result may be touched until both dry traversals complete successfully.

After successful preflight, lower calls retain their own atomicity. INT-001 is
not a rollback transaction for hardware/process failure, but no ordinary
contract error may occur after result mutation begins. Type/dtype/scalar-kind
failures raise `TypeError`; invalid budget, layout, field, geometry, map,
topology, HAL, sample, output, or overlap raises `ValueError`; unrepresentable
byte/count arithmetic raises `OverflowError`.

On successful return, pointwise and stencil backings are fully overwritten for
all global blocks, and native/zero/trilinear grids are fully overwritten for all
fields and output cells. No caller initialization value remains in any of the
five results.

## Numerical Evidence

INT-001 introduces no arithmetic. Each final artifact uses its producing
contract's metrics:

- pointwise/native/zero-order placement and bounded/full comparisons are
  bitwise where their lower contracts are exact;
- stencil and trilinear finite values use their absolute/relative/ULP and
  affine/convergence bounds, with discrete owners/indices exact;
- reduction must be bit-identical across capacities under persistent serial
  order and is compared descriptively with NumPy and accurately with
  `math.fsum`.

Retained integration evidence compares every result with an independently
composed full-resident reference and relevant current paths, includes reordered
fields and mixed block IDs, and verifies source/result preservation outside
declared writes.

## Performance And Completion Evidence

Measure total/two-pass runtime, throughput, per-stage runtime, managed bytes,
traced peak/retained allocation, capacity/chunk scaling, mapped-source page
faults, and final-output sizes. Compare useful capacities and stop when larger
temporary memory no longer materially improves composed runtime.

The boundedness claim is for managed raw workspace only, not process RSS. The
source mapping, OS page cache, topology/maps, Python runtime, and five final
outputs may all exceed `budget_bytes` and are reported separately.

INT-001 completes M0 when at least one read-only mapped source is larger than
the managed workspace, every final artifact matches its full-resident reference,
all established rewrite tests pass, and the ledger/checkpoint record M0 as
complete.
