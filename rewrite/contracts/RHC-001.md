# RHC-001 Contract: Synchronous Completed Refined-Primary Consumption

## Responsibility

RHC-001 exposes each fully halo-completed selected refined primary prefix to one
explicit synchronous coarse-grained consumer before the bounded workspace is
reused. It owns consumer representation, full-request RHE preflight, callback
order/lifetime/read-only views, and consumer statistics. It defines no new
topology/halo/numerical meaning, reader backend, consumer computation, output
or reduction semantics, cache, or parallel scheduling.

## Consumer Descriptor

```text
CompletedPrimaryConsumer(
    state,
    consume_completed,
    output_arrays=(),
)

make_completed_primary_consumer(
    state,
    consume_completed,
    *,
    output_arrays=(),
) -> CompletedPrimaryConsumer
```

The frozen descriptor retains only explicit state, a callable, and a tuple of
every mutable NumPy array that the consumer may write. Arrays merely read by
state remain the consumer's explicit responsibility; every mutable output must
be listed for RHC alias validation. Directly constructed descriptors are
revalidated. No global registry or hidden consumer mode exists.

The callback signature is

```text
consume_completed(
    state,
    input_primary_offset,
    primary_leaf_ids,
    completed_payload,
    payload_valid_lower,
    payload_valid_upper,
    interior_lower,
    interior_upper,
) -> None
```

`input_primary_offset` is the exact zero-based offset in the executor's input
primary selection. IDs are the exact ascending primary slice. Payload contains
only primary rows, never support-only rows, in canonical
`float64[P,F,x,y,z]`. All six ndarray arguments are non-writeable views for
the callback. Valid/interior boxes describe the complete padded workspace.

The callback is synchronous, may mutate only its declared state/output arrays,
returns exactly `None`, and may not retain any supplied view/pointer after
return. It is invoked once per nonempty completed primary prefix, after all
halo actions and before workspace reuse or the next reader call. There is no
empty consumer conformance call and no callback inside a Cython cell/block loop.

## Stable Executor And Statistics

```text
execute_selected_refined_halos_with_consumer(
    reader,
    consumer,
    primary_leaf_ids,
    field_ids,
    root_shape,
    coord_to_rank,
    root_node_ids,
    node_levels,
    node_coords,
    child_node_ids,
    node_leaf_ids,
    leaf_node_ids,
    lower_halo,
    upper_halo,
    boundary_modes,
    normal_field_slots,
    slot_capacity,
) -> CompletedPrimaryExecutionStats
```

Reader, selection, fields, FST/balance lifecycle, halo reach, PBC metadata, and
capacity have exact RHE-001 representations and supported scope. Success returns
exact Python integers:

```text
primary_count
chunk_count
reader_call_count
consumer_call_count
selected_load_count
maximum_selected_slots
managed_array_bytes
```

Counts exclude the one empty reader conformance call. Consumer calls equal
chunks. Managed bytes are exactly RHE-owned raw arrays; consumer output/state,
immutable metadata, backend page cache, and Python descriptor/view objects are
excluded and must be accounted by the consumer workflow.

## Validation, Mutation, And Failure

RHC reuses RHE-001's complete static validation, selected support/action
preflight for every chunk, workspace byte checks, and one empty reader call.
Before that call it additionally validates the exact consumer descriptor,
callable/output tuple, pairwise output-array nonoverlap, and output nonoverlap
with reader memory and RHE metadata. Ordinary RHC errors therefore cause no
nonempty read or consumer mutation.

During execution, each chunk follows exactly:

```text
selected read -> all RHE halo actions -> completed-primary callback -> reuse.
```

RHC mutates only private workspace. A reader failure leaves earlier consumer
calls but not the failed chunk. A consumer exception or non-`None` return stops
immediately and may leave that consumer's own output partially changed; earlier
chunks are not rolled back. Hardware/resource/process failures have no
transaction guarantee. Type/descriptor failures raise `TypeError`; invalid
layout, alias, selection, topology, halo, PBC, or capacity raises `ValueError`;
byte/index overflow raises `OverflowError`; backend/consumer exceptions
propagate except the explicit non-`None` `TypeError`.

## Conformance And Evidence

RHC introduces no numerical tolerance. Chunk IDs, offsets, valid/interior
boxes, read-only flags, calls, loads, stats, and managed bytes compare exactly.
Payload bits compare exactly with public RHE writer output. Evidence covers
empty/single/multiple chunks, nonzero input offsets, all refined relation/PBC
kinds, minimum/intermediate/full capacities, consumer state/output aliases,
direct descriptor corruption, view nonretention convention, exceptions and
return values, and reader failures.

The existing public `execute_selected_refined_halos_from_blocks` writer API,
empty writer callback, values, writer calls/IDs, stats, and failure behavior
remain unchanged. RPS-001 migrates from the prior private hook to RHC and must
retain exact point values/stats/capacity behavior. LFE-001 is the second concrete
consumer that justifies promotion.

## Performance And Immediate Composition

RHC-001 is `composition-only`. Measure descriptor/callback overhead through
RPS and LFE against the previous private/public RHE paths; the callback occurs
once per chunk, so no isolated repeated microbenchmark is useful. No material
RPS or public-RHE regression is accepted without an explicit memory/I/O benefit.

RPS consumes completed primaries for trilinear points. LFE consumes them for
per-slot geometry, curl, compact output, and serial reduction. A public async,
retained-view, generator, cache, or parallel consumer is a separate execution
strategy and cannot weaken this synchronous lifetime.
