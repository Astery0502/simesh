# GEO-001 Contract: Cartesian 3D Level-1 Block Geometry

## Responsibility

GEO-001 maps selected zero-based level-1 block IDs to Cartesian physical bounds
and defines uniform cell spacing and cell-center coordinates. It consumes
validated MOR/TOP maps but defines no topology, payload storage, halo values,
sampling, or refinement.

## Stable Operation

```text
fill_level1_block_geometry(
    domain_lower,
    domain_upper,
    domain_cell_counts,
    block_cell_counts,
    coord_to_rank,
    rank_to_coord,
    block_ids,
    block_bounds,
    cell_spacing,
) -> None
```

- Domain bounds are borrowed read-only native-endian C-contiguous `float64[3]`,
  finite, and strictly increasing componentwise.
- Cell-count triplets are borrowed read-only native-endian C-contiguous signed
  `int64[3]`, positive, and exactly divisible componentwise.
- `root_shape = domain_cell_counts // block_cell_counts`; its volume must fit
  signed `int64`.
- `coord_to_rank` and `rank_to_coord` have the exact MOR-001 shapes for that
  root shape and come from the validated TOP-001 composition.
- `block_ids` is borrowed read-only C-contiguous `int64[nslot]`. IDs may be
  empty, repeated, and in arbitrary order. Output row `s` represents global ID
  `block_ids[s]`.
- `block_bounds` is caller-owned writable C-contiguous
  `float64[nslot,2,3]`, with side zero lower and side one upper.
- `cell_spacing` is one caller-owned writable C-contiguous `float64[3]`; it is
  not repeated per block.

All input/output arrays and the two outputs are non-overlapping. Validation
completes before either output is mutated. Selected IDs, coordinates, and
`coord_to_rank[coordinate] == block_id` are checked in `O(nslot)`; the complete
maps are not rescanned for each chunk. On success both outputs are fully
defined, inputs are unchanged, and nothing is retained.

Type/dtype errors raise `TypeError`. Invalid bounds, counts, divisibility,
shapes, contiguity, writability, IDs, selected map consistency, collapsed
geometry, or overlap raise `ValueError`. Root-volume overflow raises
`OverflowError`.

## Coordinate Semantics

For axis `a`, binary64 operations define

```text
extent[a]  = domain_upper[a] - domain_lower[a]
spacing[a] = extent[a] / float(domain_cell_counts[a]).
```

Spacing must be finite, positive, and normal binary64 (not subnormal). Subnormal
spacing is rejected because accumulated rounding can no longer satisfy the
declared rational-reference error bound. For global integer cell-face index `g`:

```text
face(0)                     = domain_lower[a]
face(domain_cell_counts[a]) = domain_upper[a]
face(g)                     = domain_lower[a] + float(g) * spacing[a]
                               otherwise.
```

The first and last canonical cell centers on every axis must be finite and
strictly inside the supplied domain. This global `O(1)` representability check
rejects numeric domains whose cell centers collapse onto an outer face,
independently of which block IDs are selected. Selected block faces are also
required to remain strictly ordered. GEO does not promise that arbitrary
binary64 grids can represent every mathematical coordinate distinctly beyond
these checked conditions.

For selected block coordinate `c = rank_to_coord[block_id]`, exact integer
cell bounds are

```text
g0 = c * block_cell_counts
g1 = g0 + block_cell_counts,
```

and physical block bounds are `face(g0)` and `face(g1)`. Thus the same sibling
face is bit-identical across rows, selections, and calls, and outer faces equal
the supplied domain bounds exactly.

The center of interior local cell `i` uses global integer cell index
`q = c * block_cell_counts + i`:

```text
center = domain_lower + (float(q) + 0.5) * cell_spacing.
```

Consumers compute this formula inline; GEO-001 does not allocate center arrays.
SAM-001 uses exact integer `[g0,g1)` placement and never infers placement from
floating bounds. HAL-001 uses TOP sentinels, not float comparisons, to classify
physical boundaries.

## Numerical Evidence

Integer IDs, coordinates, and cell-face indices compare exactly. Binary64
outputs are deterministic for fixed inputs. Shared faces and supplied endpoints
compare bitwise exactly.

Against an independent exact-rational geometry reference, spacing uses relative
error at most `8*eps`. Bounds and derived centers use zero relative tolerance
and per-axis absolute tolerance

```text
8*eps*max(abs(domain_lower), abs(domain_upper), domain_extent).
```

The absolute tolerance has a floor of eight times the smallest positive
binary64 subnormal so the comparison bound itself cannot underflow to zero.

Current `rnode` values are compared with the same bound and the worst absolute,
cell-spacing-normalized, and ulp discrepancies are recorded rather than hidden.

## Performance And Memory

Validation and fill are `O(nslot)`, with fixed metadata work and no heap scratch
proportional to `N` or `nslot`. Bounds storage is `48*nslot` bytes plus one
24-byte spacing triplet. A full table remains possible by explicitly selecting
all IDs; no second full-N API or per-block spacing table is retained.

## Immediate Composition

TOP-001 supplies validated IDs and coordinates. HAL-001/HAL-002 consume spacing
and block faces, while SAM-001/SAM-002/SAM-003 consume exact integer placement,
physical bounds, and the global center formula.
