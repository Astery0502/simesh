# PRL-001 Contract: Cartesian 3D Ratio-Two Limited Prolongation

## Responsibility

PRL-001 reconstructs one explicit Cartesian 3D fine target box from an aligned
ratio-two coarse workspace using exact phase weights and LIM-001 axial slopes.
It defines no relation/support/source-slot meaning, target selection, coarse
workspace assembly/lifetime, RST placement, physical rule, backend, scheduling,
periodicity, or 2D behavior.

## Stable Operation

```text
prolong_cartesian_2to1_into(
    coarse_payload,
    coarse_valid_lower,
    coarse_valid_upper,
    coarse_origin,
    fine_payload,
    fine_lower,
    fine_upper,
    fine_origin,
) -> None
```

`coarse_payload` is borrowed read-only native-endian C-contiguous
`float64[S,F,cx,cy,cz]`.  `fine_payload` is caller-owned writable native-endian
C-contiguous `float64[S,F,fx,fy,fz]`.  Their slot and field extents match
exactly; zero slots or fields are valid.

The remaining inputs are borrowed read-only native-endian C-contiguous
`int64[3]` triplets.  Coarse validity and the fine target are FND-001 half-open
storage boxes.  `fine_origin` and `coarse_origin` identify one aligned pair:
fine index `fine_origin` is lower phase of coarse center `coarse_origin`, and
`fine_origin+1` is its upper phase.  Origins need not lie inside either box, but
all contracted mapping arithmetic must be signed-int64 representable.

## Exact Ratio-Two Mapping

For fine storage index `p` on each axis, compute in mathematical integers:

```text
r     = p - fine_origin
q     = floor(r / 2)
phase = r - 2*q                 # exactly 0 or 1
center_index = coarse_origin + q
eta   = -0.25 if phase == 0 else +0.25
```

Floor is mathematical floor, including negative `r`; C truncation toward zero
is not the contract.  Subtraction, doubled quotient, and coarse translation
must fit signed `int64`.  Eta is the exact binary64 literal selected by integer
phase; no physical coordinate, spacing, division, or weight array participates.

This intentionally differs from current physical-coordinate eta rounding.  On
the representative WENO geometry the mapped coarse indices are identical, but
current produces 27 eta bit patterns up to `2.842170943040401e-14` from exact
`+/-0.25`.  Dyadic cases may remain bitwise equal; non-dyadic current evidence
records numeric difference without redefining PRL weights.

For current-output comparison, production and the independent exact-phase
reference must be bitwise equal, and the selected zero-origin dyadic current
fixture must be bitwise equal.  For finite non-dyadic current cases, let `s_a`
be the three shared binary64 LIM slopes, `eta_a` the exact phase values, and
`eta_current_a` the current coordinate-derived values.  Define in mathematical
real arithmetic

```text
B_eta = sum_a abs(s_a) * abs(eta_current_a - eta_a)
M_exact = abs(center) + sum_a abs(s_a * eta_a)
M_current = abs(center) + sum_a abs(s_a * eta_current_a)
eps = 2**-52
gamma6 = (6*eps) / (1 - 6*eps)
B = B_eta + gamma6*(M_exact + M_current) + 8*smallest_subnormal
```

The fixed-order current and exact-phase outputs must satisfy
`abs(current-exact) <= B`.  Report maximum absolute difference, relative
difference where the output scale is nonzero, and ULP distance descriptively.
Cases with nonfinite or underflowing intermediates compare against independent
fixed-order emulations by class, sign, and operation order instead of applying
the finite bound.  WENO remains index/eta geometry evidence only because its
staggered payload is outside supported PRL input.

## Exact Limited Reconstruction

For mapped coarse center `(I,J,K)` and every slot/field, load the center and six
axial neighbors.  Evaluate three LIM-001 shared inline rules:

```text
sx = LIM(coarse[I-1,J,K], center, coarse[I+1,J,K])
sy = LIM(coarse[I,J-1,K], center, coarse[I,J+1,K])
sz = LIM(coarse[I,J,K-1], center, coarse[I,J,K+1])
```

Then evaluate separate binary64 operations in exact order:

```text
term_x = sx * eta_x
term_y = sy * eta_y
term_z = sz * eta_z
value  = center
value  = value + term_x
value  = value + term_y
value  = value + term_z
fine[p] = value
```

Every output semantically includes all three LIM results and all three terms.
An implementation may reuse bit-identical LIM results for children sharing one
coarse center, but it may not omit an axis or zero term.  Do not use FMA,
reassociate additions, or read diagonal coarse cells.  Output traversal order
is not semantic because outputs are independent and overlap is forbidden.

## Validity And Reach

Both boxes are ordered, nonnegative, and contained in their payload spatial
shapes.  For a spatially nonempty fine target, mapping is monotone.  Map the
first and last fine index on each axis to `center_min` and `center_max`.  The
required half-open coarse box is

```text
[center_min - 1, center_max + 2)
```

componentwise.  Its arithmetic must fit signed `int64`; it must lie in coarse
storage and be contained in `[coarse_valid_lower,coarse_valid_upper)`.  This is
one lower/upper coarse layer on every axis around the mapped center range, but
only the seven-point cross is read.

If any fine target extent is zero, the spatial call is empty and has no mapped
center/reach requirement beyond valid box representations.  Zero slots or
fields with a spatially nonempty target still validate mapping and reach.

## Validation, Errors, And Atomicity

Validation order is coarse payload, coarse-valid lower/upper, coarse origin,
fine payload/writability, fine lower/upper, then fine origin.  Cross-validation
checks exact slot/field equality; coarse-valid order/containment; fine-target
order/containment; output overlap with the coarse payload or any metadata;
mapping arithmetic; required storage bounds; and coarse-valid reach.  Complete
validation precedes mutation.

Wrong object or dtype raises `TypeError`.  Invalid rank, shape, layout,
writability, box, leading extent, storage bound, reach, or overlap raises
`ValueError`.  Unrepresentable signed-index mapping/reach raises
`OverflowError`.  Every failure preserves the complete fine output.  Successful
execution overwrites exactly the fine target box, preserves its exterior, and
mutates/retains no input or pointer.  The kernel allocates no payload or
size-dependent scratch.

## Nonfinite And Signed-Zero Behavior

LIM-001 controls each axial slope.  A NaN axial neighbor with finite center
suppresses that axis to positive-zero slope; a NaN center remains in the base
value and yields NaN output.  Infinite limited slopes times exact phase eta
remain signed infinities, while opposing infinite contributions may yield NaN
in fixed x/y/z addition order.

Positive-zero LIM output times negative eta produces negative-zero term; no
zero term is skipped.  Final signed zero follows the center sign, phase signs,
three multiplications, and ordered additions exactly.

## Independent Evidence

The independent reference uses Python integer floor division, exact integer
phase, literal binary64 eta, `three_point_limited_slope_reference`, separate
products, and x/y/z additions.  Evidence covers negative/positive offsets and
asymmetric origins; all eight phases; tight reach and six independent missing
faces; poisoned diagonals; constants, affine reproduction, child averaging,
step/quadratic monotonicity; partial/translated/odd boxes; random multi-slot/
field exactness; signed zero and nonfinite order; empty/read-only/preservation;
every validation/overflow/overlap failure; RST/workspace composition; bounded
slot-order substitution; current dyadic output; and real/current eta/index
mapping differences under the frozen finite bound above.

## Performance, Memory, And Composition

Each output field-cell semantically reads seven unique coarse values and writes
one fine value: 64 effective bytes before cache effects.  Measure fine
field-cells/s, effective bandwidth, validation, phase/target/field/slot scaling,
output bytes, retained/peak allocation, reference/current comparison, and
separate coarse-workspace/PRL time.

Compare exact fine-centric and coarse-centric allocation-free loops after
correctness.  A materialized three-slope array would add 24 bytes per coarse
field-cell and is not retained without a measured composed benefit.  Standard
>10% investigation and reproduced >20% blocking gates apply; parallelism is
deferred until the serial composed path is material.

RST plus a later assembler establishes coarse self/neighbor/physical values and
the valid box.  A later transfer application maps REL sources to selected slots,
chooses fine target boxes, and invokes PRL.  PRL itself accepts no leaf IDs,
relations, masks, boundary modes, or execution plan.
