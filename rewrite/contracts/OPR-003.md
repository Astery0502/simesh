# OPR-003 Contract: Cartesian 3D Refined Curl

## Responsibility

OPR-003 computes the three-component Cartesian curl of three cell-centered
fields over one explicit common box with per-slot cell spacing. It owns the
fixed component mapping, six centered derivatives, exact OPR-002/OPR-001
arithmetic tree, aggregate reach, and translated output fields. It defines no
field names, ROI grouping, geometry construction, halo values, reader/cache,
scheduling, reduction, generic term language, or current accumulation policy.

## Stable Operation

```text
cartesian_curl_into(
    source,
    source_valid_lower,
    source_valid_upper,
    output_lower,
    output_upper,
    source_field_positions,
    slot_cell_spacing,
    destination,
    destination_field_positions,
    destination_lower,
) -> None
```

- `source` is borrowed read-only C-contiguous
  `float64[S,Fsource,sx,sy,sz]` with one borrowed contained half-open valid box.
- `[output_lower,output_upper)` is a borrowed ordered source-storage box shared
  by all slots.
- `source_field_positions` is borrowed C-contiguous `int64[3]` naming
  `(Bx,By,Bz)`; positions are valid and may repeat.
- `slot_cell_spacing` is borrowed C-contiguous `float64[S,3]`; every entry is
  finite, positive, and normal.
- `destination` is caller-owned writable C-contiguous
  `float64[S,Fdestination,dx,dy,dz]`.
- `destination_field_positions` is borrowed C-contiguous `int64[3]`, valid and
  pairwise distinct, naming `(Jx,Jy,Jz)`.
- Borrowed `destination_lower int64[3]` translates the common output extent.

Source and destination slot counts match. Source/destination may not overlap;
destination may not overlap any metadata. Read-only inputs may overlap when
their simultaneous values satisfy the contract. Validation precedes mutation,
no input changes, and nothing is retained.

## Reach And Component Mapping

Let `D(field,axis)` be OPR-002's centered derivative at one source coordinate.
The mathematical mapping is

```text
Jx = D(Bz,y) - D(By,z)
Jy = D(Bx,z) - D(Bz,x)
Jz = D(By,x) - D(Bx,y).
```

The aggregate FND-002 pattern is `LOCAL_STENCIL` with lower/upper reach exactly
`(1,1,1)`. Component Jx has reach only on y/z, Jy on z/x, and Jz on x/y. Every
nonempty requested box must be supported by `source_valid`; transverse output
edges are valid when the corresponding component does not read that axis, but
the stable all-component operation requires the aggregate box support.

All twelve neighbor values are loaded for every cell, even if fields repeat or
later arithmetic has zero/NaN behavior. The source center is not read.

## Exact Arithmetic

For a slot and one derivative axis, precompute separately

```text
inverse_two_spacing = 0.5 / slot_cell_spacing[slot,axis].
```

For each positive/negative derivative in the component order shown above:

```text
difference = source[plus_neighbor] - source[minus_neighbor]
derivative = difference * inverse_two_spacing
```

Then complete each component as OPR-001 scale-one arithmetic:

```text
product = 1.0 * negative_derivative
result  = positive_derivative - product
```

Each division, subtraction, multiplication, and final subtraction is separately
rounded binary64; no FMA, reassociation, `+0` accumulation, or algebraic
rewrite is permitted. Component evaluation order is Jx, Jy, Jz; there is no
cross-component dependence. For mixed slot spacing, the separate composition
runs six one-slot OPR-002 derivatives per slot (or groups only slots with
bit-identical spacing), stores six binary64 intermediate fields, then runs the
three OPR-001 scale-one differences. The fused tree has the same finite and
signed-zero bits as that exact composition.

Only the three selected destination fields and translated box may change;
everything else is bitwise preserved. IEEE NaN, infinity, overflow, and signed
zero follow the fixed all-neighbor tree. Current's generic derivative batch
uses `+0.0 + coefficient*contribution`; its operation-order/signed-zero
differences are intentional and measured rather than adopted.

## Validation And Atomicity

Before mutation, validate exact ndarray types/dtypes/ranks/C-contiguity,
destination writability, slot extents, valid/output ordering and aggregate
reach, field-position vectors, distinct destination positions, all per-slot
spacing, translated output/int64 containment, and forbidden overlap. Metadata
and field positions are validated even for empty slots/boxes.

An empty slot axis or output box is a validated no-op. Type/dtype/scalar-kind
failures raise `TypeError`; invalid layout, box, reach, field, spacing, output,
writability, or overlap raises `ValueError`; translated index overflow raises
`OverflowError`. Every ordinary failure preserves the complete destination.

## Numerical Evidence

Boxes, field mappings, neighbor indices, and preservation compare exactly. The
independent scalar reference implements the written tree. A second reference
uses six one-slot OPR-002 calls per slot, six explicit binary64 intermediate
arrays, and three OPR-001 calls. Finite and signed-zero results compare by exact
bits; nonfinite results compare IEEE classification and sign, matching the
lower contracts rather than imposing a cross-platform NaN-payload promise.

Finite comparisons report maximum absolute, relative-away-from-cancellation,
and ULP error. A conservative local bound is the sum of the two OPR-002 bounds
plus the OPR-001 scale-one bound. Affine vector fields reproduce constant curl
within that bound; smooth analytic fields demonstrate approximately second-
order L-infinity convergence with observed order at least 1.8. IEEE tests cover
all neighbor loads, repeated source positions, signed zeros, NaNs, same/opposite
infinities, and finite overflow. All four positive/negative-zero derivative
pairs are frozen; in particular `-0 - (+0)` is `-0`, while current's full
`+0`/coefficient accumulation produces `+0`. Mixed-level/per-slot spacing is a
required composition case. Current comparison uses the common valid interior
and records its known accumulation-tree differences.

## Performance And Immediate Composition

The fused Cython kernel reads twelve values and writes three per output cell,
with three inverse spacings per slot and fixed scalar state. It allocates no
payload-, derivative-, slot-, box-, or field-sized scratch. OPR-003 is
`hot-kernel`: compare values/s, effective traffic, slot/box/level/field scaling,
fixed allocation, per-slot six-OPR-002/three-OPR-001 composition, current generic batch,
and immediate LFE execution. The hypothesis is that one traversal and no six
derivative temporaries materially reduce memory traffic without changing the
frozen primitive composition.

RHC-001 supplies completed primary payload. LFE-001 groups consecutive equal
ROI windows, passes per-slot GEO spacing, writes compact selected curl rows,
and reduces one component after this kernel returns.
