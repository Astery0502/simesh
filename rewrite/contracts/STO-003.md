# STO-003 Contract: Functional Block Transfer Adapters

## Responsibility

STO-003 represents canonical block reads and writes as explicit immutable data
plus coarse-grained functions. It allows storage implementations to be
substituted at Python chunk boundaries without changing chunk, topology, halo,
sampling, operator, or reduction semantics. It defines no file format, cache,
transaction, asynchronous scheduling, framework kernel, or new payload layout.

## Descriptors

```text
BlockReader(state, shape, read_into, memory_arrays=())
BlockWriter(state, shape, write_from, memory_arrays=())
```

`shape` is the canonical five-entry `(block,field,x,y,z)` extent. Block and
field extents are nonnegative; spatial extents are positive. State is explicit
and may be any object. The callable is invoked with state as its first argument
and returns `None`.

`memory_arrays` lists every NumPy array owned or borrowed by the backend that
participates in executor alias validation. Resident array and memory-map
adapters expose their backing array. External file or remote state need not
invent an array alias. A custom adapter that omits a real memory alias violates
the descriptor contract.

Descriptors are frozen and retain only the explicitly supplied state, callable,
shape, and alias tuple. No global registry or implicit backend selection is
used.

## Reader Operation

```text
read_blocks_into(
    reader,
    source_valid_lower,
    source_valid_upper,
    block_ids,
    field_ids,
    destination,
    destination_lower,
) -> None
```

The callback must implement the STO-001 gather meaning over its declared
canonical shape: selected block/field values in the source box are copied into
the translated destination box, and everything outside the destination box is
preserved. It may not mutate metadata or backend source state. Selection order,
duplicates, regions, binary64 bit preservation, and empty requests have STO-001
semantics.

## Writer Operation

```text
write_blocks_from(
    writer,
    source,
    source_valid_lower,
    source_valid_upper,
    block_ids,
    field_ids,
    destination_lower,
) -> None
```

The callback must implement the STO-001 scatter meaning over its declared
canonical shape. It mutates only selected block/field destination cells and
uses STO-001 deterministic duplicate ordering. It may not mutate the source or
metadata.

`array_block_reader(...)` and `array_block_writer(...)` are the reference
adapters. They accept native-endian C-contiguous rank-five `float64` resident
arrays or `numpy.memmap` objects and delegate to STO-001.

## Validation, Failure, And Ownership

Factories validate descriptor shape, callable presence, and alias-array types.
Invocation revalidates descriptors constructed directly and rejects a callback
that returns a value. The concrete callback owns request validation and must
leave its destination unchanged on an ordinary request-contract error. The
array adapters inherit complete STO-001 validation and atomicity.

Executors validate declared shapes, selectors, topology, budget, result grids,
and exposed memory aliases before numerical mutation. Backend state is borrowed
for the call and may not be retained by the executor. Callbacks may retain no
caller-owned request arrays or workspace views after return.

An external read/write error after successful preflight may leave already
executed caller or external outputs partially updated. STO-003 does not claim a
transaction across arbitrary storage systems. Backends that offer stronger
atomicity document and test it separately.

## Execution Integration

`execute_level1_m0_from_blocks(...)` accepts one reader and two result writers.
It composes the established INT-001 plans and numerical kernels unchanged. The
stable `execute_level1_m0(...)` array API creates reference adapters and calls
that function.

Capacity equal to the block count is the initial resident strategy; smaller
capacity is the bounded strategy. Both use the same canonical padded workspace
and must produce contract-equivalent outputs and capacity-invariant reduction.
A later zero-copy or cached strategy is a separate optimization because halo
padding, output ownership, and deterministic traversal can still require
buffers.

## Exactness And Conformance

Array-adapter transfers are bitwise equal to direct STO-001 calls. A backend
whose explicit state is not an ndarray must pass the same selection/region
contract and complete M0 composition. Bounded array/memmap and full-capacity
functional paths must agree bitwise for all five INT outputs and in reduction
bits.

Conformance includes reordered/repeated fields, multiple chunk capacities,
physical and sibling halos, alias exposure, direct descriptor validation,
empty preflight calls, source preservation, and callback return behavior.

## Performance And Memory

Adapter dispatch occurs once per transfer, never in a Cython hot loop. Measure
direct STO-001 versus array-adapter latency for small and bandwidth-scale
transfers, traced retained/peak allocation, and composed call counts. No adapter
may allocate a payload-sized temporary unless its concrete backend contract and
memory evidence declare it.

## Immediate Composition

STO-001 implements the reference array callbacks. STO-002 supplies selected
IDs and bounded workspaces. INT-001 remains the array compatibility surface;
`execute_level1_m0_from_blocks` is the functional composition point for future
resident, mapped, native AMRVAC, cached, or framework transfer adapters.
