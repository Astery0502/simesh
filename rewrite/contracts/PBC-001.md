# PBC-001 Contract: Per-Axis Cartesian Physical Boundary Rules

## Responsibility

PBC-001 defines the source-coordinate and binary64 value rule for one explicit
non-periodic Cartesian physical face.  It does not decide whether a face is
physical, locate a source block/slot, choose multi-axis composition order,
infer field names, mutate payloads, allocate workspaces, or define refined,
periodic, or 2D behavior.

## Stable Operations

```text
physical_halo_source_index(
    target_index,
    interior_lower,
    interior_upper,
    face,
    mode,
) -> source_index
```

- `interior_lower` and `interior_upper` are borrowed C-contiguous `int64[3]`
  triplets defining a nonempty nonnegative box.
- `face` is a Python/NumPy integer scalar (including `IntEnum` values),
  excluding booleans and rank-zero arrays, fitting signed `int64`; its value is
  the exact HAL/TOP column `2*axis+side` in `[0,6)`.
- `target_index` is an exact Python `int` or NumPy integer scalar, excluding
  Python/NumPy booleans and rank-zero arrays, and must fit signed `int64`.  It
  is outside the interior on that face:
  below `interior_lower[axis]` for lower, or at/above
  `interior_upper[axis]` for upper.
- `mode` has the same integer-scalar rule and is exact `BoundaryMode` code
  `0..3`.

Let `lower=interior_lower[axis]`, `upper=interior_upper[axis]`, and
`extent=upper-lower`.  Define the positive layer without overflow in Python
integer arithmetic:

```text
lower face: layer = lower - target
upper face: layer = target - upper + 1
```

The exact source coordinate is:

| Mode | Lower face | Upper face |
| --- | --- | --- |
| continuous / no-inflow | `lower` | `upper-1` |
| symmetric / antisymmetric | `lower+layer-1` | `upper-layer` |

For symmetric/antisymmetric modes, `layer > extent` raises `ValueError` before
any fixed-width subtraction.  Every accepted result then lies in
`[lower,upper)` and fits signed `int64`, including valid upper reflection next
to `INT64_MAX`.  Continuous/no-inflow may clamp any representable outside
depth.  The operation returns an exact Python `int`.

```text
transform_physical_halo_value(
    value,
    field_position,
    normal_field_slot,
    face,
    mode,
) -> transformed_value
```

- `value` is an exact built-in Python `float` or exact NumPy `float64` scalar;
  integers, booleans, other NumPy float widths, subclasses, and rank-zero
  arrays are rejected.
- `field_position` is an exact nonnegative Python/NumPy integer scalar fitting
  signed `int64`, excluding booleans and rank-zero arrays.
- `normal_field_slot` is an exact Python/NumPy integer scalar fitting signed
  `int64`, excluding booleans/rank-zero arrays, and is `-1` or nonnegative.
- `face` and `mode` have the same representations above.

Continuous and symmetric return `value` bitwise unchanged.  Antisymmetric
toggles only the binary64 sign bit, with no rounding.  No-inflow acts only when
`field_position == normal_field_slot`:

- lower face: positive finite values and `+inf` become exact `+0.0`;
- upper face: negative finite values and `-inf` become exact `+0.0`;
- opposite-sign infinities, both signed zeros, and every NaN retain all input
  bits.

No-inflow on a nonnormal field is identity.  The return is an exact built-in
Python `float` carrying the specified binary64 bits.  Whether a missing normal
slot is valid for a complete boundary table remains HAL/adapter validation,
not this per-axis scalar rule.

## Composition, Validation, And Errors

For an edge/corner, callers first map every incident physical axis, load the
single interior/source-block value, then apply value transformations in their
declared axis order.  PBC-001 does not select that order.  HAL-001/HAL-002 retain
x, then y, then z.

Wrong scalar/array/dtype kinds raise `TypeError`.  An integer scalar outside
signed `int64` raises `OverflowError`.  Invalid box shape/contiguity/order,
face, mode, target side, reflected depth, field position, or normal slot raises
`ValueError`.  In particular, a representable lower target of `INT64_MIN`
against `[0,1)` is excessive depth and raises `ValueError`, not an
implementation-dependent overflow.  Read-only triplets are accepted and all
inputs are preserved; no state is retained.

## Exactness And Evidence

Coordinate results are exact integers.  Continuous/symmetric identity,
antisymmetric sign-bit toggling, and no-inflow clipping compare through
`uint64` views, including signed zero, infinities, quiet/signaling NaN payloads,
and nonnormal rows.  Evidence includes every face/mode/layer, randomized scalar
comparison with an independent Python reference, validation boundaries, and
bitwise unchanged HAL-001 and HAL-002 aggregate suites/current comparisons.

The production bodies are `cdef inline noexcept nogil` definitions in a Cython
header consumed by aggregate halo translation units; public validated scalar
entrypoints delegate to the same primitives without putting `cpdef` calls in
cell loops.  They allocate no memory.  Isolated validated scalar-call runtime is descriptive;
meaningful performance gates are unchanged HAL-001 produced-values/s and
both HAL-002 direct-kernel and gather/HAL composed runtime/allocation.

## Immediate Composition

HAL-001 consumes both rules for purely physical cells.  HAL-002 consumes them
for physical axes of mixed sibling/physical cells.  HPL-001 supplies source
slots and physical masks to the next explicit same-level transfer boundary,
which uses these rules without topology discovery.
