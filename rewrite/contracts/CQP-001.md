# CQP-001: Indexed Cache Query Planning

Frozen 2026-09-07. Implements CHS-001's existing cache access simulation, with
CHS-001 and HPR-001 complete. Numerical operations and public contracts remain
unchanged. Design, workload, budgets and promotion gates are in
[round evidence](../evidence/M1-OPTIMIZATION-ROUND.md).

For capacity>=16 and at least eight owner groups, a temporary dictionary maps
nonnegative copied cache keys to slots. Process owners in the original order:
hit updates copied recency; miss completes original halo preflight, admits into
the first empty slot or the minimum `(recency, slot)` victim, and updates the
dictionary by removing the evicted key and inserting the new key. Capacity zero
and smaller queries retain the linear scan. Overflow checks precede simulation.

Return the same five owned arrays, with identical dtypes, values and byte counts.
The real session and caller outputs are unchanged until all planning succeeds;
no temporary dictionary survives the call. Preserve the original scan as an
explicit private reference via `_indexed=False`. This is an execution choice,
not a new cache lifecycle, invalidation rule or field-validity representation.

Warm indexed planning is O(C+O); miss preflight and victim scans retain their
existing costs. Copied arrays remain `16*C+17*O` bytes. Dictionary storage is
O(C) Python objects, excluded from historical raw-array stats but measured in
complete workflow resources. Full preflight failure, LRU ties, empty/zero
capacity, mixed hits/misses, repeated histories, and reader failure behavior
must remain exactly equivalent. Use the existing scientific acceptance suite.
