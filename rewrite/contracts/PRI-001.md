# PRI-001 Contract: Deterministic Ascending Primary Prefix

## Responsibility

PRI-001 fills the maximal ascending contiguous prefix of dense zero-based global
block IDs that fits an explicit caller buffer.  It defines no byte accounting,
capacity selection, topology, support closure, minimum closure capacity,
selected/support distinction, transfer, payload, backend, or scheduling.

## Stable Operation

```text
fill_ascending_primary_prefix(
    first_primary_id,
    block_count,
    primary_ids,
) -> primary_count
```

`first_primary_id` and `block_count` accept Python `int` and NumPy integer
scalars but reject booleans, floating values, and rank-zero arrays.  Both are
nonnegative and signed-int64 representable, with
`first_primary_id <= block_count`.

`primary_ids` is caller-owned writable native-endian C-contiguous `int64[S]`.
Its length is the explicit capacity.  No input/output pointer is retained.

## Exact Prefix

At end-of-stream, `first_primary_id == block_count`, return zero and leave the
entire output unchanged for every capacity, including zero.

Before end-of-stream, zero capacity raises `ValueError` without mutation.
Otherwise:

```text
primary_count = min(S, block_count - first_primary_id)

primary_ids[i] = first_primary_id + i
    for i in [0, primary_count).
```

The suffix `primary_ids[primary_count:]` is bitwise preserved.  The result is
independent of prior prefix contents.  `primary_count` is positive before the
end, no greater than capacity, and maximal: either the buffer is full or the
stream ends.  Returning a separate selected count has no meaning without a
support policy and is excluded.

Starting with zero and repeatedly advancing `first_primary_id` by the returned
positive count covers every ID in `[0,block_count)` exactly once in ascending
order.  Positive capacity intrinsically guarantees dense-primary progress;
face/full/refined closure progress is independent.

## Validation, Errors, And Atomicity

Scalar kind errors and non-array/output dtype errors raise `TypeError`.
Negative scalars, `first_primary_id > block_count`, invalid output rank/layout/
writability, or unfinished zero capacity raise `ValueError`.  Scalars above
signed int64 raise `OverflowError`.

Validation order is `first_primary_id`, then `block_count`, then output object/
dtype/rank/contiguity/writability, then range and unfinished-capacity checks.
Every ordinary failure precedes mutation.  Successful calls use no
input-size-dependent scratch and retain no state.

## STO-002 Compatibility

Existing

```text
plan_level1_chunk(first_primary_id, face_neighbor_ids, False, chunk_block_ids)
```

remains stable.  It preserves its current face-table, output, first-ID, boolean,
overlap, and unfinished-capacity validation order before delegating the fill to
PRI-001, then returns `(primary_count, primary_count)`.  It still validates the
face table even though no relation value is consulted.  The `True` direct-face
closure path is unchanged and remains outside PRI-001.

## Independent Evidence

The independent reference uses Python `range` and arbitrary integers.  Evidence
covers zero/one/large block counts and capacities; exact/partial final prefixes;
suffix bits; full randomized/exhaustive traversals; signed-int64 endpoints;
scalar/output error families and precedence; end no-op versus unfinished zero
capacity; arbitrary unused face-table values; old/new result/error conformance;
WSP-derived capacity; and bit-identical pipeline/RED composition.

## Performance And Memory

Production performs exactly one sequential int64 store per returned ID and no
size-dependent scratch.  Runtime is `O(primary_count)` and output writes are
exactly `8*primary_count` bytes.  Measure calls/s, IDs/s, capacity/final-prefix
scaling, full traversal, fixed allocation, compatibility-wrapper overhead, and
pipeline/RED composition.  Topology size, support amplification, RSS/I/O, and
parallel scaling are not PRI kernel metrics.

## Immediate Composition

WSP-001 normally supplies explicit buffer capacity.  The M0 pipeline consumes
PRI-001 for topology-free dry preflight and pass-one reader/pointwise/placement/
sampling/reduction traversal.  STO-002 compatibility callers continue through
the preserved wrapper; later closure capabilities reuse the primary-prefix
meaning without adding modes to PRI.
