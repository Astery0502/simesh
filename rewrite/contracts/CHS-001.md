# CHS-001 Contract: Completed Refined Owner-Halo Sampling Session

## Responsibility

CHS-001 serves ordered Cartesian 3D refined trilinear vector batches through
one explicit serial session with a byte-bounded deterministic LRU of completed
owner halos. It owns immutable session provenance, reusable miss workspace,
ascending owner grouping, cache lookup/admission/clear, SAM-005 application,
statistics, and external-failure prefix behavior. It defines no LOC/SAM/RHE
numerical meaning, raw-interior cache, direction-projected support, field-line
ODE, stepper, termination, prefetch, concurrency, file-descriptor ownership, or
dataset lifecycle.

## Stable Session Operations

```text
make_completed_halo_sampling_session(
    reader,
    magnetic_field_ids,
    domain_lower,
    domain_upper,
    domain_cell_counts,
    block_cell_counts,
    max_level,
    root_shape,
    coord_to_rank,
    root_node_ids,
    node_levels,
    node_coords,
    child_node_ids,
    node_leaf_ids,
    leaf_node_ids,
    boundary_modes,
    normal_field_slots,
    rhe_slot_capacity,
    cache_byte_budget,
) -> CompletedHaloSamplingSession

clear_completed_halo_sampling_session(session) -> None

sample_refined_trilinear_vectors_cached(
    session,
    points,
    hint_leaf_ids,
    point_values,
    point_leaf_ids,
) -> CachedVectorSamplingStats
```

`reader` is one immutable-lifecycle STO-003 source. It remains caller-owned and
open for the session lifetime. Source contents, descriptor state, and borrowed
FST/GEO metadata may not change during that lifetime. The factory copies and
freezes exact ordered `magnetic_field_ids int64[3]`,
`boundary_modes uint8[3,6]`, and `normal_field_slots int64[3]`; repeated and
reordered magnetic fields retain RHE/SAM meaning. All other metadata has its
completed DAT/FST/GEO/RHE representation and is retained as borrowed read-only
session provenance.

The session fixes lower/upper halo reach to `(1,1,1)` and owns one reusable RHE
workspace of `rhe_slot_capacity`. This capacity is distinct from the cache
budget and must fit the universal one-primary all-26 closure. Session creation
performs complete static validation, byte checks, workspace/cache allocation,
and exactly one empty reader conformance call. It does not perform a nonempty
read or precompute every leaf's support/actions.

The session is explicitly serial and non-reentrant. It owns no file descriptor
and exposes no implicit global registry. Use a separate session for another
reader lifecycle, field order, reach/PBC configuration, or concurrent task.
Sampling sets an internal busy flag before dynamic work and clears it in a
`finally` boundary; nested/concurrent sampling or clearing raises `ValueError`
before touching shared workspace/cache arrays.

## Cache Budget, Key, And LRU

For block shape `B`, one cache entry owns:

```text
payload bytes = 3 * product(B + 2) * 8
entry bytes   = payload bytes + 8-byte leaf key + 8-byte recency
capacity      = min(L, floor(cache_byte_budget / entry_bytes))
```

`cache_byte_budget` is an exact nonnegative Python integer. Entry-dependent raw
arrays never exceed it; unused remainder is reported by the caller from the
budget and exact session fields. Capacity zero is a valid uncached session.
Reusable RHE workspace, fixed session arrays, borrowed metadata, dynamic-call
plans, backend buffers/page cache, Python objects, and outputs are outside this
entry budget and separately accounted.

Because all other provenance is fixed by the session, a valid entry key is only
canonical leaf ID. Cached payload is primary-only canonical
`float64[1,3,Bx+2,By+2,Bz+2]` with the complete RHE-001 one-cell halo.

Owner groups are visited in ascending leaf ID. A valid matching entry is a hit.
On a miss choose the lowest invalid slot, otherwise the least-recent valid slot
with lowest slot as tie-break. Recency changes only after that owner group is
sampled successfully. Complete/preflight/read/apply the missing owner in the
reusable RHE workspace and sample it synchronously. Reader/RHE/sampling failure
occurs before admission and leaves the victim's old valid entry unchanged.
Immediately before the first cache-payload write, invalidate a valid victim
key; copy the completed staging payload; then publish the new key/recency only
after the full copy succeeds. A recoverable copy failure leaves that slot
invalid. No old or new valid key may expose a partial halo.

`clear_completed_halo_sampling_session` invalidates every key and resets LRU
order without I/O or payload clearing. Stale payload bits remain inaccessible.

## Dynamic Sampling Operation

`points` is C-contiguous `float64[P,3]`; all entries must be finite.
`hint_leaf_ids int64[P]` contains `-1` or valid HLO-001 hints.
`point_values` is caller-owned writable C-contiguous `float64[P,3]`.
`point_leaf_ids` is caller-owned writable C-contiguous `int64[P]`.
Mutable outputs are pairwise nonoverlapping and do not overlap session arrays,
reader memory, metadata, or dynamic inputs.
Dynamic `points` and `hint_leaf_ids` may not overlap any mutable session-owned
array because miss planning/reading and cache admission mutate that storage
after point/stencil preflight.

Before nonempty I/O, cache mutation, or output mutation, validate all dynamic
representations/aliases, points/hints, exact HLO owners, ascending owner plan,
and every interior SAM-005 point/group/stencil. Then publish all owner IDs.
Exterior finite points receive `-1` and preserve their `point_values` row
bitwise. Interior points are grouped stably by ascending owner; within each
owner, original point order is preserved. Hit and miss payloads both call the
same unchecked SAM-005 kernel after equivalent preflight.

Cache capacity/history may change only reads and statistics. Owner IDs and
point values must be identical to HLO-001 plus public uncached RPS-001 for the
same points and fixed session provenance.

## Statistics And Managed Memory

Success returns exact Python-integer deltas for the current call, never
cumulative session-history counters:

```text
point_count
inside_point_count
owner_count
hint_candidate_count
hint_hit_count
hierarchy_fallback_count
cache_lookup_count
cache_hit_count
cache_miss_count
cache_eviction_count
halo_fill_count
reader_call_count
selected_load_count
support_load_count
maximum_selected_slots
logical_reader_bytes
call_managed_array_bytes
session_managed_array_bytes
```

Cache lookups equal unique interior owners; hits plus misses equal lookups. An
eviction is one successfully completed replacement of a previously valid entry.
At cache capacity zero, hits and evictions are zero while misses, halo fills, and
nonempty reader calls equal unique interior owners. The one factory empty reader
conformance call is excluded. `selected_load_count` sums every
RHE miss selection, `support_load_count = selected_load_count - misses`, and
logical bytes are `selected_load_count * 3 * product(B) * 8`. A cache hit adds no
reader call/load/byte. `call_managed_array_bytes` is the exact retained dynamic
owner/group-plan raw arrays. Sorting-library transient memory is measured.
`session_managed_array_bytes` is the exact owned persistent raw cache,
provenance-copy, fixed scratch, and reusable RHE workspace total. Caller points,
hints, outputs, borrowed metadata, backend buffers/page cache, Python objects,
and process RSS are excluded.

## Validation, Failure, And Mutation

Factory and dynamic ordinary type/dtype/scalar-kind errors raise `TypeError`;
invalid shapes/layouts, source/forest/geometry/PBC/capacity/hints/points/cache
state/aliases raise `ValueError`; integer/byte overflow raises `OverflowError`.
Ordinary dynamic failure leaves outputs and cache history unchanged and makes
no nonempty read. Factory failure publishes no session.

After dynamic preflight, an external reader failure preserves completed earlier
owner values/admissions and all published owner IDs; the failed/current and
later point-value groups remain unchanged. The failed victim remains valid with
its prior key/value because admission has not started. Unexpected sampling/
resource/process failure may partially mutate its current output. A copy failure
may partially mutate cache payload only after the victim key is invalidated; the
new key is published only after the completed copy. Earlier work is not rolled
back.

Inputs remain unchanged. No dynamic point/output view is retained. The explicit
session retains only its documented reader, borrowed immutable metadata, copied
provenance, and owned arrays until the caller releases it.

wrong/absent hints, repeated/reordered magnetic fields, capacity zero/one/
working-set/resident, deterministic eviction and clear, every SAME/FINER/
COARSER/PHYSICAL plus mixed boundary mode, array/native readers, exact HLO/RPS

CHS-001 is `composition-only`. Its group benchmark records cold/warm coherent
and divergent batches, points/s and latency, hint/fallback and owner reuse,
cache hit/miss/eviction, halo fills, selected/support loads, logical/native
header/payload bytes, bytes per interior point, cache/RHE/plan/peak/RSS memory,
capacity knees, and bitwise trajectory-input equivalence to RPS. Capacity-zero
CHS uses positive RHE capacity and completes owners individually; only its owner
IDs and numerical values, not chunk/load/call statistics, are compared with
public RPS. The following SLE-001 milestone workflow is its final completion
consumer.

Retain full all-26 RHE behavior on misses. Direction-projected COARSER/PBC
support and a raw-interior LRU are separate capabilities and reopen only if
native miss-heavy or cache-thrashing streamline evidence remains material.
