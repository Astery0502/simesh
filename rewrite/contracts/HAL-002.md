# HAL-002 Contract: Same-Level Level-1 Halos

## Responsibility

HAL-002 fills the same-level-dependent halo cells of primary level-1 blocks in
a bounded HCL-001-selected workspace. Together with HAL-001 it makes every allocated
primary cell valid. It defines no chunk planning, allocation, refined exchange,
periodicity, field inference, 2D behavior, sampling, or operator execution.

## Stable Operation

```text
fill_same_level_halos(
    payload,
    interior_lower,
    interior_upper,
    block_ids,
    primary_count,
    face_neighbor_ids,
    boundary_modes,
    normal_field_slots,
) -> None
```

- `payload` is caller-owned writable C-contiguous
  `float64[nslot,nfield,sx,sy,sz]`.
- `[interior_lower,interior_upper)` is a borrowed C-contiguous `int64[3]`
  nonempty box contained in the spatial shape.
- `block_ids` is borrowed C-contiguous `int64[nslot]`, contains unique global
  IDs, and maps every payload slot explicitly.
- `primary_count` is an integer in `[0,nslot]`; only that slot prefix is output.
- `face_neighbor_ids`, `boundary_modes`, and `normal_field_slots` have the
  exact TOP-001 and HAL-001 representations.

All selected-slot interiors are valid on entry. For every primary, the selected
IDs contain its complete clipped one-block `3x3x3` neighborhood under TOP-001
face walks, as produced by `plan_level1_halo_closed_prefix` or its compatibility
wrapper. Purely physical primary
halo cells are valid HAL-001 results on entry. The normal composition is
therefore STO-001 gather, HAL-001 physical fill, then HAL-002 same-level fill.

## Direct Source Mapping

Let `L=interior_lower`, `U=interior_upper`, `E=U-L`, and target coordinate `q`.
For each axis `a`:

- if `L[a] <= q[a] < U[a]`, the source coordinate is `q[a]` and the block
  displacement is zero;
- if `q[a] < L[a]` and the lower face has a sibling, displacement is `-1` and
  source coordinate is `U[a] - (L[a] - q[a])`;
- if `q[a] >= U[a]` and the upper face has a sibling, displacement is `+1` and
  source coordinate is `L[a] + (q[a] - U[a])`;
- if the crossed face is physical, displacement is zero and the source
  coordinate is HAL-001's clamp or reflection for that field and face.

The source global ID is obtained from the primary by walking nonzero sibling
displacements in fixed x, then y, then z order. TOP-001 commutation makes that
the unique diagonal block. The source slot is the unique matching entry in
`block_ids`; only its valid interior is read.

If no outside axis crosses a sibling face, HAL-002 preserves the target: it is
either interior or a purely physical HAL-001 result. Otherwise HAL-002 reads the
direct source value, then applies the physical-axis value transforms in x/y/z
order using HAL-001's exact boundary-mode and normal-field semantics. Thus a
mixed edge or corner is sibling selection followed by physical
post-composition, never a read from an unspecified halo.

Every allocated lower and upper halo width must be at most `E` on its axis.
Larger widths can require a source two blocks away and are rejected even when a
particular primary happens to lie on a physical face.

## Mutation, Validity, And Atomicity

On success:

- every allocated halo cell of `payload[:primary_count]` is valid;
- primary interiors are bitwise preserved;
- purely physical primary halo cells are bitwise preserved;
- every support slot `payload[primary_count:]` is bitwise preserved.

The full spatial payload box is therefore the common FND-001 valid region for
the primary prefix. The operation returns no metadata or allocation.

Payload may not overlap metadata. Read-only inputs may overlap one another.
Nothing is retained. Before mutation, validate exact ndarray types/dtypes,
ranks, shapes, C-contiguity, payload writability, box bounds, halo depths,
primary count, block-ID ranges and uniqueness, mode codes, normal metadata,
forbidden overlap, and complete primary closure. TOP semantic validity is an
upstream precondition and is not rescanned. Any invalid call leaves payload
unchanged. Type/dtype errors raise `TypeError`; other contract violations raise
`ValueError`; an unrepresentable scalar count raises `OverflowError`.

## Exactness And Evidence

Sibling values are bitwise copies. HAL-001 antisymmetric negation and no-inflow
clipping retain their exact binary64 behavior, including NaN and signed zero.
All comparisons use `uint64` views with no tolerance.

The current implementation is pass-ordered at mixed boundaries and can apply a
noncommuting physical transform in a different effective order. HAL-002 retains
HAL-001's deterministic x/y/z order as an intentional divergence. Exact current
comparison therefore covers sibling placement and commuting physical modes; a
focused no-inflow/antisymmetric mixed-corner comparison records both exact
results and proves the bounded difference rather than accepting either result
with tolerance.

Correctness evidence includes an independent direct-cell reference;
axis-coded asymmetric halos; faces, edges, corners, singleton root axes, mixed
physical/sibling modes, and NaN-filled entry halos; exact full-mesh comparison
with the current level-1 implementation for commuting modes; the explicit
noncommuting current divergence; closure/uniqueness/atomic-failure checks; and
preservation of interiors, pure physical cells, and support slots.

## Performance And Memory

The simple implementation scans selected IDs to build a fixed 27-entry source-
slot table per primary, then visits the primary allocated box and writes each
same-level-dependent halo cell once. Allocation-free uniqueness validation is
quadratic in selected slots; total complexity is
`O(nslot^2 + primary_count * 27 * nslot + primary_count * nfield * allocated_cells)`;
scratch is exactly a fixed 27-entry integer table plus scalar loop state.
Measure written-cell throughput, halo-width/field/primary scaling, fixed
allocation behavior, and composed STO-001/HAL-001/HAL-002 runtime before
considering directional cuboid fusion.

## Immediate Composition

HCL-001 supplies the full-halo-closed selected workspace, STO-001 fills its
interiors, and HAL-001 supplies pure physical cells and shared boundary rules.
SAM-003 and OPR-002 consume the completed primary prefix.
