# WSP-001 Contract: Canonical Payload Workspace Accounting

## Responsibility

WSP-001 computes exact managed bytes for one FND-001 canonical float64 payload
workspace plus its aligned int64 global-block-ID vector, and inverts that same
formula under an explicit block-count limit.  It defines no allocation,
traversal, progress, support closure, topology, transfer, backend, RSS/page
cache, I/O, or additional executor scratch.

## Stable Operations

```text
workspace_nbytes(
    slot_capacity,
    field_count,
    workspace_shape,
) -> bytes

workspace_slot_capacity(
    budget_bytes,
    block_count,
    field_count,
    workspace_shape,
) -> slot_capacity
```

Scalar arguments accept Python `int` and NumPy integer scalars but reject
booleans, floating values, and rank-zero arrays.  `slot_capacity`,
`budget_bytes`, and `block_count` are nonnegative and fit signed `int64`.
`field_count` is positive and fits signed `int64`.

`workspace_shape` is borrowed read-only native-endian C-contiguous
`int64[3]`, with every extent positive.  Writable and read-only arrays are both
accepted.  No input is mutated or retained.

## Exact Formula

For slot capacity `S`, field count `F`, and spatial volume
`V=sx*sy*sz`, the counted arrays are exactly:

```text
payload   float64[S,F,sx,sy,sz] = 8*S*F*V bytes
block_ids int64[S]              = 8*S bytes
bytes_per_slot                  = 8*(F*V + 1)
managed_bytes                   = S*bytes_per_slot
```

`workspace_nbytes(...)` returns `managed_bytes`.  Given byte budget `B` and
block-count limit `N`, `workspace_slot_capacity(...)` returns exactly

```text
min(N, floor(B / bytes_per_slot)).
```

The block-count clamp is an algebraic upper bound, not primary traversal or
progress policy.  Zero capacity, budget, or block count is valid, but the field
and shape descriptor is still fully validated.

Every spatial product, bytes-per-slot result, and total byte result must fit
signed `int64`.  Capacity inversion never returns a value outside signed
`int64` because both inputs are already bounded.

## Managed Boundary And Exclusions

The count includes full allocated payload and ID capacity, including unused
final slots.  NumPy object headers, borrowed source/topology arrays, output
arrays, support/relation plans, coarse/output/reduction workspaces, mapped-file
pages, OS page cache, and backend state are excluded.  A consumer with more
arrays must define a separate composed formula; INT-001 remains such a richer
contract and is not redirected through WSP-001.

WSP-001 does not decide whether returned capacity is sufficient for a primary,
face, halo, or refined closure.  Minimum-progress and amplification semantics
belong to their respective traversal/support capabilities.

## Validation And Errors

Wrong scalar/array kinds, shape dtype, rank, or layout raise `TypeError` or
`ValueError` with the existing STO-002 behavior: scalar/array/dtype kinds use
`TypeError`; negative scalars, zero fields, nonpositive extents, and invalid
shape/rank/layout use `ValueError`.  Scalar, volume, per-slot, or total signed
`int64` overflow raises `OverflowError`.

Validation precedence is stable when multiple inputs are invalid.
`workspace_nbytes` validates `slot_capacity`, then `field_count` kind/range and
positivity, then shape kind/dtype/shape/contiguity/positivity, then spatial and
per-slot overflow, and finally total-byte overflow.
`workspace_slot_capacity` validates `budget_bytes`, then `block_count`, then the
same field/shape/per-slot sequence.  Zero capacity or block limit does not skip
later descriptor validation.

Both operations are pure and failures preserve every input by construction.
The canonical module is `simesh_rewrite.workspace`.  Existing
`simesh_rewrite.chunking.workspace_nbytes`,
`simesh_rewrite.chunking.workspace_slot_capacity`, and package-root exports are
stable compatibility wrappers with bit-identical results and identical error
types/messages.

## Independent Evidence

An independent arbitrary-integer reference evaluates the formula directly.
Evidence covers zero and exact byte boundaries, field/shape variation,
linearity in slots, block-count clamping, inverse maximality, Python/NumPy
integer scalars, all validation/error families, every overflow stage,
read-only shapes, and exact equality to allocated NumPy payload plus ID
`nbytes`.  Canonical and compatibility entrypoints agree for results and errors.

## Performance And Memory

Both operations are fixed-rank `O(1)` integer arithmetic with no array- or
input-size-dependent scratch and no retained state.  Fixed Python scalar/call
objects are permitted.  Isolated runtime is descriptive; meaningful composition is
exact agreement between budget, returned capacity, and actual allocated array
bytes.  Measure calls/s, wrapper overhead, fixed traced allocation, and actual
allocation equality.  No parallel scaling applies.

## Immediate Composition

FND-001 supplies canonical payload and ID layouts.  STO-002 and current M0
executors consume WSP-001 through preserved wrappers.  Later primary traversal,
closure, and STO-004 refined support use the same accounting without adding
their policies to this capability.
