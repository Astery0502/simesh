# DAT-002 Contract: Canonical AMRVAC Leaf-Order Forest Binding

## Responsibility

DAT-002 reconstructs the canonical Cartesian 3D FST artifact from one DAT-001
forest stream and proves that every stored leaf level/coordinate row names the
same canonical leaf ID. It defines no binary parsing, record ghosts/offsets,
payload values, geometry/periodic support, topology, reader/cache, or numerical
execution.

## Stable Operation And Result

```text
bind_amrvac_v5_forest(index) -> AMRVACV5ForestBinding
```

`index` is one unchanged `AMRVACV5Index` lifecycle from DAT-001. The frozen
result groups copied source provenance and newly owned canonical arrays:

```text
source_file_identity           copied DAT-001 identity tuple
root_shape                    int64[3]
coord_to_rank                 int64[root_shape]
rank_to_coord                 int64[R,3]
forest                        RefinedForest from FST-001
```

The provenance binds this proof to DAT-003's index/file lifecycle. The binding
retains no pointer, file descriptor, path, mmap, or reference to the input
index. Its arrays are native, C-contiguous, mutually nonoverlapping, and
caller-owned. Mutation starts a new artifact lifecycle and requires the
corresponding MOR/FST validation again.

## Canonical Construction And Exact Binding

Compute exactly in signed integer arithmetic:

```text
root_shape = domain_cell_counts // block_cell_counts
```

DAT-001 has already proved positive exact divisibility and representable root
volume. Run MOR-001 for root order, FST-001 for the bool preorder stream, and
FST-002 on the produced flat arrays. Let `node = leaf_node_ids[leaf]`. For every
file/canonical leaf row require exactly:

```text
index.block_levels[leaf]     == forest.node_levels[node]
index.block_coordinates[leaf] == forest.node_coords[node]
```

The file coordinates are already zero-based by DAT-001. The reconstructed
maximum level must not exceed the v5 header's declared maximum. Equality is
not required because `levmax` may describe the allowed rather than occupied
maximum.

These checks plus copied source identity prove that DAT-003 block ID `leaf` and
every RHE/RPS canonical leaf ID address the same file record. DAT-003 requires
exact provenance equality with its supplied index. They do not prove balance,
topology, geometry, periodicity, or record payload validity.

## Validation, Errors, And Atomicity

The operation accepts exactly an `AMRVACV5Index`; descriptor substitution by a
similar tuple is rejected with `TypeError`. It validates the input array shapes,
dtypes, C-contiguity, count-derived root shape, and safe stored leaf access
before returning a binding. DAT-001 semantic corruption after creation is a
caller contract violation, but ordinary detectable shape/value failures raise
`ValueError`; signed-volume/refinement overflow raises `OverflowError`.

Construction is allocating and transactional: an error returns no partial
binding and mutates no input. MOR/FST failure behavior remains owned by their
contracts.

## Exactness, Evidence, And Performance

All mappings, levels, coordinates, parent/child relations, node/leaf maps, root
IDs, and maximum level compare exactly. Independent evidence uses byte-crafted
mixed-depth files, reordered/corrupted tree rows, nonsymmetric roots, the real
tdm level-one tree, the real staggered WENO level-three-to-six tree, and the
real refined non-staggered spherical/periodic `reference/bw.dat` tree when
available. Geometry and periodicity do not alter the discrete forest binding.

DAT-002 is `cold/control`. Its complexity and allocation are the existing
MOR/FST passes plus one `O(L)` exact equality scan. Required output bytes are

```text
24 + 40*R + 112*K + 8*L
```

where the fixed 24 bytes are `root_shape`. It performs no file I/O and retains
no duplicate file tree table.

## Immediate Composition

DAT-003 relies on the unchanged DAT-001/DAT-002 lifecycle when exposing file
row IDs through STO-003. RHE/RPS consume the binding's root/MOR/forest arrays
and the reader's identically numbered blocks. M2 may generalize the dimension-
specific MOR/FST construction without changing the v5 byte parser.
