# HPL-001 Contract: Level-1 Halo Relation And Source-Slot Plan

## Responsibility

HPL-001 maps every direction around selected non-periodic Cartesian 3D
level-1 primary blocks to an explicit selected source slot and physical-axis
mask.  It defines no cell-coordinate mapping, boundary value rule, payload
mutation, chunk selection/capacity, refinement, periodicity, or scheduling.

## Stable Operation

```text
fill_level1_halo_relation_plan(
    block_ids,
    primary_count,
    face_neighbor_ids,
    source_slots,
    physical_masks,
) -> None
```

`level1_halo_relation_plan(...)` is an allocating helper returning new
`(source_slots, physical_masks)` arrays after the same validation.

- `block_ids` is borrowed read-only C-contiguous `int64[S]`, contains unique
  global TOP-001 block IDs, and maps selected slots explicitly.
- `primary_count` is an integer in `[0,S]`; primaries are the selected prefix.
- `face_neighbor_ids` is borrowed read-only TOP-001 `int64[N,6]`.
- `source_slots` is caller-owned writable C-contiguous `int64[P,27]`.
- `physical_masks` is caller-owned writable C-contiguous `uint8[P,27]`.
- Outputs do not overlap inputs or one another.  On success both outputs are
  completely overwritten, inputs are unchanged, and no array is retained.

TOP-001 semantic validity is an upstream precondition.  `block_ids` must contain
the complete clipped one-block closure for every primary, as produced by
STO-002 full-halo planning.

## Direction And Plan Semantics

For `dx,dy,dz` in `{-1,0,1}`, the exact direction column is

```text
column = (dz + 1)*9 + (dy + 1)*3 + (dx + 1).
```

Thus x varies fastest and center is column 13.  Starting from the primary
global block, process nonzero axes x, then y, then z:

- if the crossed TOP face is physical, set bit `1 << axis` in the mask and do
  not change the current block;
- otherwise advance to the face-neighbor block and mark that the direction has
  a sibling component.

If any sibling component exists, `source_slots[primary,column]` is the unique
selected slot containing the final block.  If none exists, the source slot is
exact `-1`.  Consequently center and purely physical directions have `-1`;
mixed physical/sibling directions have a valid source slot plus a nonzero mask.
Unused mask bits 3 through 7 are zero.

`column` always represents the full target outside direction, including axes
whose mask bits are physical.  It is never reduced to the sibling-only
displacement.  The direction sign and physical bit together determine the
physical face side; each nonzero unmasked axis is a sibling crossing.

The source slot is a local selected-slot index, never a global block or leaf ID.
It may refer to a primary or support slot.  HPL-001 does not decide whether or
how a consumer reads that slot.

## Validation And Atomicity

Before output mutation, validate exact ndarray types/dtypes/ranks/shapes/
C-contiguity, output writability/nonoverlap, scalar kind/range, global block-ID
ranges, selected-ID uniqueness, and complete source-slot closure for all 27
directions of every primary.  Missing closure identifies the first primary and
direction and raises `ValueError`.

TOP-001 semantic validity remains an upstream precondition.  For pointer
safety and atomicity, HPL range-checks every face relation actually traversed
by selected primary directions before using it as another topology row; it
does not rescan unrelated topology rows on each bounded chunk.

Type/dtype/scalar-kind failures raise `TypeError`; invalid shape, layout,
writability, overlap, ID, duplicate, primary prefix, or closure raises
`ValueError`; an unrepresentable scalar count raises `OverflowError`.  Every
invalid call leaves both outputs unchanged.  Empty selected/primary axes are
valid after ordinary validation and require exact `(0,27)` outputs.

## Exactness, Memory, And Evidence

All results are discrete and exact.  Evidence includes an independent Python
walk, every face/edge/corner and mixed physical/sibling direction,
nonsymmetric/singleton roots, shuffled selected slots, zero/all primaries,
closure/duplicate/map/output failures, and exact equivalence with the relations
consumed by HAL-002.

Retained plan storage is exactly

```text
P*27*(8 + 1) = 243*P bytes.
```

The compiled fill performs no heap or selection-sized scratch beyond outputs.
The optimized HAL-002 compatibility path retains its fixed sibling-only
source-slot stack because a full-direction mask variant materially regressed
broad-halo kernels.  Exact per-target conformance with HPL-001 is required even
though the internal representation differs.  Measure primary-directions/s,
fixed allocation, selected-size scaling, Python-reference ratio, and the
unchanged HAL-002 kernel/composition.

## Immediate Composition

TOP-001 supplies face relations and STO-002 supplies the selected full-halo
closure.  An independent direct-cell consumer establishes that HPL outputs are
sufficient and bitwise equivalent to retained HAL-002 behavior.  The next
production decomposition boundary consumes caller-owned plans to apply
same-level copies and shared HAL-001 physical transformations without topology
discovery; retained HAL-002 remains the optimized compatibility comparator.
