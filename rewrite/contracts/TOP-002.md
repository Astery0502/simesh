# TOP-002 Contract: Exact Refined Contact Target Lookup

## Responsibility

TOP-002 returns the raw flat-forest node covering an explicitly requested
adjacent logical block at the source leaf's level, or the non-periodic physical
sentinel.  It defines no FST conformance, balance/admissibility rule, relation
kind/cache, fine-child expansion, geometry, halo operation, support plan,
storage, periodicity, or scheduling.

## Stable Operation

```text
fill_refined_contact_targets(
    root_shape,
    coord_to_rank,
    root_node_ids,
    node_levels,
    node_coords,
    child_node_ids,
    node_leaf_ids,
    leaf_node_ids,
    source_leaf_ids,
    directions,
    target_node_ids,
) -> None
```

Let `R=product(root_shape)`, `K=len(node_levels)`, `L=len(leaf_node_ids)`, and
`Q=len(source_leaf_ids)`.

- `root_shape` and `coord_to_rank` are borrowed read-only MOR-001 C-contiguous
  `int64` arrays with shapes `(3,)` and `root_shape`.
- `root_node_ids` is borrowed read-only C-contiguous `int64[R]`.
- `node_levels` and `node_leaf_ids` are borrowed read-only C-contiguous
  `int64[K]`; `node_coords` is `int64[K,3]` and `child_node_ids` is
  `int64[K,8]`.
- `leaf_node_ids` is borrowed read-only C-contiguous `int64[L]`.
- `source_leaf_ids` is borrowed read-only C-contiguous `int64[Q]`; repeated and
  arbitrarily ordered canonical leaf IDs are allowed.
- `directions` is aligned borrowed read-only C-contiguous `int64[Q,3]`.
- `target_node_ids` is caller-owned writable C-contiguous `int64[Q]`.

The output may not overlap any input.  Inputs are unchanged and nothing is
retained.  Successful execution overwrites every output entry.

`refined_contact_targets(...)` is an allocating helper returning a new
`int64[Q]` output after the same validation.

## FST Lifecycle Precondition

All forest/maps inputs belong to one unchanged artifact that has successfully
passed FST-002.  MOR mathematical key order remains the MOR-001 precondition.
TOP-002 validates its own array shapes, query leaf ranges, directions, output,
and overlap, but does not repeat recursive conformance per call.  If any
artifact array is mutated, FST-002 must run again before TOP-002.

## Exact Contact Meaning

Every direction component is exactly `-1`, `0`, or `+1`, and the triplet may
not be `(0,0,0)`.  For query `q`, let source node
`s=leaf_node_ids[source_leaf_ids[q]]`, source level `ell=node_levels[s]`, and
source logical coordinate `c=node_coords[s]`.  The target logical block at
that level is exactly

```text
t = c + directions[q].
```

The complete logical grid at level `ell` has shape
`root_shape*2**(ell-1)`, already proved representable by FST-002.  If any
component of `t` lies outside `[0,level_shape)`, output exact sentinel `-1`.

Otherwise select the level-1 root coordinate
`rcoord=t//2**(ell-1)`, root rank `coord_to_rank[rcoord]`, and root node
`root_node_ids[root_rank]`.  Descend canonical child columns using the remaining
bits of `t`, stopping when either:

- the current node is a leaf before level `ell`: output that coarser leaf node;
- level `ell` is reached: output the current node, whether a same-level leaf or
  a subdivided internal node.

The output is always `-1` or a node ID in `[0,K)`.  TOP-002 does not assign a
kind.  Consumers classify a nonphysical result using `node_levels` and
`node_leaf_ids`: leaf below source level is coarser, leaf at source level is
same, and internal at source level is subdivided/finer.  Arbitrarily large
level gaps and unbalanced forests are valid results under this contract.

For a multi-axis direction crossing any physical domain component, the result
is `-1`; mixed physical/source operation planning belongs to REL-001, which may
neutralize physical components before a separate query.

## Validation, Mutation, And Errors

Before output mutation, validate exact ndarray type/dtype/rank/shape/
C-contiguity, positive representable root volume, output writability/nonoverlap,
every source leaf range, every direction code, and noncenter directions.  These
query checks complete for all rows before unchecked descent begins.

Wrong types/dtypes raise `TypeError`.  Invalid shapes/layouts, query IDs,
directions, output, or overlap raise `ValueError`.  Root-volume overflow raises
`OverflowError`.  FST semantic corruption after its lifecycle validation is a
caller contract violation rather than a query-time repair or rescan.  All
ordinary TOP-002 validation failures leave the output unchanged.  `Q=0` is a
valid fully validated no-op with shape `(0,)` output.

## Exactness, Evidence, And Performance

Every result is discrete and exact.  Evidence includes an independent
coordinate-dictionary/ancestor reference; all 26 directions; faces, edges,
corners, physical/mixed directions, singleton/nonsymmetric roots, every child
phase, repeated/reordered/empty queries, same/coarser/arbitrarily coarser and
subdivided targets, balanced and unbalanced forests, root crossings, current
face-kind/index comparison, representative real metadata, and atomic query/
output failures.

The compiled lookup is `O(Q*max_source_level)` worst-case, allocates no scratch,
and retains only caller output `8*Q` bytes.  Measure contacts/s by depth/kind
mix, fixed allocation, query scaling, one FST-002+lookup composition, real-tree
faces, and current table lookup descriptively.  TOP-003 caching is a separate
measured policy decision.

## Immediate Composition

FST-002 establishes the immutable artifact lifecycle.  BAL-001 queries all
in-domain touching directions and applies its separate level-gap policy.
REL-001 uses selected raw contacts for operation/source expansion.  Optional
TOP-003 may materialize six admitted face results after cached-versus-on-demand
evidence.
