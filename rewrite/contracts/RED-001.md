# RED-001 Contract: Streaming Field Sum

## Responsibility

RED-001 reduces one selected field/region into a caller-owned streaming sum. It
defines a fixed serial update order, explicit partial-state merge, and scalar
finalization. It defines no allocation, chunk planning, field names, weighting,
geometry, halo use, parallel tree, compensated state, or storage I/O.

## Accumulator Representation

One accumulator is a native-endian C-contiguous writable `float64[1]`. The
caller initializes it, normally to exact `+0.0`. Its sole element is the entire
state; nothing is retained between calls except that caller-owned value.

## Stable Operations

```text
accumulate_field_sum(
    payload,
    valid_lower,
    valid_upper,
    field_position,
    accumulator,
) -> None
```

`payload` is borrowed read-only C-contiguous
`float64[nslot,nfield,sx,sy,sz]`; its borrowed `int64[3]` box is ordered and
contained, and the field position is valid. Starting from `accumulator[0]`, the
operation visits slot, x, y, then z in ascending order and executes exactly:

```text
total = total + payload[slot,field,i,j,k]
```

as one separately rounded binary64 addition per visited value. If at least one
value is visited, it writes the final `total` back to the accumulator once; a
zero-value update performs no accumulator write.

```text
merge_field_sums(accumulator, partial) -> None
```

`partial` is borrowed read-only C-contiguous `float64[1]`, does not overlap the
writable accumulator, and merge performs exactly one separately rounded
addition `accumulator[0] = accumulator[0] + partial[0]`. The caller defines the
order/tree of repeated merges.

```text
finalize_field_sum(accumulator) -> float
```

Finalization validates a borrowed C-contiguous `float64[1]` and returns its
binary64 value as a Python float without further arithmetic or mutation.

## Associativity And Streaming Order

For finite mathematical inputs, the reduced real-number operation is addition,
which is associative. IEEE nonfinite arithmetic is not a real-number reduction,
and binary64 addition is not associative, so RED-001 does not promise merge-tree
or arbitrary-reordering invariance.

The M0 executor uses no partial merges: PRI-001 prefixes present unique primaries
in ascending global ID order, each gather preserves slot and C-order
cells, and one persistent accumulator crosses chunk calls. Consequently every
capacity executes the identical global block/field/x/y/z addition sequence and
must produce bit-identical output. Reordering chunks or using partial merges is
a different declared execution strategy and may change low bits.

The operation is FND-002 `STREAMING_REDUCTION` with zero lower/upper reach. Only
the supplied valid region is visited; support blocks and halos are excluded by
passing the primary payload prefix and interior box.

## Empty And IEEE Behavior

An empty slot axis or spatial box performs no additions and preserves the
accumulator bitwise. With the normal `+0.0` identity, an entirely empty stream
finalizes to exact `+0.0`.

NaN, infinities, overflow, and signed zero follow the fixed sequential IEEE
addition order. Examples include `+inf + -inf -> NaN`; initializing `+0.0` and
adding only negative zeros yields `+0.0`. No NaN skipping, finite filtering,
reassociation, vector reduction, or zero special case is permitted.

## Validation And Atomicity

Before accumulator mutation, validate exact ndarray types/dtypes/ranks/
C-contiguity, payload region ordering/containment, field position, accumulator
shape/writability, and forbidden overlap with payload or metadata. Merge
validates both states and overlap before mutation. Finalize accepts read-only or
writable state and does not mutate it.

Field and state metadata are checked even for empty requests. Invalid calls
leave accumulator and payload unchanged. Type/dtype/scalar-kind failures raise
`TypeError`; invalid layout, region, field, state, writability, or overlap raises
`ValueError`.

## Numerical Evidence

Small integer-valued streams with exactly representable totals compare bitwise.
General finite evidence reports absolute, away-from-zero relative, and
finite-nonzero ULP error against `math.fsum`. Relative error is reported only
when

```text
abs(fsum) >= sqrt(eps) * max(1, math.fsum(abs(stream values))).
```

Adversarial cancellation records the expected serial absolute error rather than
widening tolerance. NumPy comparison is descriptive because its pairwise
strategy may differ.

Retained invariants include bit-identical results across capacities under the
persistent serial strategy, exact manual scalar-loop agreement, explicit merge-
tree examples that differ in low bits, empty identity, signed zero, NaN,
opposite infinities, and finite overflow classification.

## Performance And Memory

Update reads each selected value once and uses one fixed scalar state. No
payload-, field-, slot-, region-, chunk-, or topology-sized scratch is allocated.
Measure values/s, read bandwidth, region/slot/capacity scaling, fixed allocation,
NumPy runtime, accuracy versus `math.fsum`, and memmap-backed plan/gather/reduce
composition. Explore compensated states, vector/pairwise updates, or parallel
merge trees only as separately specified strategies after the serial baseline.

## Immediate Composition

FND-002 supplies streaming zero-reach semantics. PRI-001 supplies exactly-once
ascending primary order; STO-001 gathers the selected field/interior. INT-001
uses the persistent accumulator to prove bounded reduction of a payload larger
than the managed workspace.
