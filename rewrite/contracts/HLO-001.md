# HLO-001 Contract: Exact Hinted Refined Point Ownership

## Responsibility

HLO-001 resolves finite Cartesian 3D point owners by testing one explicit
last-owner hint before falling back to LOC-001 hierarchy descent. It owns hint
representation, the canonical hinted-leaf containment test, fallback choice,
and hit statistics. It defines no new ownership/tie meaning, adjacency walk,
payload, cache, sampling, stepping, termination, or scheduling.

## Stable Operation

```text
fill_refined_point_leaf_ids_with_hints(
    domain_lower,
    domain_upper,
    root_shape,
    domain_cell_counts,
    block_cell_counts,
    max_level,
    coord_to_rank,
    root_node_ids,
    node_levels,
    node_coords,
    child_node_ids,
    node_leaf_ids,
    leaf_node_ids,
    points,
    hint_leaf_ids,
    point_leaf_ids,
) -> HintedLocationStats
```

All domain/count/MOR/FST/GEO inputs have their completed LOC-001/GEO-002
representations and belong to one unchanged FST-002 lifecycle. `points` is
C-contiguous `float64[P,3]`. `hint_leaf_ids` is C-contiguous `int64[P]`; each
entry is `-1` for no hint or a canonical leaf ID in `[0,L)`. `point_leaf_ids` is
caller-owned writable C-contiguous `int64[P]`.

Success returns exact Python integers:

```text
point_count
interior_point_count
exterior_point_count
hint_candidate_count
hint_hit_count
hierarchy_fallback_count
```

`hint_candidate_count` counts nonnegative input hints, including hints attached
to exterior points. `hint_hit_count` counts interior points accepted by their
hint. `hierarchy_fallback_count = interior_point_count - hint_hit_count`.
Exterior points do not descend and receive `-1`.

## Exact Hint And Fallback Meaning

For a hinted leaf, derive its three lower/upper faces with the exact GEO-002
binary64 operation order from `node_levels`, `node_coords`, `leaf_node_ids`,
domain bounds/counts, and block counts. The hint owns a point exactly when for
every axis:

```text
leaf_lower <= point < leaf_upper
```

Thus a point on a shared face rejects the lower-side leaf's upper face and
accepts the upper-side leaf's lower face. Exact global upper is exterior. A
valid but wrong hint is not an error; LOC-001 root selection and flat hierarchy
descent supplies the owner. Returned owner IDs must be exactly equal to calling
LOC-001 for the same points regardless of hints.

The production Cython implementation shares the LOC-001 descent primitive and
performs no Python callback, allocation, adjacency query, or payload access in
its point loop. CHS-001 may call the unchecked path only after its session and
dynamic-call preflight establishes this complete contract.

## Validation, Mutation, And Errors

Before mutating `point_leaf_ids`, validate exact ndarray types, dtypes, ranks,
shapes, C-contiguity, output writability/nonoverlap, finite points, hint range,
LOC metadata, and every hinted leaf's GEO geometry/overflow invariants.
Type/dtype/scalar-kind errors raise `TypeError`; invalid layout, nonfinite point,
hint, map, hierarchy, or geometry raises `ValueError`; integer/spacing overflow
raises `OverflowError`. Ordinary failure leaves every output bit unchanged.

Inputs are borrowed read-only for the call and remain unchanged. No input or
output view is retained. The output may not overlap any input.

## Reference, Tests, And Performance

Exact comparison is LOC-001 output equality plus scalar canonical-face checks.
Cover empty/single/batch points; correct, absent, stale, sibling, ancestor-
region, and random valid hints; all lower/upper root/child/leaf faces; mixed
depth; exterior coordinates on every side; nonfinite/alias/range/geometry
atomicity; and randomized equality to LOC-001.

HLO-001 is `hot-kernel` because it runs at every streamline stage after session
validation. Measure checked and prevalidated singleton/batch latency for long
same-leaf runs, single-face transitions, divergent hints, and all-fallback
order. Record hint/fallback rates and immediate CHS/SLE latency. Investigate a
fallback regression above 10%; two stable cases above 20% block completion
unless the coherent hit benefit is material and both paths remain available.

HLO-001 deliberately stops before an exact neighbor transition. Such a path may
use TOP/REL or optional TOP-003 only after a streamline trace shows hierarchy
fallbacks remain material following last-owner hits and cache reuse.
