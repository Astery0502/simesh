# FND-002 Contract: Access Patterns And Halo Reach

## Responsibility

FND-002 describes the spatial input access of one consumer against the
FND-001 payload and valid-region conventions. It lets storage and halo planning
decide whether a requested output region is supported without knowing operator
arithmetic.

## Access Patterns

`AccessPattern` has exactly three contractual meanings:

- `POINTWISE`: each output cell may read only aligned input cells. Neighbor
  chunks are not required.
- `LOCAL_STENCIL`: each output cell may read a fixed bounded neighborhood.
- `STREAMING_REDUCTION`: valid input cells may be presented in bounded chunks
  with no spatial-neighbor access. RED-001 later defines accumulator state,
  associativity, merge order, numerical behavior, and exactly-once traversal.

The enum names and meanings are stable. Numeric enum values are an internal
Python/Cython bridge, not a serialization format.

## Per-Input Reach

One input requirement is `(pattern, lower_reach, upper_reach)`. Both reach
values are borrowed read-only, native-endian, C-contiguous signed `int64[3]`
triplets in `(x, y, z)` order. Entries are nonnegative.

For an output coordinate `p`, a consumer may read offsets `d` only within

```text
-lower_reach <= d <= upper_reach
```

componentwise. The pair is the tight smallest axis-aligned bound over every
offset the consumer may read and is constant across cells, slots, and chunks.
It does not claim that every cell inside the box is read.

Pointwise and streaming-reduction requirements use zero reach on both sides.
A local-stencil requirement has at least one nonzero reach entry. A reduction
of stencil results is expressed as stencil composition followed by reduction,
not as a reduction with halo.

An operator with several inputs declares one reach pair per input. FND-002 does
not define fields, formulas, exact sparse offsets, or output mutation.

## Region Algebra

For a nonempty requested output box `O = [output_lower, output_upper)`, the
minimal enclosing input box is

```text
[output_lower - lower_reach, output_upper + upper_reach).
```

`required_input_region(...)` returns this box exactly. It rejects a requirement
below storage coordinate zero and rejects signed-`int64` overflow.

For a nonempty input-valid box `V = [valid_lower, valid_upper)`, the maximum
aligned output-valid box is

```text
[valid_lower + lower_reach, valid_upper - upper_reach).
```

`valid_output_region(...)` returns this box when it contains at least one cell.
If the input box is empty or any input extent is no larger than the sum of its
two reaches, it returns the canonical empty box
`[valid_lower, valid_lower)`.

An input or output box is empty when any axis has zero extent.
`required_input_region(...)` canonicalizes an empty requested output to
`[output_lower, output_lower)`, because no output cells require no input reads.

`supports_output_region(...)` returns true for an empty output. Otherwise it is
true exactly when the available input-valid box contains the required input
box. An unrepresentable requirement remains an error rather than false.

All input boxes and reaches follow FND-001 ownership, dtype, contiguity,
zero-based, half-open, and signed-representability rules. Functions borrow and
do not mutate their inputs. Returned triplets are newly owned fixed-size
metadata arrays.

## Exactness And Evidence

Pattern validation and region arithmetic are exact. Required invariants are:

- zero reach is the identity for nonempty boxes;
- asymmetric expansion and contraction have no side off-by-one;
- for nonempty representable boxes, a valid input contains the required input
  exactly when its maximum output contains the request;
- contraction of a matching expansion recovers the original output box;
- each one-cell-short required face fails support;
- empty boxes require no reads;
- inputs remain unchanged and overflow is rejected before Cython.

The current central-difference kernel provides behavior evidence: symmetric
one-cell reach contracts a fully valid padded box by one cell on every side,
matching its produced valid region. Axis-selective stencils may declare tighter
reach than the current kernel's conservative all-axis loop bounds.

The arithmetic is `O(3)`, independent of payload size, and accesses no payload.
Only fixed-size metadata results are allocated. Payload throughput and parallel
scaling are therefore not relevant to FND-002.

## Immediate Composition

FND-001 produces the payload and valid boxes. OPR-001 consumes pointwise zero
reach. OPR-002 uses local-stencil reach against HAL-002-produced validity.
RED-001 consumes the streaming-reduction tag with STO-002 chunks. Halo
capabilities produce valid cells but do not interpret operator formulas.
