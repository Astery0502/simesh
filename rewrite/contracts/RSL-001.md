# RSL-001 Contract: Accepted Refined Relation Source-Slot Resolution

## Responsibility

RSL-001 maps active global source leaf IDs in accepted REL-001 rows to exact
positions in one unique STO-004 selected vector.  It preserves REL tensor shape
and inactive sentinels.  It defines no relation kind/mask interpretation,
action filtering, target box/phase, geometry/reach, restriction/prolongation,
workspace/payload, boundary rule, backend, or scheduling.

## Stable Operation

```text
resolve_refined_relation_source_slots(
    leaf_count,
    selected_leaf_ids,
    source_counts,
    source_leaf_ids,
    source_slots,
) -> None
```

`leaf_count` accepts Python/NumPy integer scalars except booleans and rank-zero
arrays.  It is nonnegative and signed-int64 representable.

`selected_leaf_ids` is borrowed read-only native-endian C-contiguous
`int64[S]`.  Every entry is in `[0,leaf_count)` and entries are unique.  It is
the complete STO-004 selected prefix plus support, but RSL does not interpret
primary/support positions.

`source_counts` is borrowed read-only C-contiguous `uint8[P,D]`, and
`source_leaf_ids` is borrowed read-only native-endian C-contiguous
`int64[P,D,4]`.  The `P` rows are exactly accepted REL rows.  `D` may be zero or
any caller-fixed REL-valid direction selection/order.  REL provenance and
kind/mask meaning are upstream; RSL validates the plain active/trailing source
representation.

Accepted row `p` corresponds upstream to primary selected slot `p`.  Therefore
`P <= S` is required even though RSL interprets only source identities.  Empty
`D` does not waive this invariant; empty `P` is valid.

`source_slots` is caller-owned writable native-endian C-contiguous
`int64[P,D,4]`.  Outputs and pointers are never retained.

## Exact Mapping

Traverse row `p`, direction `d`, then source column `q` in ascending order.

```text
if q < source_counts[p,d]:
    source_slots[p,d,q] =
        the unique s where selected_leaf_ids[s] == source_leaf_ids[p,d,q]
else:
    source_slots[p,d,q] = -1
```

Every active source must occur in `selected_leaf_ids`; the first missing active
source in traversal order raises `ValueError` before any output mutation.
Missing active sources never become `-1`, because that would be indistinguishable
from an inactive column.  Repeated global sources across rows/directions map to
the same slot.  Active source and REL finer-child order are preserved exactly.

RSL does not receive relation kinds.  PHYSICAL records naturally have count
zero; SAME, COARSER, FINER, and mixed records are mapped identically.  A later
planner owns action choice.

## Validation, Errors, And Atomicity

Validation order is `leaf_count` scalar kind/nonnegative/int64, selected vector
representation, counts representation, source representation/exact paired
shape, then output representation/shape/writability.  Value validation then
checks `P<=S`, selected ranges and uniqueness, count range `0..4`, active source
ranges, exact inactive source `-1` sentinels, output/input nonoverlap, and
complete active-source membership.  Only then is the full output written.

Wrong object/dtype/scalar kind raises `TypeError`.  Invalid rank, shape, layout,
writability, range, duplicate, count, sentinel, overlap, or missing source
raises `ValueError`.  Scalar overflow raises `OverflowError`.  Every failure
preserves the complete output.  Inputs may be read-only, may overlap each other,
and are never mutated or retained.

Empty `P` or `D` axes are valid after complete selected-vector and ordinary
representation validation.  Their exact output shape is still `[P,D,4]`.

## Independent Evidence

The independent reference uses a Python list, explicit duplicate checks, and
`.index` for each active source; it uses no production helper, hash, dense map,
sort, or bitmap.  Evidence covers arbitrary selected permutations; primary and
support slots; all REL kinds/mixed masks without interpretation; repeated
sources; exact tensor/trailing preservation; first/late missing atomicity;
selected duplicate/range, count, active/trailing corruption; empty/read-only/
overlap behavior; random balanced REL/STO windows; level-one HPL source-slot
reduction; WENO bounded roundtrip; and FINER/COARSER consumer probes.

Current canonical connectivity retains global one-based leaf identities and
has no bounded refined local-slot surface.  Relevant current evidence is the
same linear lookup behavior in HPL/HAL, exact current relation identities, and
canonical finer-child order before local mapping.

## Performance And Memory

Let `A=sum(source_counts)`.  The allocation-free linear implementation is
`O(S^2 + A*S + 4*P*D)` for checked uniqueness, complete relation validation,
membership/fill, and full output overwrite, with a second active lookup pass
after atomic preflight absorbed into `A*S`.  In an upstream-validated executor,
the unchecked fill is `O(A*S + 4*P*D)`.  No hash, inverse table, sort, bitmap,
heap, or size-dependent scratch is used.

Caller output is exactly

```text
8*P*D*4 = 32*P*D bytes.
```

For canonical `D=26`, this is `832*P` bytes.  A full WENO materialization would
be 18,814,848 bytes and is rejected; RSL is bounded per accepted chunk.  With
capacity 1,024 and `C=S=P=1,024`, REL rows, RSL slots, and selected IDs total
1,792,000 bytes.  Actual accepted `P` is reported.

Measure active lookups/s, tensor entries/s, actual comparisons, selected/row/
direction/count scaling, checked/unchecked time, fixed traced allocation,
reference ratio, WENO capacities 57/64/128/256/512/1024, and immediate action
scan consumption.  Exact mapping/output bytes are hard gates.  Standard >10%
investigation and reproduced >20% blocking gates apply to composed planning.
Parallelism is deferred unless later planning makes this metadata pass material.

## Immediate Composition

STO-004 supplies unique selected IDs and accepted REL source rows.  The next
refined transfer action/region planner consumes REL kinds, physical masks,
counts, and RSL slots to choose same-level, restriction, prolongation, physical,
and target-region actions.  RSL itself consumes no numerical values, payload,
geometry, boundary modes, or execution plan.
