# FLN-001 Contract: Normalized Magnetic Field-Line RHS

## Responsibility

FLN-001 maps sampled Cartesian magnetic vectors and an orientation sign to the
unit-arclength field-line RHS `(dx/ds,dI/ds)`, where
`I = integral(B dot dx)`, plus an exact row status. It owns the robust norm and
binary64 operation tree, exact zero/nonfinite/unrepresentable categories, sign
application, and output layout. It defines no interpolation, RK stepping,
termination policy, cache, I/O, or scheduling.

## Stable Operation

```text
field_line_rhs_into(
    field_vectors,
    direction_signs,
    rhs_values,
    rhs_statuses,
) -> None
```

`field_vectors` is borrowed read-only C-contiguous `float64[N,3]` in
`(Bx,By,Bz)` order. `direction_signs` is borrowed read-only C-contiguous
`int8[N]` with every entry exactly `-1` or `+1`. `rhs_values` is caller-owned
writable C-contiguous `float64[N,4]` in `(dx/ds,dy/ds,dz/ds,dI/ds)` order.
`rhs_statuses` is caller-owned writable C-contiguous `uint8[N]`.

Stable status codes are:

```text
RHS_OK                     = 0
RHS_ZERO_FIELD             = 1
RHS_NONFINITE_FIELD        = 2
RHS_UNREPRESENTABLE_NORM   = 3
```

On a successful call every status row is overwritten. An RHS row is overwritten
only for `RHS_OK`; every failed row preserves its prior bits.

## Numerical Meaning And Operation Tree

For a row with three finite components:

```text
ax = abs(Bx)
ay = abs(By)
az = abs(Bz)
m = ax
if ay > m: m = ay
if az > m: m = az
```

Exact `m == 0.0`, including every signed-zero combination, is
`RHS_ZERO_FIELD`. Otherwise evaluate each line as separately rounded binary64:

```text
ux = Bx / m; uy = By / m; uz = Bz / m
xx = ux*ux; yy = uy*uy; zz = uz*uz
xy = xx + yy
xyz = xy + zz
r = sqrt(xyz)
mag = m * r
tx = ux / r; ty = uy / r; tz = uz / r
rhs = (sign*tx, sign*ty, sign*tz, sign*mag)
```

The production implementation prevents contraction/FMA across the frozen tree.
Any NaN or infinity input is `RHS_NONFINITE_FIELD` before this arithmetic. If
`mag` is nonfinite, the row is `RHS_UNREPRESENTABLE_NORM`. For finite nonzero
input, `r` is finite/positive by construction; subnormal `m` remains valid when
the represented `mag` is finite and nonzero.

For `RHS_OK`, the first three components represent
`dx/ds = sign*B/|B|`, and the fourth is
`dI/ds = B dot dx/ds = sign*|B|`. The tangent Euclidean norm is compared to one
within binary64 rounding; RHS bits compare exactly with the scalar frozen tree.

## Validation, Ownership, And Errors

Before either output mutates, validate exact ndarray types, dtypes, ranks,
shapes, C-contiguity, output writability, signs, and all input/output and
output/output nonoverlap. Type/dtype failures raise `TypeError`; invalid layout,
sign, writability, or overlap raises `ValueError`. Ordinary failure preserves
all output bits. Inputs remain unchanged and no view is retained.

## Reference, Tests, And Performance

The independent scalar reference follows the written operation tree. Cover
empty and batch rows; all axes/signs; finite normals; constant scale invariance;
minimum/maximum normal and subnormal values; representable and overflowing true
norms; every signed zero; NaNs/infinities in each component; mixed statuses;
untouched failed RHS rows; aliases and atomicity. Check exact finite/status bits,
nonfinite category, tangent norm, orientation, and analytic `B dot tangent`.

FLN-001 is `hot-kernel`. The standard group profile records checked and
unchecked rows/s, validation/allocation, vector scale/status mixes, and its SLE
share. Investigate a same-runner median regression above 10%; two stable cases
above 20% block completion without a material composed benefit.

RKS-001 consumes successful RHS rows. TRM-001 maps failed RHS codes to
trajectory termination, and SLE-001 owns batching/result mutation.
