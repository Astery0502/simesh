# LIM-001 Contract: Cartesian Three-Point Limited Slope

## Responsibility

LIM-001 computes the exact current scalar limited slope from explicit left,
center, and right binary64 values.  It defines no coarse indexing/axis/reach,
coordinates, ratio-two phase or eta, reconstruction, region mutation, slope
storage/cache, relation/support meaning, workspace, backend, or scheduling.

## Stable Operation

```text
three_point_limited_slope(
    left_value,
    center_value,
    right_value,
) -> slope
```

Each input must have exact built-in Python `float` or exact NumPy `float64`
type.  Integers, booleans, other NumPy floating widths, subclasses, rank-zero
arrays, and other objects raise `TypeError`.  Validate left, then center, then
right.  NaN, infinity, signed zero, subnormal, and every other binary64 value
are valid inputs.  The result is an exact built-in Python `float`.

## Exact Binary64 Rule

Evaluate these as separate binary64 operations:

```text
slope_l = center_value - left_value
slope_r = right_value - center_value
sum_lr  = slope_l + slope_r
slope_c = 0.5 * sum_lr
```

Define exact helper behavior:

```text
abs_current(value) = -value if value < 0.0 else value
min_current(a,b)   = a if a < b else b
```

Then evaluate:

```text
if slope_c > 0.0:
    limited = min_current(
        abs_current(slope_c),
        min_current(slope_l, slope_r),
    )
    if limited <= 0.0:
        return +0.0
    return 1.0 * limited

if slope_c < 0.0:
    limited = min_current(
        abs_current(slope_c),
        min_current(-slope_l, -slope_r),
    )
    if limited <= 0.0:
        return +0.0
    return -1.0 * limited

return +0.0
```

Do not replace the first four operations with `0.5*(right-left)`, reassociate
them, scale one-sided differences, use FMA, or substitute generic `abs`, `min`,
`sign`, `minimum`, or minmod behavior.  The shared Cython rule is
`inline noexcept nogil` so PRL can consume it without callbacks.

## Finite And IEEE Behavior

For finite inputs, two positive one-sided differences return their smaller
positive value; two negative differences return the negative smaller
magnitude.  Opposite signs, either zero difference, a plateau, or an extremum
return exact positive zero.  This is not the common monotonized-central rule
that clips against twice each one-sided difference.

Every zero-return path emits bit pattern `0x0000000000000000`, never negative
zero.  Any NaN input makes `slope_c` NaN, both sign comparisons are false, and
the result is positive zero; LIM never returns NaN.  Same-sign infinite
differences may return signed infinity.  Centered-sum overflow can still return
the smaller finite one-sided difference.  Same-sign subnormal differences are
preserved when they are the limiting magnitude.

## Ownership And Errors

The operation has no mutable output and performs no input mutation, pointer
retention, cache, or size-dependent scratch.  Its only caller-visible object is
the ordinary Python-float return; the shared inline Cython rule allocates
nothing.  Scalar kind is the only validation failure and raises `TypeError`;
arithmetic follows the contracted binary64 rule without warnings, sanitization,
or alternate policy.

## Independent Evidence

The independent reference uses explicit NumPy `float64` scalar statements and
ordinary comparisons, not production helpers or vectorized minmod reductions.
Evidence covers increasing/decreasing/tied monotone cases; plateaus, extrema,
one-sided zero, and large-offset rounding; centered overflow with finite
limited output; every signed-zero combination; smallest subnormals; NaN in each
position; finite/infinite and opposite-infinity cases; random finite triples;
exact input-kind errors; exact Python-float output; and RST-produced constant,
affine, step, and quadratic coarse values.

Current source behavior is frozen directly because `_limited_slope` is an
internal inline function without a public callable.  PRL evidence later embeds
the same shared inline rule and compares complete current prolongation outputs.
