# SLE-001 Contract: Cached Native Refined Field-Line Execution

## Responsibility

SLE-001 executes one deterministic serial stage-major multi-seed field-line
schedule into caller-owned accepted-prefix results. It owns active-seed order,
CHS batch calls, scratch reuse, atomic candidate commit, aggregate statistics,
and external-failure prefix behavior. It defines no FLN/RKS/TRM/LOC/SAM/RHE
meaning, cache policy/provenance, adaptive control, periodicity, parallelism,
file ownership, or dataset lifecycle.

## Stable Operation

```text
execute_refined_field_lines(
    sampling_session,
    seeds,
    direction_signs,
    step_size,
    max_steps,
    positions,
    integrals,
    point_counts,
    termination_codes,
    termination_stages,
) -> FieldLineExecutionStats
```

`sampling_session` is an idle caller-owned CHS-001 session fixed to exactly
three ordered vector fields. `seeds` is borrowed read-only C-contiguous
`float64[N,3]`; every coordinate must be finite. `direction_signs` is borrowed
read-only C-contiguous `int8[N]` with entries exactly `-1` or `+1`.
`step_size` has RKS-001's finite positive normal binary64 scalar meaning.
`max_steps` is an exact nonnegative Python integer fitting `int64`.

Caller-owned outputs are writable C-contiguous:

```text
positions           float64[N,max_steps+1,3]
integrals           float64[N,max_steps+1]
point_counts        int64[N]
termination_codes   uint8[N]
termination_stages  uint8[N]
```

Outputs are pairwise nonoverlapping and do not overlap seeds/signs, session
owned/borrowed arrays, or reader memory. The session is retained by the caller;
SLE clears neither cache nor history.

## Initialization, Schedule, And Commit

Complete all static type/layout/scalar/shape/alias/byte validation before any
output/cache mutation or I/O. Then initialize each seed in ascending input ID:

- finite exterior seed: count zero, `SEED_OUTSIDE`, stage `CONTROL`, no position
  or integral write;
- interior seed: write position zero from the seed, write integral positive
  zero, set count one, status `ACTIVE`, stage `CONTROL`.

If `max_steps==0`, every interior seed becomes `MAX_STEPS` without sampling.

For each accepted-step round, active seed IDs remain ascending. SLE performs
stage-major k1, k2, k3, k4 batches. Before each CHS call, classify private stage
states with TRM-001; terminated rows leave the active set and are not sampled.
Pass each survivor's most recent sampled owner as its HLO hint (`-1` before its
first sample). CHS returns exact vectors and current owners; FLN-001 maps them
to augmented RHS rows or per-seed termination. RKS-001 constructs the next
private stage/candidate for survivors.

If CHS raises its stable `UnrepresentableRefinedSampleError` during dynamic
preflight, classify the identified seed as `UNREPRESENTABLE_SAMPLE` at the
current K1--K4 marker, remove it, and retry the remaining compact batch. CHS
guarantees that rejected preflight changed no cache/value/I/O state. Multiple
invalid rows are removed through repeated deterministic lowest-reported-index
retries. Any other CHS exception propagates with the prefix behavior below.

After k4, classify candidates in ascending seed ID. An `ACTIVE` candidate is
committed by writing the complete position/integral at the next prefix slot and
then incrementing its count. No rejected stage/candidate is appended. Continue
until every seed terminates or exactly `max_steps` candidates have been accepted
for remaining seeds; those become `MAX_STEPS`, stage `CONTROL`.

This ordering is fixed:

```text
round -> k1 active IDs -> k2 survivors -> k3 survivors -> k4 survivors
      -> candidate classification/commit in ascending ID
```

Cache capacity/history/backend may change CHS calls/bytes only. With identical
input field bits, every accepted position/integral/status/stage/count is
bitwise/exactly invariant.

## Result And Failure Semantics

Only accepted position/integral prefixes and the complete control arrays are
written on successful execution. All tail bits remain caller supplied.
Numerical termination codes/stages have exact TRM-001 meaning and do not raise.

After ordinary preflight, any propagated data-dependent CHS/backend/resource
exception preserves previously committed trajectory points and completed
terminal seeds. The current attempted step is not appended because every stage
and candidate is private. CHS may retain earlier successful admissions; its
failed miss follows CHS failure rules. Active current/later seed codes may
remain `ACTIVE` because the overall call did not return successfully. No
rollback is attempted for hardware/process failures.


An attempted step starts when an interior active seed enters k1. An accepted
step is one committed candidate. Stage samples count rows in successful CHS
calls, while sampler calls count every nonempty CHS invocation attempt,
including a classified preflight rejection.
`sampler_preflight_rejection_count` counts that subset. CHS delta fields sum
exactly across successful calls; maximum selected slots takes their maximum.
`sampler_call_managed_peak_bytes` is the maximum of successful CHS stats and
the exact rejected-plan bytes carried by each
`UnrepresentableRefinedSampleError`. The
termination histogram sums to `seed_count` and matches output codes.
`accepted_point_count = interior_seed_count + accepted_step_count`.

`executor_managed_array_bytes` is the exact SLE-owned private NumPy scratch total
at peak, including active IDs, last owners, compact stage points/vectors/owners,
augmented base/stage/RHS/candidate rows, FLN statuses, and classification masks.
`session_managed_array_bytes` is CHS's separately reported persistent total.
Caller inputs/outputs, borrowed metadata, backend page cache/buffers, Python
objects, sorting transients, and process RSS are excluded.

## Validation And Errors

Type/dtype/scalar-kind failures raise `TypeError`; invalid shape/layout/sign/
step/budget/session state/writability/alias raises `ValueError`; dimension and
raw-byte arithmetic overflow raises `OverflowError`. Nonfinite user seeds are
ordinary `ValueError` before output/cache/I/O. Sampled nonfinite fields,
generated nonfinite states, and the stable CHS unrepresentable-sample exception
are classified results. Other data-dependent CHS/backend/resource exceptions
propagate with prior-prefix semantics. Initial caller-input ordinary failure
preserves every output bit and cache history.

## Reference, Tests, And Performance

The reference is a scalar one-seed FLN/RKS/TRM composition using exact CHS/RPS
samples. Cover empty/single/multiple seeds; forward/backward constant lines and
oriented integrals; rotational convergence; exterior and exact upper seeds;
max-step zero/positive; every RHS/state/no-progress/domain termination at every
stage; mixed seed outcomes; cache zero/working-set/resident and array/native
invariance; mixed refined/PBC sampling; tail preservation; aliases/overflow/
ordinary atomicity; reader failure at each stage; accepted-prefix/cache state;
and exact stats/memory.

SLE-001 is `milestone-workflow`. The standard profile uses single/multiple
seeds, short/long coherent and divergent paths, synthetic analytic fields, and
real tdm native fields. Record steps/points/s, per-step latency distribution,
hint/fallback and owner transitions, cache hits/misses/evictions, halo fills,
reader calls/logical/native bytes per accepted point, cold/warm cache capacity,
managed/output/peak/RSS memory, termination histogram, trajectory/integral
errors, and independent-seed scaling. There is no current tracer performance
baseline; public RPS and scalar integration are semantic/structural comparators.

The completed native trajectory trace decides whether to activate a separate
direction-projected support planner, raw-interior cache, exact neighbor
transition, adaptive RK, or parallel seed strategy.
