# RST-001 Contract: Cartesian 3D Ratio-Two Cell-Average Restriction

## Responsibility

RST-001 computes one Cartesian 3D ratio-two cell-average restriction over an
explicit canonical fine region into an explicit translated coarse region.  It
defines only local numerical averaging and region mapping.  It defines no
forest/relation/support meaning, selected-slot mapping, child phase, halo
policy, geometry, physical transform, coarse-scratch ownership, prolongation,
backend, scheduling, or parallel strategy.

## Stable Operation

```text
restrict_cartesian_2to1_into(
    fine_payload,
    fine_lower,
    fine_upper,
    coarse_payload,
    coarse_lower,
) -> None
```

`fine_payload` is borrowed read-only native-endian C-contiguous
`float64[S,F,fx,fy,fz]`.  `coarse_payload` is caller-owned writable
native-endian C-contiguous `float64[S,F,cx,cy,cz]`.  Their slot and field
extents match exactly; zero slots or fields are valid.

`fine_lower`, `fine_upper`, and `coarse_lower` are borrowed read-only
native-endian C-contiguous `int64[3]` triplets.  All regions use FND-001
half-open storage coordinates.

## Region Mapping

The fine box is ordered, nonnegative, and contained in the fine spatial shape.
Let

```text
fine_extent = fine_upper - fine_lower
coarse_extent = fine_extent // 2
coarse_upper = coarse_lower + coarse_extent.
```

Every fine extent is even; zero is valid.  `coarse_lower` is nonnegative, its
translated upper is signed-int64 representable, and the derived coarse box is
contained in the coarse spatial shape.  On an axis with zero derived extent,
the corresponding lower may equal that payload's spatial extent, consistent
with an empty half-open box.

For every slot `s`, field `f`, and
`q in [0,coarse_extent[0]) x [0,coarse_extent[1]) x
[0,coarse_extent[2])`, let

```text
(i,j,k) = fine_lower + 2*q
(I,J,K) = coarse_lower + q.
```

The call writes exactly `coarse_payload[s,f,I,J,K]`.  Every coarse value
outside the translated box is bitwise preserved.  Fine cells outside the
declared fine box are not read.

## Exact Binary64 Rule

For each output independently, evaluate eight input values through seven
binary64 additions in this exact sequence, then one binary64 multiplication:

```text
total = fine[i  ,j  ,k  ]
total = total + fine[i+1,j  ,k  ]
total = total + fine[i  ,j+1,k  ]
total = total + fine[i+1,j+1,k  ]
total = total + fine[i  ,j  ,k+1]
total = total + fine[i+1,j  ,k+1]
total = total + fine[i  ,j+1,k+1]
total = total + fine[i+1,j+1,k+1]
coarse[I,J,K] = total * 0.125
```

This freezes the current Cartesian 3D `coarsen_grid` arithmetic.  Pairwise
trees, vectorized means, division, and reassociation are not equivalent
contracts.  Finite overflow, signed zero, infinity, and NaN follow these
ordinary platform binary64 operations; no alternate sanitization or reduction
policy is applied.  Output-cell loop order is not semantic because cells are
independent and overlap is forbidden.

## Validation, Empty Calls, And Atomicity

Validation order is fine payload representation, fine-lower triplet,
fine-upper triplet, coarse payload representation/writability, then
coarse-lower triplet.  Cross-validation then checks exact slot/field equality,
fine-region order/containment, even extents, coarse-lower nonnegativity,
translated-upper overflow/containment, and output overlap with the fine payload
or any metadata input.

Wrong object or dtype raises `TypeError`.  Invalid rank, shape, layout,
writability, region, parity, bounds, or overlap raises `ValueError`.
Unrepresentable translated coarse bounds raise `OverflowError`.  All failures
preserve the complete coarse output.  Inputs and metadata are never mutated or
retained.

After full validation, zero slots, zero fields, or any zero spatial extent is a
no-op.  Empty calls do not weaken representation, bounds, parity, or overlap
validation.

## Independent Evidence

The independent reference uses scalar Python indexing and the contracted
addition sequence rather than NumPy reduction.  Evidence covers axis-coded and
nonassociative cells, constants, affine fields, random multi-slot/multi-field
translated boxes, complete region partitions, signed zero/infinity/NaN,
read-only fine input, output preservation, every representation/range/parity/
overlap failure, empty calls, and bitwise current `coarsen_grid` comparison for
eligible fine leaves.  STO gather plus restriction is compared with resident
restriction independently of chunk capacity/order.

## Performance And Memory

One output field-cell performs eight binary64 reads, seven additions, one
multiplication, and one write: 72 effective bytes excluding cache effects.
Measure coarse cells/s, fine values/s, effective GB/s, validation cost, block
shapes, fields, slots, scaling, caller output bytes, retained/peak allocation,
scalar-reference ratio, current descriptive runtime, and separate STO gather
and restriction composition times.  The kernel allocates no payload scratch or
size-dependent state.  Parallel scaling is deferred until serial composed
profiling shows material benefit.

## Immediate Composition

STO-004 supplies a bounded selected-leaf plan and STO-001/003 gathers selected
fine interiors into canonical slots.  RST-001 may restrict any explicit subset
presented as its own canonical payload or contiguous slot slice; it performs no
slot selection or compaction.  A later refined transfer capability owns global
source-to-slot mapping, child phase, source/target regions, coarse workspace
validity, and copy/application order; limiter and prolongation remain separate
numerical capabilities.
