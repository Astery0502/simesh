# PRI-001 Design: Ascending Primary Prefix

## Trigger And Inventory

WSP-001 extracted the first STO-002 Yellow decision.  The next independently
variable decision is topology-free primary traversal: the existing no-closure
branch uses the face table only for its row count, fills a maximal ascending ID
prefix, and returns identical primary/selected counts.  Face and full-halo
branches additionally own support decisions and remain untouched.

## Alternatives

Keeping no-closure in the mode-bearing STO wrapper preserves a false topology
dependency in streaming consumers.  A generic traversal object or arbitrary-ID
iterator would add scheduling/state beyond the dense supported behavior.

Expose one caller-buffered fill over explicit `block_count`.  Keep the old
`plan_level1_chunk(..., False, ...)` validation and tuple surface as a delegating
compatibility path.  Migrate the M0 pipeline's preflight/pass-one loops as the
first production consumer; pass two remains full-halo planned.

## Decomposition Record

Responsibility: fill the maximal ascending contiguous dense primary-ID prefix
that fits one explicit caller buffer.

Owned semantic decisions: zero-based dense identity, ascending order, maximal
capacity use, end-of-stream behavior, unfinished zero-capacity rejection,
prefix overwrite, suffix preservation, scalar/output errors, and exactly-once
coverage when successive calls advance by the returned count.

Explicitly non-owned decisions: byte budgets/capacity choice, topology, face/
halo/refined closure, minimum closure progress, support union/promotion/order,
selected count, slot mapping, transfer, payload, backend, parallelism, caching,
or scheduling.

Inputs and outputs: two integer scalars and caller-owned writable C-contiguous
`int64[S]`; one exact Python integer count.

Mutation and ownership: validate completely, overwrite only the returned
prefix, preserve the suffix, retain nothing, and use no size-dependent scratch.

Access pattern / halo reach: metadata-only dense traversal; no payload or
topology access.

Independent reference or invariant: Python `range`; maximality; suffix bits;
end/zero-capacity cases; full exactly-once traversal; compatibility with
arbitrary unused face-table values; WSP capacity composition.

Immediate producer and consumer: WSP-001 normally supplies buffer capacity;
the M0 pipeline's dry preflight and pass one consume PRI directly.  STO-002's
false wrapper and RED/SAM/OPR callers remain compatibility evidence.

Kernel and composed measurement boundary: IDs/s, calls/s, full traversal time,
capacity/final-prefix scaling, fixed allocation, wrapper overhead, pipeline
bitwise conformance, and bounded RED streaming order.

Five-question result: yes/yes/yes/yes/yes.  PRI owns dense primary identity and
prefix fill only; every support and execution decision stays downstream.

## Compatibility Baseline

The existing no-closure planner passes 52 relevant regression tests and writes
about 51, 210, and 746 million primary IDs/s for capacities 64, 256, and 1,024
over 32,768 blocks.  The old wrapper must preserve validation precedence,
`(count,count)`, suffix/end behavior, and these throughput characteristics.
