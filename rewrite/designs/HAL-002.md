# HAL-002 Design: Same-Level Level-1 Halos

## Problem

A bounded STO-002 workspace contains a primary prefix and the complete clipped
one-block neighborhood of every primary. HAL-002 must finish each primary's
padded region from those selected interiors while preserving HAL-001's physical
rules at mixed physical/sibling edges and corners. Support slots are reusable
inputs, not additional outputs.

## Alternatives

An ordered face sweep can propagate face values into edges and corners, but it
reads mutable halo state, makes physical post-composition order significant, and
still needs loaded diagonal interiors for bounded chunks. A stored global-ID to
slot map would simplify lookup but adds selection- or topology-sized scratch to
the explicit workspace budget. A fused directional cuboid kernel can reduce
per-cell classification overhead, but it is more intricate and should be
justified only after the direct path is measured.

The selected approach maps every primary halo cell directly to one selected
source interior. Sibling crossings choose a neighboring block and the opposite
interior layer. Physical crossings choose HAL-001's clamped or reflected local
coordinate. The source block is derived by TOP-001 face walks in x/y/z order;
physical transforms then apply in the same x/y/z order as HAL-001. Each primary
builds a fixed 27-entry source-slot table on the C stack, found by linear scans
of the caller's selected IDs. This introduces no hash, dense map, or heap
scratch and never depends on support halo contents.

The independent Python reference uses explicit coordinates and dictionary-free
linear slot lookup. The initial Cython form mirrors it cell by cell. A later
directional cuboid variant is credible only if composed measurements show this
classification work is material beside gathering and downstream sampling.

## Current Ordering Conflict

Independent contract review found a noncommuting mixed-boundary case where the
current imperative ghost passes do not preserve HAL-001's established order. In
a `2x2x2` root grid with x-low no-inflow, y-high antisymmetry, and a z-high
sibling crossing, the direct HAL order maps `+611` to `+0.0` and then `-0.0`;
the current pass sequence returns `-611`. The review observed 16 bitwise
mismatches in that focused fixture.

The selected contract keeps deterministic x/y/z physical composition. This is
an intentional numerical divergence for noncommuting mixed physical/sibling
corners, not a reason to make the functional result depend on mutation passes.
Current comparisons remain exact for sibling placement and commuting boundary
configurations, while the conflicting fixture is retained to prove and bound
the divergence. Independent re-review agreed that this correction resolved the
sole contract objection and that the direct contract was ready to implement.

## Optimization Result

After the direct reference and checked Cython loop agreed bitwise, disabling
memoryview bounds and wraparound checks inside the fully prevalidated hot loop
improved the measured kernel by about 2.3--2.5x and the composed path by
1.4--1.5x. A separate early-interior branch changed representative runtimes by
less than 6% and regressed broad halos, so it was removed. Directional cuboid
fusion would duplicate the mixed-boundary logic across 26 regions; the retained
loop already reaches 129--237 million written values/s in larger measured
chunks, so that complexity is deferred until a real sampling consumer shows a
material composed benefit.
