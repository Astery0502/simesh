# FND-001 Design: Core Layout And Region Conventions

## Problem

The rewrite needs one unambiguous interchange boundary before Morton mappings,
storage, halos, and operators can compose. The current implementation exposes
field-major block data but stores padded mesh data field-last, and it mixes
Python half-open slices with inclusive internal bounds. Preserving both choices
would make every early kernel layout-polymorphic without evidence that this is
useful.

## Choices Considered

For block payloads, the credible choices were field-major
`(block, field, x, y, z)`, field-last `(block, x, y, z, field)`, or arbitrary
strides. Field-major matches the current reader and public block surface,
makes each field's z-contiguous block directly streamable, and avoids an
adapter transpose. Field-last can help operations over many fields at one cell,
but it would impose conversion on the first producer. Arbitrary strides defer
the decision into every kernel and complicate measured optimization.

For valid cells, a symmetric halo-width scalar is compact but cannot express
asymmetric chunks or stencil-shrunk results. Per-cell masks express more than
M0 needs. A half-open spatial box is sufficient and composes with NumPy slices.

For visible indices, unsigned values match parts of the current Cython code,
but signed `int64` keeps zero available as a real ID and allows later contracts
to choose a negative missing-neighbor sentinel without changing dtype.

## Selected Direction

Use C-contiguous `float64` block chunks in field-major
`(slot, field, x, y, z)` order. Use zero-based signed `int64` indices and
half-open `[lower, upper)` spatial boxes. Keep chunk-local slots distinct from
global block IDs. Inputs are borrowed read-only, while callers own and provide
all output and workspace buffers.

Alternative measured scratch layouts remain possible later, but conversion to
the canonical interchange layout must be explicit. Disk serialization order,
topology flattening, halo requirements, and source protocols are deferred to
their capabilities.
