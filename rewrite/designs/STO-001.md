# STO-001 Design: In-Memory Block Transfer

## Problem

M0 consumers need an explicit source and sink over resident canonical block
arrays. Current APIs mix views, detached advanced-index copies, implicit all-
block ordering, and hidden field naming. The rewrite also needs to move an
interior or already-valid halo box into a caller-owned padded buffer.

## Choices Considered

Returning views would reintroduce selector-dependent ownership and stale-halo
state. Allocating gather results would prevent workspace reuse. Whole-block-only
copying is smaller but forces an extra pass whenever a padded workspace is the
immediate consumer. Arbitrary request objects or storage classes are premature.

Scatter duplicate rejection requires sorting or selection-sized uniqueness
state. A fixed serial slot-major/field-slot order instead gives deterministic
last-write-wins behavior and keeps the operation allocation-free. Callers that
need disjoint parallel writes can provide unique selectors later.

## Selected Direction

Use two caller-buffer functions over canonical
`(global_block, field, x, y, z)` backing. Select blocks and field positions with
explicit `int64` vectors, translate one common half-open valid box, and preserve
everything outside the target. Validate the complete request before mutation.

Implement exact Cython copies with a general contiguous-z row path and larger
contiguous-suffix `memcpy` paths. Keep NumPy basic-slice loops as the independent
reference. Defer budgets, protocols, file backing, selector sorting, caching,
and parallel execution to STO-002 or composed consumers.
