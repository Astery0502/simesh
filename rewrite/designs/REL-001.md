# REL-001 Design: Balanced Refined Direction Relations

## Problem

TOP-002 returns a raw target node and BAL-001 admits the forest, but refined
halo/support consumers need one usable record for each selected leaf and full
direction.  A full direction may cross one or more physical axes while still
having an in-domain same/coarser/finer source along its remaining components.
The current 27-direction table collapses every such mixed case to physical.

## Alternatives

Returning only target node plus kind would repeat fine-child expansion in every
consumer and would add little beyond TOP-002.  Retaining current global 27/64
tables fuses relation meaning with one support-cache layout and costs 472 bytes
per leaf.  A six-face TOP-003 cache does not encode edge/corner sources or mixed
physical masks and cannot be a semantic dependency.

Emit a selected Cartesian-product record: kind, physical-axis mask, source
count, and up to four canonical source leaf IDs.  Physical components are
neutralized before TOP lookup.  For a finer reduced contact, expand the exact
immediate children touching the reduced contact region in canonical child
order.  Physical-neutralized axes admit both child bits; narrowing them for a
specific reflection depth or boundary rule belongs to later transfer planning.

## Decomposition Record

Responsibility: materialize the complete balanced non-periodic relation fact
for selected canonical leaf IDs and explicit noncenter directions.

Owned semantic decisions: physical-axis detection and bit mask; reduced
in-domain direction; physical/coarser/same/finer kind; exact touching source
leaf set; canonical fine-source order; sentinels and atomic caller outputs.

Explicitly non-owned decisions: raw contact discovery, forest conformance,
balance policy, global cache retention, geometry, cell-region phase, physical
coordinate/value rule and multi-axis transform order, restriction/prolongation
formula, support union/order/capacity, selected-slot mapping, payload, storage,
backend, scheduling, and periodicity.

Inputs and outputs: borrowed FST/TOP arrays plus selected leaf vector and one
shared direction matrix; caller-owned `uint8[P,D]` kind/mask/count arrays and
`int64[P,D,4]` source IDs.

Mutation and ownership: all inputs read-only borrowed; outputs are completely
validated and then overwritten; no relation or query scratch is retained.

Access pattern / halo reach: metadata-only selected leaf-by-direction records;
no payload access or assumed halo width.

Independent reference or invariant: common-maximum-level integer leaf boxes
with positive-overlap matching along reduced-zero axes; level-1 reduction to
HPL source/mask meaning; reciprocity; all directions/child phases; current and
real-tree comparisons.

Immediate producer and consumer: FST-002 and BAL-001 establish the lifecycle;
TOP-002 supplies raw contact semantics.  STO-004 later unions global source
leaf IDs under an explicit capacity policy, and transfer/halo capabilities use
kind/mask/sources without changing relation meaning.

Kernel and composed measurement boundary: records/s, emitted source IDs/s,
kind/mask/direction mix, fixed allocation, exact `35*P*D` output bytes,
FST-to-BAL-to-REL lifecycle, bounded selections, and face-only/all-direction
cache comparisons.

Five-question result: yes/yes/yes/yes/yes.  Fine expansion is intrinsic to the
balanced relation record; support union and transfer-specific phase selection
remain independently variable downstream decisions.

## Performance Gate

Compare a fused inline TOP lookup/classification/expansion with the simple
two-pass TOP-output reference.  Measure six faces and all 26 directions on
uniform, mixed, and real forests.  TOP-003 remains deferred unless a concrete
repeated face consumer amortizes its build and `54*L` retained bytes; it cannot
accelerate most edge/corner or mixed records.  Stop after the scratch-free
selected implementation reaches a useful bounded runtime/memory trade-off.
