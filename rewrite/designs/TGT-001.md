# TGT-001 Design: Directed Halo Target Boxes

## Problem And Alternatives

A requested halo envelope must be partitioned into full face/edge/corner target
boxes.  Current tables mix this simple geometry with physical status, symmetric
ghost width, refinement phases, scratch layout, and send order.  Computing each
box repeatedly inside later action loops duplicates fixed integer work; coupling
it to refined phase validation makes unrelated failures block valid geometry.

Use one caller-buffered direction-box function.  It knows only the requested
envelope, interior box, and explicit directions.  Refinement phases remain
RPH-001; PBC and value application remain later.

## Decomposition Record

Responsibility: map each explicit noncenter Cartesian direction to its exact
half-open target box in one requested envelope.

Owned decisions: lower/center/upper interval selection per direction component;
direction order/repetition; empty sides; validation, atomicity, and ownership.

Explicitly non-owned decisions: relation kind/mask/source/phase; requested reach
choice; source boxes; PBC rules; RST/PRL values; workspace/payload; refinement;
backend; scheduling; periodicity; or 2D policy.

Inputs and outputs: four `int64[3]` boxes, directions `int64[D,3]`, and two
caller-owned `int64[D,3]` outputs.

Mutation and ownership: complete validation precedes either output; both are
fully overwritten on success; inputs remain unchanged; nothing is retained;
the kernel uses no size-dependent scratch.

Independent reference and invariants: Python per-axis selection; every
direction/subset/reorder/repeat; asymmetric and zero-width sides; canonical 26
pairwise disjoint union; current safe table cases; singleton-axis rewrite
boxes; complete representation/overlap atomicity.

Immediate producer and consumer: FND boxes and an explicit direction selection
produce TGT.  Later refined action/region application consumes boxes alongside
independent RPH phase facts and REL actions.

Kernel and composed measurement boundary: directions/s, fixed validation,
exact 48*D bytes, allocation, subset/size scaling, reference/current comparison,
and native materialize-once versus repeated derivation scans.

Five-question result: yes/yes/yes/yes/yes.  TGT is one reusable integer
partition, independently substitutable and measurable, with no refinement,
storage, numerical, or execution policy.

## Performance Gate

Standard input uses an asymmetric padded box and canonical 26 directions.
Compare checked/unchecked/list reference with exact full arrays, then compare
one native materialization plus native scans against repeated native derivation
into the same-shaped output.  Include artifact creation and exact 48*D bytes.

Investigate >10% and block reproduced >20% composed regressions absent a
documented memory/complexity benefit.  Do not add phase tensors, action enums,
payload scratch, dynamic dispatch, or parallelism.
