# RED-001 Design: Streaming Field Sum

## Alternatives

Whole-array NumPy summation is fast and often pairwise, but it does not expose
bounded state or a stable chunk/merge order. Per-chunk partial sums followed by
scalar merging make results capacity-dependent. Kahan/Neumaier states improve
some errors but add merge semantics that are not associative either and are not
needed to establish the first reduction contract. Parallel trees likewise need
an executor policy first.

Use one caller-owned binary64 scalar state. Update it by visiting slots then
x/y/z in canonical C order and performing one separately rounded addition per
value. A persistent state across ascending no-closure primary chunks produces
the same binary sequence for every capacity. A separate one-addition merge
primitive exists for explicitly chosen partial trees; the contract never calls
floating addition associative merely because real addition is.

Finalization copies the state value. This minimal design handles empty and
nonfinite streams explicitly, uses fixed memory, and gives INT-001 a genuine
out-of-core reduction before compensated or parallel strategies are justified.

## Optimization Result

The fixed scalar dependency chain reaches about 280 Mvalue/s (2.24 GB/s) on
larger retained cases. NumPy is roughly an order of magnitude faster through a
different vector/pairwise strategy, but substituting it per chunk changes both
the global addition order and capacity invariance. A 16 MiB memmap stream reaches
274 Mvalue/s at capacity 1,024 with fixed managed state. Compensated, pairwise,
SIMD, and parallel trees therefore remain distinct future contracts rather than
silent optimizations of this serial baseline.
