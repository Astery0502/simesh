# RST-001 Design: Cartesian 3D Ratio-Two Restriction

## Problem And Current Rule

The current refined halo path averages every fine leaf that has a coarser
contact into an eagerly retained all-leaf coarse scratch array.  For each
coarse cell it adds the eight `2x2x2` fine values in fixed
`000,100,010,110,001,101,011,111` order and then multiplies by exact binary64
`0.125`.  Relation classification, child phase, physical filling, scratch
assembly, copies, prolongation, and global pass order surround that one
numerical rule but can vary independently.

## Alternatives

A refined-halo dispatcher would preserve the current coupling and prevent
independent numerical validation.  A NumPy reshape/mean is a useful descriptive
comparator but may allocate and uses a different reduction tree.  A fused
gather/restrict kernel could save one bounded payload write, but would couple a
storage strategy to restriction before composition shows a material bottleneck.

Use one pure region kernel over canonical caller-owned payloads.  It maps an
explicit even fine box to a translated coarse box, fixes the per-cell binary64
order, and owns no topology or scratch lifetime.  STO gather plus this kernel is
the first composed strategy; fusion is considered only after exactness and
measurement.

## Decomposition Record

Responsibility: compute Cartesian 3D ratio-two cell averages for explicit
fine-cell groups into an explicit translated output region.

Owned decisions: local `2x2x2` mapping; fixed eight-value addition order;
final `0.125` multiplication; fine/coarse region translation; complete
requested-box overwrite and outside-box preservation; empty behavior,
validation, and atomicity.

Explicitly non-owned decisions: forest/contact/relation kind; support union;
global leaf-to-slot mapping; child phase; which cells require transfer; source
or target halo boxes; geometry; physical rules; coarse scratch shape/validity/
lifetime; limiter/prolongation; field selection; payload source/backend;
resident/bounded scheduling; parallelism; or 2D.

Inputs and outputs: borrowed canonical `float64[slot,field,x,y,z]` fine input,
three `int64[3]` region lowers/upper, and caller-owned canonical coarse output.
Slot/field extents match; the derived output extent is half the even fine
extent.

Mutation and ownership: only the translated coarse box changes.  Fine payload
and metadata remain unchanged, output/input overlap is forbidden, all
validation precedes mutation, and no pointer or allocation is retained.

Access pattern and reach: each output reads exactly its disjoint local
`2x2x2` fine group.  It has no fine halo requirement and establishes only the
declared coarse output box.

Independent reference and invariants: a scalar Python loop with the same
explicit addition sequence; axis-coded and nonassociative values; constants;
affine-center averages; partition completeness; finite conservation error;
and bitwise comparison with current `coarsen_grid` output on eligible leaves.

Immediate producer and consumer: STO-004 chooses selected global leaves,
STO-001/003 gathers their interiors, and RST-001 restricts chosen slots.  A
later transfer plan maps restricted cells to coarse-primary halos.  The
numerical kernel depends only on FND-001; the ledger also records STO-001/004
because bounded gather composition is required before completion.

Kernel and composed measurement boundary: coarse cells/s, fine values/s,
effective 72-byte traffic per output field-cell, validation cost, output bytes,
allocation, block/field/slot scaling, scalar and current comparisons, and
separate gather/restrict times.  Relation planning, support amplification,
scratch assembly, and halo writes are reported but not attributed to the RST
kernel.

Five-question result: yes/yes/yes/yes/yes.  The numerical average can be
validated, substituted, and measured without any storage or halo policy.

## Performance Gate

Freeze exact outputs before optimization.  Start with the direct Cython loop;
then compare only credible loop orders or a composed gather/restrict variant.
Exact bits, zero retained allocation, and preservation outside the output box
are hard gates.

The standard kernel workload is canonical fine payload
`float64[64,4,16,16,16]` restricted to `float64[64,4,8,8,8]`.  Scaling covers
even cubic fine shapes 4/8/16/32, fields 1/4/8, and slots 1/8/64/256.  The
same-run direct comparators are the scalar exact oracle on bounded cases and an
explicitly reported vectorized NumPy expression on standard cases; current
`coarsen_grid` is a correctness and aggregate descriptive comparator because
it is not independently callable.  The composed comparator restricts the same
resident source once directly and once through STO gather into bounded slots,
with gather and RST times reported separately and exact outputs required.

Hypothesis: the allocation-free direct loop adds no material overhead over the
retained eight-read/seven-add/current arithmetic, while bounded-composition
overhead is attributable to the separately measured gather and repeated support
loads rather than hidden RST state.  Investigate a same-run slowdown above 10%
against the relevant established comparator; a reproduced slowdown above 20%
blocks completion unless an explicit memory/complexity improvement justifies
it.  Stop when further variants do not materially improve the
runtime-memory-complexity trade-off.  Parallel scaling is deferred unless the
serial kernel is material in the composed profile.
