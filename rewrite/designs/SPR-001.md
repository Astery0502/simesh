# SPR-001 Design: Explicit Selected-Primary Refined Support

## Choice

Accept one immutable strictly increasing primary-leaf vector plus a position into
that vector.  A bounded REL lookahead contains exactly
`min(selected capacity, remaining primaries)` rows.  Greedily admit its maximal
prefix and emit accepted primaries first followed by unique support in stable
direction/source discovery order.

Sparse gaps remain valid.  This preserves STO-004's selected-slot representation
and support semantics but replaces its independently variable dense-primary
enumeration.  An executor
validates the complete primary selection once and uses the unchecked operation
for successive windows.  The checked standalone operation retains full
validation and atomicity.

Dense-run decomposition was rejected as the primary selected strategy because
fragmented selections require many unrelated plans or inclusion of gaps.
Arbitrary caller order is deferred to a higher selection/result adapter that
can retain an inverse permutation when a real API requires it.  Hash/bitmap
membership is deferred: bounded
balanced closures have a small fixed source bound, and the first real
plan-to-gather composition owns that trade-off.

## Decomposition Record

Responsibility: plan the maximal prefix of one explicit selected-primary stream
whose ordered unique REL source union fits caller capacity.

Owned semantic decisions: canonical strictly increasing stream and position; exact lookahead
length; primary-prefix/support layout; promotion; stable source discovery;
unique union; greedy maximality; first-fit; suffix/end behavior.

Explicitly non-owned decisions: primary selection creation, forest/contact/
balance/REL meaning, direction choice, byte-budget choice, geometry, source-slot
resolution, values, payload transfer, cache, scheduling, periodicity, or 2D.

Inputs and outputs: borrowed strictly increasing `int64[P]` primary IDs, first position,
leaf count, borrowed REL `uint8[C,D]` counts and `int64[C,D,4]` sources, writable
`int64[S]` selected IDs, and exact primary/selected counts.

Mutation and ownership: complete checked preflight precedes output mutation;
success overwrites only the selected prefix and preserves its suffix; nothing
is retained.

Access pattern / halo reach: metadata-only relation-source union for the
caller's direction set; no value reach is inferred.

Independent reference or invariant: one linear range/order scan plus Python
list composition; exact order,
promotion, unique union, first-fit/maximality, sparse omission, dense STO-004
equivalence, and exactly-once selected-primary traversal.

Immediate producer and consumer: an ROI/leaf selector and REL rows produce the
input; RSL and STO-001/003 consume the unchanged selected-slot representation.

Performance class and measurement boundary: composition-only at selected
REL/plan/gather; record primary/support amplification, relation/output bytes,
reader calls, useful/read bytes, and validation versus unchecked planning.

Five-question result: yes/yes/yes/yes/yes.  Enumeration is the capability's
explicit policy; relation and execution remain separate.
