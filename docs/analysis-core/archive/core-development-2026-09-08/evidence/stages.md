# 原型逐阶段比较：优化、复用与新增成本

日期：2026-09-08。本轮只补比较脚本和记录，没有修改生产实现。因此本页与上一轮
绝对时间的差异不能解释为又做了一次优化。

## 对照边界

使用 WENO 的 B1/B2/B3，22,614 个叶块、34,735,104 个原始值。原型指未改动的
`datio.read_blocks_sequential` 与规范 `AMRForest/AMRMesh`。完整流程统一接同一
analysis curl 和两张切片，避免把不同产品或 Dataset 字段追加成本混在一起。
这不是所有历史消费者内核的逐一速度比较。

| 版本 | 文件传输 | 解码、检查与布局复制 | 后续交换与计算 |
| --- | --- | --- | --- |
| A | 原型逐块、逐字段读取 | 原型逐块提取 | 相同规范交换与消费者 |
| B | 当前连续记录批次读取 | 每条记录单独调用当前解码函数 | 同 A |
| C | 当前连续记录批次读取 | 当前跨记录批量解码 | 同 A |

B 只在 benchmark 进程内临时替换解码调用，退出上下文后恢复；没有添加产品参数。
A→B 测的是读取组织改变，包含多读连续字节、减少小读取、不同记录处理等取舍，
不是严格固定字节数的纯磁盘吞吐比较。B→C 的字节数和读取批次相同，可以观察
批量解码/验证/复制的额外贡献。

正式计时与诊断计时分开。正式计时采用 A/B/C、B/C/A、C/A/B 三次轮换，同时记录
墙钟与进程 CPU 时间；诊断运行才包裹文件调用和解码函数。所有版本的完整原始值
都按 uint64 位模式与原型一致，包含正式与诊断运行。

操作系统缓存和其他主机负载未被控制。读取组保留原始参考数组，而完整流程只
保留小型输出参考；两组的驻留与缓存状态不同，不能相加或跨组相减推算收益。

## 1. 初始化、元数据和几何

两次新解释器中，analysis 导入为 285 / 51 毫秒，首次无载荷 source 打开为
115 / 97 毫秒。新解释器不等于清空操作系统代码/文件缓存；没有复现此前的
18 秒初始化异常，也没有据此宣称异常永久消失。

下面是已导入依赖后的三次诊断中位数。`source` 打开整体约 36.5 毫秒，细分如下。

| 阶段 | 墙钟中位数 | 相对原型的性质 | 判断 |
| --- | ---: | --- | --- |
| 打开 fd | 0.058 毫秒 | 普通文件操作 | 保留 |
| checked index：读取、解析、检查与索引规范化 | 19.63 毫秒 | 原型 `get_metadata` 约 4.05 毫秒，但检查和输出约定不同 | 新增职责有成本，没有宣称加速 |
| 文件森林绑定 | 1.25 毫秒 | analysis 的文件顺序/森林适配 | 保留 |
| reader 构建 | 0.058 毫秒 | 新读取边界的适配 | 保留 |
| source 检查与消费者几何构造 | 11.69 毫秒 | 包含平衡检查、MeshIndex 和固定工作区估算 | 保留 |
| 请求、上下文及计时残项 | 3.13 毫秒 | 不是独立数值内核 | 保留易用接口 |

各列中位数不要求相加等于整体中位数。原型读取函数本身还会调用 `get_metadata`；
正式读取 A 保留这一行为，B/C 的 checked reader 预先建立。该边界差异在这里单列，
完整流程对照则包含初始化成本。没有为了消除几毫秒而修改原型或用户入口。

## 2. 正式读取比较

| 版本 | 墙钟中位数 | CPU 中位数 | 墙钟三次原始值 |
| --- | ---: | ---: | --- |
| A | 8.581 秒 | 1.501 秒 | 4.897 / 8.581 / 8.815 秒 |
| B | 0.697 秒 | 0.513 秒 | 0.697 / 0.642 / 0.962 秒 |
| C | 0.593 秒 | 0.388 秒 | 0.499 / 0.593 / 0.809 秒 |

A 有明显读取/主机波动，所以不把本组比值替换成一个新的“固定读取加速倍率”。
可以确认大幅收益在 B 已经出现；B→C 额外减少约 0.104 秒墙钟、0.125 秒 CPU。
完整流程里也能观察到约 0.1 秒级的额外差异，但样本波动不支持精确百分比分摊。

## 3. 读取诊断：时间具体花在哪里

以下来自单独的包裹计时，不作为正式加速倍率。A 的 `read`/`seek` 是 Python
缓冲文件接口调用，B/C 是 `_pread_exact` 批次调用，不能把调用数量之比直接说成
内核系统调用数量之比。

| 诊断项 | A | B | C |
| --- | ---: | ---: | ---: |
| 数据读取接口调用 | 90,456 | 63 | 63 |
| 数据 seek 调用 | 90,456 | 无逐字段 seek | 无逐字段 seek |
| 数据区返回/请求字节 | 278,423,568 | 1,044,585,888 | 1,044,585,888 |
| 所选字段结果字节 | 277,880,832 | 相同 | 相同 |
| 数据读取墙钟 | 5.923 秒 | 0.436 秒 | 0.470 秒 |
| 数据读取 CPU | 0.679 秒 | 0.246 秒 | 0.256 秒 |
| 数据 seek 墙钟 | 0.131 秒 | — | — |
| 解码、验证及复制组数 | 原型嵌在逐块/逐字段循环中 | 22,614 | 63 |
| B/C 解码、验证及复制墙钟 | 不作同口径直接比较 | 0.346 秒 | 0.115 秒 |
| B/C 解码、验证及复制 CPU | 不作同口径直接比较 | 0.291 秒 | 0.067 秒 |

A 另有约 6.55 毫秒 metadata，以及约 1.128 秒解码、循环、分配和计时开销残项。
该残项不是纯解码时间，不能与 C 的 0.115 秒直接相除。A metadata 内还读取
646,432 字节；它的 read/seek 子计时已包含在 metadata 总计时中，不重复加总。

墙钟减 CPU 包含等待、调度和缺页等影响，不等于测得的纯磁盘等待。可以直接
观察到的是：连续批次在多读字节的情况下显著降低了接口读取耗时，而 B/C 的
读取差别很小，额外变化主要在记录解码/验证/复制。

## 4. 从同一个已加载数组开始：准备与交换

三次使用同一个原型读入的原始数组，新建规范森林与 AMRMesh，再加载并交换。
这排除了每次重新读取数据的影响。调用的是与生产适配器相同的构造、复制和
交换方法；64 个分散叶块的全部准备值与生产 `prepare_resident` 参考一致。

| 阶段 | 墙钟中位数 | CPU 中位数 | 处理性质 |
| --- | ---: | ---: | --- |
| AMRForest 与 connectivity | 0.0241 秒 | 0.0208 秒 | 原样复用 |
| AMRMesh 分配与初始化 | 0.1442 秒 | 0.0907 秒 | 原样复用 |
| 内部值复制进 padded 场 | 0.5700 秒 | 0.3079 秒 | 原样复用 |
| ghost 交换，包括首次 coarse 工作区准备 | 2.0874 秒 | 1.0791 秒 | 原样复用，没有新算法加速声明 |

ghost 墙钟三次为 2.087 / 2.697 / 1.062 秒，波动显著。这是带固定原始数组驻留的
独立阶段实验，不能把它加到另一次完整流程上，也不能拿它与上一轮不同状态下
的 0.3–1.3 秒直接判定回归。当前只能说明这里仍有可观成本，且代码确实保持原样；
若之后选择优化它，应针对同状态的候选和原型再做配对实验。

## 5. 从同一份准备场开始：计算与输出

释放原始数组后，三次使用同一个准备场计算完整 curl 和两张切片。此处使用共同的
analysis 消费者，明确不是不同历史 curl API 的性能比赛。

| 阶段 | 墙钟中位数 | CPU 中位数 | 本轮处理 |
| --- | ---: | ---: | --- |
| 完整 curl，含其结果分配 | 0.4488 秒 | 0.3553 秒 | 保留 |
| 128² 轴向切片 | 0.0453 秒 | 0.0142 秒 | 保留友好接口 |
| 96×80 斜向切片 | 0.0130 秒 | 0.0106 秒 | 保留友好接口 |

这组不包含磁盘写出；所选产品是内存中的完整派生场与图像。没有为了基准引入
不属于请求的导出或存储层。

## 6. 完整流程复核

三条路径均返回两张完整图像；全域 curl 实际计算并随后释放。计时包括函数返回前
的中间场释放。各版本的图像与同准备场计算的参考逐值一致。

| 版本 | 墙钟中位数 | CPU 中位数 | 墙钟三次原始值 |
| --- | ---: | ---: | --- |
| A：原型读取与 AMRMesh，共同消费者 | 6.110 秒 | 2.121 秒 | 7.374 / 6.110 / 5.633 秒 |
| B：批量读取，逐记录解码 | 2.277 秒 | 1.735 秒 | 2.277 / 2.127 / 2.324 秒 |
| C：当前批量读取与解码 | 2.169 秒 | 1.617 秒 | 1.900 / 2.169 / 2.546 秒 |

因此“大头在读取组织，批量解码是较小的额外贡献”的判断有完整结果支持。
B/C 单次范围重叠，不能声称每次都恰好省 0.108 秒。原型正式读取组中位数比
完整流程组更高，进一步说明不同驻留/系统状态的计时不能拼接成一个虚构总量。

## 占用、验证与复现

- 原始 B：277,880,832 字节；padded B：937,847,808 字节；coarse：277,880,832 字节。
- connectivity 三数组：10,673,808 字节；消费者几何：4,910,480 字节。
- 准备产品保留量（含 C 辅助结构上界）：1,254,292,688 字节；它已含上述部分存储，
  不重复相加。独立交换与完整流程具有不同活跃数组集合。
- 本轮整个比较进程峰值 RSS：1,623,687,168 字节；不是硬内存限制或大输入验收。
- 正式及诊断读取的所有原始位一致；准备阶段对照 64 个分散块；各次两张图像一致。
  没有将抽样准备比较写成全部 ghost/curl 值的逐值比较。
- 归因各项与其残项按墙钟、CPU 分别检查可回加到对应诊断总时间。没有把嵌套
  metadata 子项重复加总。
