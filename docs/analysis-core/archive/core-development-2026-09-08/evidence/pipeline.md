# 读取—交换—计算：成本估算与批量读取

日期：2026-09-08。按用户最新要求，只针对显著耗时优化，保留易用接口和便宜的
驻留几何/邻接，不引入新的缓存、存储生命周期或微秒级接口优化。

## 范围与对照

本轮针对全域驻留 `open_prepared`，使用实际 WENO 文件的 B1/B2/B3，22,614 个
叶块。比较规范 `read_blocks_sequential`、上一轮 analysis 逐记录读取，以及新的
连续记录批量读取。全部路径使用相同 canonical ghost 交换、同一 native curl，
然后生成 128² 轴向和 96×80 斜向切片。这里的“原型对照”是规范读取与 AMRMesh
准备接同一个科学消费者，不是带字段追加/存储重建的 Dataset 派生字段流程。

基线是本轮开始前的工作区，相关文件保存在
`benchmark-results/analysis-core/pipeline-baseline/`；包含此前未提交的直接准备
改进。只读比较先取得完整原始值参考，再交错三次读取；完整工作流按正反次序
交错三次，每次释放上一次大数组，只保留小型参考。操作系统缓存未受控，不宣称
冷磁盘结果。原始时间、阶段拆分和进程峰值见 `pipeline.json`。

| 森林与 connectivity 构造 | 通常约 19–21 毫秒 | 保持现有实现与驻留所有权，不建额外管理机制 |

## 读取的实际改变

新增内部 `amrvac/analysis_read.py`。全域读取按约 16 MiB 连续文件区间、在记录边界
结束，读取完整记录后提取所选普通字段。规则形状以跨记录的 NumPy stride view
批量转换；混合保存 ghost 的记录在同一已读缓冲区内逐记录解码，不重读文件。

保存 ghost 范围必须非负，普通字段和 staggered 尾部的总字节数必须与记录长度
一致；源文件身份在读取前后检查。通过整数位模式复制及字节序转换保留 float64
的全部位，包括 signed zero、无穷与 NaN payload。输出独立持有；失败不返回结果。
没有修改文件格式、ghost 算术或普通用户函数签名。

稀疏/区域 source 仍使用原来的选择性读取；此次批量读取只用于全域驻留入口。
为了减少小 I/O，本例读取约 1.045 GB 的记录区，包括未选字段和 staggered 尾部，
最终只保留约 278 MB 的所选值。因此这是明确的读取粒度取舍，不是读取量减少。
批次大小是内部实现细节，没有新增用户调参入口。

## 实测结果

环境为 macOS arm64、Python 3.11、NumPy 2.4.4、默认非 OpenMP 构建；本轮没有
增加计算工作者。原始记录保留所有波动，下面使用同轮中位数。

| 读取路径 | 中位数 |
| --- | ---: |
| 规范逐块字段读取 | 4.7949 秒 |
| 16 MiB 连续记录批次 | 0.6892 秒 |
| 64 MiB 连续记录批次比较 | 0.6103 秒 |

16 MiB 路径约快 6.96 倍，已解决主要读取开销。64 MiB 只相差约 79 毫秒，
不据此扩展调参接口或自适应策略；当前保留简单的 16 MiB 默认实现。

| 从文件到全域 curl 与两张切片 | 中位数 | 各次时间 |
| --- | ---: | --- |
| 规范读取 + AMRMesh + 同一消费者 | 6.9749 秒 | 7.2522 / 6.9749 / 6.6735 秒 |
| 上一轮 analysis 驻留入口 | 6.3566 秒 | 6.3023 / 6.3566 / 6.9955 秒 |
| 本轮批量读取驻留入口 | 2.7782 秒 | 2.4102 / 3.3777 / 2.7782 秒 |

完整流程相对原型对照约快 2.51 倍，相对上一轮驻留入口约快 2.29 倍。
没有使用此前 16 秒的分批 curl 来放大本轮收益。

本轮批量流程内：读取约 0.48–0.65 秒、邻接约 18–20 毫秒、网格分配约
0.16–0.23 秒、内部值复制约 0.38–0.48 秒、ghost 约 0.62–1.27 秒、curl 约
0.39–0.89 秒、两切片约 19–58 毫秒。阶段中位数不能直接相加替代完整流程计时。
交换和复制有明显主机/内存访问波动；未改变的内核不能被宣称加速或退化了固定倍率。

每次批量读取本例产生 63 个记录批次，请求 1,044,585,888 字节，最大单缓冲区
16,767,696 字节；完整流程受控数组上界仍约 1.54 GB（准备阶段），整个比较进程
峰值 RSS 为 1,601,044,480 字节。比较进程包含参考与计时辅助数据，这些数字不等于
硬 RSS 限额，也不是超内存输入验证。

## 正确性与启动检查

所有 34,735,104 个原始 B 值与规范读取器按 uint64 位模式完整比较一致。完整流程
还比较了 64 个分散叶块的全部 prepared B/curl 值和两张完整切片，逐值一致；没有
把这个抽样检查写成全域所有 ghost/curl 的逐值对照。交换与 curl 使用同一未改内核。

新增读取检查覆盖大小端、连续/重排字段、统一及混合 saved-ghost 形状、跨批边界、
staggered 尾部、特殊浮点位、负 ghost、截断和源改变。已有区域与源关闭后的独立
结果、全域派生场等组合检查继续通过。

完整 analysis 检查共 35 项通过；最终位模式用例另外确认字段/单元具有不同数据，
避免相同测试值掩盖排列错误。仓库 `make test` 通过。干净源码 wheel 为 9,613,828
字节，构建约 58.14 秒，`python -S` 隔离调用通过；记录在 `pipeline-install.json`，
目录为 `source-build-1wtwbpzb/`。默认非 OpenMP 构建状态保持不变，本轮没有改 Cython
计算内核，因此没有另做后端性能矩阵。

一次新解释器检查中，analysis 导入约 0.100 秒，打开/初始化约 0.147 秒，文件到
准备约 3.450 秒，其中读入约 0.623 秒、复制约 1.050 秒、ghost 约 1.441 秒。
记录位于 `pipeline-fresh-start.json` 与 `pipeline-import-time.log`。没有重现前次
18 秒打开/初始化异常，但未控制系统代码缓存，因此不宣称已经定位或永久消除该异常。
