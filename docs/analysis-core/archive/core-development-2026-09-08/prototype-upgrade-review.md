# 从原型出发的 analysis-core 简化审查

日期：2026-09-08。源码基线：`d922e29`。

本次面向开发协作。用户要求检查过度设计、相对原始 simesh 的不足，以及值得在原型上保留的升级；特别考虑由外层流程先选区域、读取并准备，再执行分析。本次只审查源码与已有证据，没有运行新性能实验，也没有修改运行代码。以下是建议，不代表已删除功能或完成新架构迁移。

后续用户已授权效率优先的实现；实际范围与证据见 [当前进度](current-before-freeze.md) 和
[直接准备改进](evidence/direct-preparation.md)。本页保留修改前的审查判断，
其中工作区释放等存储建议已按新指令后置。

这里的“原型”指当前规范路径 `simesh.amrvac` 与 Cython `AMRForest` / `AMRMesh`，不指 `simesh.legacy` 或某个未经指定的历史提交。相对原型的不足需区分“新路径更慢或更复杂”与“原有入口已发生回归”；现有整合保持了原入口。

## 核心判断

analysis-core 的科学消费者、独立派生场和输出分批具有明确价值。主要设计偏差是让“任意计算中途自动发现缺失场、暂停、加载、淘汰、恢复”影响了过多准备与消费接口。对于用户明确选择局部、准备一次再反复分析的流程，这些机制并非必要。

最初 intent 同时要求驻留竞争力和超内存访问。已有工作对后者投入了大量机制，但真实 10–20 GB / 超内存输入还没有验收。用户现在提出的显式区域流程应成为重新分配设计重点的依据，不能继续从旧实现队列反推需求。局部流程不能被宣称已经替代全部全域科学任务。

建议默认流程为：选择字段和分析区域 → 一次补齐真实 AMR 支撑并准备 → 保留独立场 → 直接执行采样、导数、追踪或 LOS → 按需分批输出。区域不够时由外层明确扩大并重算；全域放不下时提供独立的分区作业流程。科学核心不默认承担透明换入换出。

## 需要收缩的设计

| 问题及判断 | 当前证据 | 建议处置 |
| --- | --- | --- |
| 动态补数进入普通消费者：对区域驻留工作流属于过重机制 | `field_lines._run_chunk`、`los._tile` 同时处理驻留场和池，管理请求、暂停、借用及恢复；追踪还跨缺失保留 RK 阶段 | 普通消费者只接收已准备的固定覆盖。暂保留已有有限容量入口作为独立高级路径；新普通接口不再要求理解池 |
| 全域顺序遍历仍借用缓存池：使用机制超过任务需要 | `global_curl` 按连续叶块批次遍历，却借助 `PreparedPool` 的目录、年龄、淘汰与借用协议 | 外层顺序批处理直接准备一个批次并写入稳定输出；无需缓存替换策略。仍保留支撑闭包、失败标记和输出所有权 |
| 重复规划和检查：是实现成本，不能都算作科学必要工作 | 普通 RHC 消费路径先对整次请求预检查，执行时重建批次邻接、支撑和槽位；逐块逐方向还有 Python 编排 | 新准备边界复用稳定邻接和传递模板，把动态绑定留在批次；私有结果成功才发布。旧入口的预检查与失败约定不直接删除 |
| 多种复用机制同时进入用户选择面 | 完整准备块池、原始值缓存、curl 伴随池、几何计划解决不同问题；原始缓存默认关闭，计划可选，并非每次调用全部启用 | 主流程保留明确的 B / curl 场。原始缓存和计划退到有测量依据的高级准备选项，不建设自动多层缓存 |
| 多视角和并行策略暴露较多执行细节 | 视角次序、tile、池容量、支撑容量、线程池/OpenMP 与静态/动态调度；热射线又有独立调度 | 普通用户主要选择结果、精度、工作者数和输出方式。已知多视角的交错顺序由外层批作业决定；保留实测选项供高级用途，不要求每个科学函数扩展全部组合 |
| 多进程 curl 在加速当前准备器，也放大了准备器的重复建立 | `_curl_job` 每个任务重新 `open_source`，建立自己的元数据/几何/准备器；返回数组另有序列化和汇集 | 保留为现有受限内存工具与对照。先改善单进程准备，再决定是否还需要该专用后端；不把它当驻留全域分析的默认方案 |
| 本机实验配置成为产品约束 | 追踪、标量 LOS、热射线及进程 curl 显式拒绝超过四个工作者；多处默认 2 GiB 并层层扣减估算 | 四工作者应是历史验证范围，不是科学限制。预算放在分配和作业入口，支持估算与显式控制；保留大输出检查，但不把估算宣称为 RSS 上限 |

## 原型更好的地方，以及新路径没有解决好的地方

### 驻留准备的执行方式

原型在森林构造时保留邻接表，在网格构造时初始化索引和坐标；填充时直接访问全域数组，循环在 Cython 中执行。它没有逐请求装入支撑和分配动态槽位的需求。这是应继承的快路径。

[D 证据](evidence/p3-d-global-slices.md)中，规范驻留构建/复制/ghost 准备约 1.228 秒；当时有限容量全域 curl 加两切片约 21.949 / 23.710 秒。两边内存与计时范围不同，文件启动另计，不能作为纯内核倍率；但已足够支持字段放得下时采用驻留准备。当前 `open_prepared` 已调用规范 bulk provider，不能说所有新调用都承担有限容量成本。

### 普通工作流与支持范围

原型已有字段选择、2D singleton-z、多个物理边界模式、可变 Dataset、写回和导出。新 analysis 文件源只接受非周期 Cartesian 3D，默认准备策略只有 continuous 物理边界，尚不能承担通用替代。

这是新路径的覆盖缺口，现有旧入口仍保留。也不能据此声称原型已经正确支持周期鬼点；现有集成证据明确区分周期元数据保留与未交付的周期连接计算。

### 两套几何与准备器装配

当前 `open_prepared` 先通过 `open_source` 建立 rewrite 森林与 `MeshIndex`，随后 `prepare_resident` 再构造规范 `AMRForest` / `AMRMesh`。准备期间存在两套结构，结果还保留消费者几何与规范 owner。

显式依赖的目标不要求保留两个完整构造体系。值得从现有规范森林导出消费者所需的轻量几何，或共享一次验证后的几何；是否能直接共享具体数组需要实现时确认。当前没有测量证明这部分是总耗时第一瓶颈，不能给出虚构节省量。

### “局部分析”入口反而没有优先完善

规范 `read_uniform(bounds=...)` 先 `load_data` 再裁输出，所以设置 bounds 并不等于只读取该区域。规范 `read_blocks` 也没有区域参数。

新路径已有 `MeshIndex.select_box`、`descendants`、按叶读取与 `prepare`，但 `open_prepared` 仍只按字段选择全域。用户还得拼装区域选择、支撑准备和消费。相较于更多缓存/调度参数，一个明确的区域读取与准备入口更贴近实际需求。

## 外层 workaround 的适用范围

| 请求 | 可以采用的简单流程 | 必须保留的科学边界 |
| --- | --- | --- |
| 局部切片、导数、结构检查 | 预选区域或切片涉及的块，一次读取支撑，驻留准备并计算；特别薄的区域先容许整块读取 | 结果区与支撑区分开；导数和插值需真实跨级邻居。仅有切片需求时不强制先算全域 curl |
| 局部磁力线、twist | 预选磁结构包围盒和场，计算中不自动加载；不足时返回覆盖不足，由外层扩大区域重追踪 | 区域退出不等于物理边界足点。固定额外几层单元不能保证未知长路径始终在区域内 |
| 明确要求全域 curl | 所选 B 放得下时一次驻留；放不下时外层按稳定区域分批，写 memmap 或分块结果 | 不遗漏任何目标叶块，各分区独立取得正确支撑。局部 curl 不能冒充全域结果 |
| 全域光学薄 LOS | 场放得下时一次准备后改变观察方向；更大作业可由外层显式分区、累积局部积分 | 裁小体积会改变积分。分区必须无漏计/重计，保持局部重构与支撑；改变累加顺序需说明并验证数值影响 |
| 大轨迹集或大统一网格输出 | 分批种子、分 slab 写出，不自动拼接完整输出 | 输入是否驻留和输出是否分批是两个独立选择 |

“先选局部”不要求把裁出的不完整叶块数组伪装成新的完整 AMR 森林，也不要求先写一个局部 `.dat`。可以保留原始全局拓扑元数据，数值只加载选区和支撑，使用固定叶块到局部数组的映射。该映射对局部寻址仍有价值，但不需要 LRU 或淘汰状态。

选择框也需要明确含义：已有 `select_box` 返回单元中心窗口，不自动等同于任意平面相交或精确几何裁剪。可以先支持按叶块扩大的区域，避免为了最小读量立刻开发复杂的逐单元 I/O。分析有效区仍需明确记录。

当前规范 `AMRMesh` 的全域假设不能靠切片数组直接绕过。快速局部准备需要一个明确的选定目标入口；现有 `prepare(source, ids, ...)` 可以先作正确性和可用性基线，但不能宣称已经拥有与规范全域路径同样快的局部实现。

## 值得从 analysis-core 保留并升级到原型的能力

1. **独立场组和派生结果。**规范 `derived_fields` 会 concatenate 内部场，`_refresh_mesh_after_field_axis_change` 复制旧 padded 数据并重建网格存储。新 `curl(B)` 独立分配结果，不改变 B。这是实质改进，应保留字段含义、单位和剩余 halo，不要求连带保留缓存池。
2. **准备结果独立存活。**保留只读结果和安全 C 所有权，使结果与输入文件、后续分析分离。继续改进最终值与 coarse 工作区的生命周期；当前 owner 会保留整个 `AMRMesh`，这是尚未解决的继承限制。WENO 约 278 MB coarse 是分配量，不是已测 RSS 节省。
3. **直接编译科学消费者。**保留任意点采样、RK4 追踪、接受段 twist、切片和射线内核及独立参考。普通驻留路径无需自动缺失恢复；可以先简化外层而不重写全部数值循环。
4. **结果按需保留与流式输出。**诊断优先、轨迹可选、按种子 ID 重追踪、`iter_traces` 和 `iter_uniform` 都解决实际大输出问题，与输入分页无关。完整 `trace` 目前先收集批次再 concatenate，存在峰值双份输出，可在需要时改为预分配后写入。
5. **明确热力学和数值解释。**密度/长度单位、外部温度或等温输入、响应模型、两种非线性重构顺序不能为了接口简短而隐去。它们决定科学量；具体仪器模型可保留在上层科学模块，AMR 准备层无需理解 AIA。
6. **实用选择性读取。**保留已有普通字段/记录偏移读取能力，服务一次选区读取。不要把按块读取与多层动态缓存绑定；也不回退到无检查的字节解释。格式检查放在明确装载边界，源关闭后只读结果不必反复检查文件。
7. **单层独立任务并行。**保留种子和像素分区、只读共享场与私有输出的设计。无需让普通用户同时选择准备进程、消费者线程池和 OpenMP 调度组合。已有高级后端先保留以免丢失能力，默认选择继续以同范围实测为据。

## 如何处置已有优化证据

- 原始值缓存：重复 LOS 的文件传输量约 695 → 117 MB，总时间却约 14.3 → 13.9 秒。保留为特定 I/O 请求的选项，不能以字节命中率证明默认架构合理。
- 完整场保留：同一 F 比较中约 42.6 MB 的 600-slot 池容纳实际 590 个 owner 后，重复计算约 0.0202 秒；相近内存的 256 准备槽加 1,024 原始槽约 0.735 秒。它支持避免重复准备；不证明无先验的所有路径都能局部驻留。
- 几何计划：选定重复准备组合确有 2.56 / 6.67 倍改善，但稠密选区计划自身约 52 MB。对同一组已准备值反复消费时无需再执行计划；不应自动全域建立计划来加速根本不再发生的准备。
- 进程 curl、多视角交错：保留实测范围。它们改进了当前有限容量流程，不证明该流程在可驻留任务中优于原型。
- 实际命中追踪、额外 padded staging 已回退；E1 重分块未进入生产。它们属于已结束的探索，不应误报成目前每次运行都付出的成本。

## 建议的实施顺序与取舍

1. **先做简单主流程。**以规范驻留准备接已有 `PreparedFields` 和科学消费者；明确全域/区域覆盖，提供一次局部读取准备的方便入口。先允许按叶块扩大，测量一次准备与后续多个请求。
2. **消除直接可见的原型缺陷。**独立派生场、避免字段追加重建主存储、准备工作区可独立释放、共享已有几何；检查峰值与长期保留量，避免为释放工作区复制整个场。
3. **收缩外层执行机制。**顺序分区和流式输出作为显式作业功能；普通消费者不承担透明加载。冻结新的缓存/后端扩展，已有有限容量入口先保留，待替代流程覆盖后再决定兼容性迁移或删除。
4. **最后处理真实无法驻留的任务。**用实际所需字段、区域、精度、完整输出评估，而非只看整个文件大小。需要全域时不能默认降分辨率或裁域；更大内存机器、显式预处理和分区是用户可选流程，真实超内存性能继续保持未验收状态。

后续验证应围绕三个具体结果：一次局部 B 准备后多次追踪/twist；一次全域或区域 curl 后多切片；一次热力学场准备后多视角。比较规范原型、现有 analysis 驻留、选区驻留及仅在必要时的有限容量路径，分别记录文件到首结果、后续结果、真实读取量、准备次数、活跃数组和 RSS。先复用已有科学参考，仅为实际改变的边界增加检查。

本轮没有证明一个新的局部准备器的速度，也没有删除代码。建议重点已从继续完善动态运行时，转为以原型快路径为基础完善区域入口、独立场和直接科学计算。
