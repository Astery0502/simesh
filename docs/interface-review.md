# 当前应用接口与资源开销审查

日期：2026-09-09。范围：当前根目录版本的应用调用链及结果输出。
已完成两轮优化：路径缓冲、分片索引、MHD 可选诊断按需计算，以及调用链和保存复制。
优化前数据见[原始检查数据](interface-review-data.json)，当前复测见
[第一轮数据](resource-optimization-data.json)、[第二轮数据](resource-optimization-round2-data.json)，可用


## 结论

**基础分层没有明显过度设计，但公开使用面偏宽，少数输出路径确实存在可避免的开销。**
不能把所有复制都归因于接口封装，也不能把所有成本都解释成必需的安全检查。

`Source → Fields → 计算函数` 能明确文件生命周期、空间覆盖和支撑是否可用；
单位和物理模型也确实影响结果，保留这些边界合理。
`PointSet`/`RaySet`/结果类用于关联编号、几何和有效性，适合需要筛选、保存和恢复的应用。
如果只做一次数组计算，可以直接用原生接口。

目前顶层导出有 90 个名称，包含函数和数据类型，不是 90 种物理算法。
同类任务存在原始数组接口、应用接口、批次接口和有限容量接口；主要问题是学习成本及
参数命名不一致。应用手册已将常用路径和高级选项分开，不要求日常调用全部接口。

## 1. 已修正：应用路径工作区按最大步数分配

[tracing.py](../src/simesh/tracing.py) 和 [applications.py](../src/simesh/applications.py)
现在使用每条路径 64 个接受步的固定缓冲段。段满时保留 RK 状态并暂停输出，下一段继续积分；
步数、长度上限及物理终止条件不变。每段只复制实际接受的点，最后直接打包到 `LineSet`，
不再建立完整的中间分支数组。种子编号、方向、首点和终止状态保持原语义。

同一均匀磁场、64 个种子、固定步长的前后对照：

| 最大步数 | 实际保存点数 | 最终坐标字节 | 优化前分配峰值 | 优化后分配峰值 |
| --- | ---: | ---: | ---: | ---: |
| 100 | 3200 | 76800 | 265177 | 234580 |
| 5000 | 3200 | 76800 | 7790441 | 233188 |

两个步数上限的坐标逐位一致。另以 `max_steps=1000` 和 `10**8` 检查短轨迹，
固定预算下均正常返回；实际长路径超预算则报错，不截断、不改变终止状态。
跨多段的曲线路径已与原生稠密结果逐点对照，覆盖步数/长度上限、域外种子、
域退出、缺少覆盖、零场和多工作者调度。

`app.trace` 仍需容纳完整 `LineSet`；`app.iter_lines` 只汇总当前种子分片。
原生 `sm.trace(..., trajectories=True)`、`sm.iter_traces` 及有限容量原生追踪的稠密
返回约定未改，其路径输出容量仍随 `max_steps` 增长。
固定段长是内部实现细节，不增加应用参数。本轮没有作吞吐量提升承诺。

## 2. 已修正：分片清单重复写入全量种子

[result_shards.py](../src/simesh/result_shards.py) 新写入采用版本 2：

- 每片 NPZ 发布后，再原子发布该片的 `index-*.json`，包含范围、文件名、类型和校验和。
- 开始时写未完成清单；结束时写完整汇总清单，不在每片结束时重写已有列表。
- 中断目录通过连续索引识别已提交分片；残留、未提交的 NPZ 不计为已交付。
- 版本 1 仍可读取；`ResultShards.seed_ids` 为两个版本提供统一编号访问。

固定 10000 个种子、40 个空路径分片的对照：

| --- | ---: | ---: |
| JSON 累计写入字节 | 2612727 | 12885 |

## 3. 已修正：MHD 可选诊断按需计算

[mhd.py](../src/simesh/physics/mhd.py) 仍检查完整物理状态，包括输入有限性、
密度/内能正值、单位换算、压力和温度可表示性。`invalid="raise"` 和 `"nan"` 的
物理判定及定位不变。完成检查后提前释放转换临时数组，再计算可选诊断：

- 只请求速度、密度或温度时，不计算可选诊断。
- beta、声速、Alfvén 速度按需计算；马赫数会带上对应速度依赖。
- 请求 `status` 时执行完整诊断，默认输出仍走完整路径。
- `preparation_stats["evaluated_diagnostics"]` 明示检查范围。诊断溢出计数只描述
  该范围；完全未检查可选诊断时为 `None`，避免把“未检查”当成“通过”。
- 诊断依赖先使用原始数值计算，再把非有限输出变为 NaN，保留极端值的公式顺序。

| 请求 | 输出字节 | 优化前分配峰值 | 优化后分配峰值 |
| --- | ---: | ---: | ---: |
| 仅速度 | 1536000 | 3498688 | 3309696 |
| 默认输出 | 6144000 | 8040152 | 7854864 |

完整物理检查仍占主要开销，不能期待选择速度就只执行动量除以密度。
本机仅速度调用中位数从第一轮复测的 3.77 ms 变为 3.27 ms，默认输出约 4.69 ms；
这是小例复测，不是普遍吞吐保证。针对两种能量定义、普通和极端量级的 12 组对照，
完整输出与修改前实现逐位相同；分别请求每个输出也与完整恢复结果一致。
另外检查了无效节点仍报错/标记 NaN、beta 溢出与部分诊断范围、依赖速度溢出的计算顺序。

## 4. 已减少调用链复制；保留字段独立所有权

[field_ops.py](../src/simesh/field_ops.py) 的 `select_fields` 和 `merge_fields`
继续分配独立连续数组，支持任意叶块顺序对齐、紧凑字段组及独立值身份。
即使选全部字段或只改名，也不是视图。

在 8 叶块、每块 `16³`、两层 halo 的例子中，八分量输入为 4096000 字节；
选择一个分量会分配 512000 字节，合并四个分量会分配 2048000 字节。
这类复制应按消费目的避免，而不是改变所有权约定。

[恢复状态示例](../examples/recovered_state_analysis.py) 已改为：
直接在八分量场上指定磁场列计算电流；使用 `derive_many` 从状态和电流两组中
直接生成温度换算、密度换算与 jz 三列，省去三分量磁场副本、两列换算中间组和
五列合并组。对应的三列值逐位一致，代表性分配峰值从 **5559809** 降为 **2387919 字节**。
最终三列字段为 **1119744 字节**，原五列字段为 **1866240 字节**。

只做采样、切片或剖面选列时，直接传 `components`；同时需要 MHD 状态和磁场时，
可在同一 Source 中按用途准备两组。没有新增公共执行框架或借用字段接口。

## 5. 已减少保存复制；保留别名保护和原子发布

[results_io.py](../src/simesh/results_io.py) 保留 NPZ 版本 1、结构校验和临时文件原子发布：

- 构造器自有、连续且只读的 `PointSet`/`RaySet`/`Plane` 几何直接用于保存。
- 可写输出，以及可能仍有外部可写别名的数组，继续建立独立快照。
  `LineSet` 数组即使只读也不据此免除快照。
- 保存前校验编码结构时，不再通过公共构造器额外复制一遍几何。
- 用 256 KiB 的内存视图向 ZIP 写入 NPY 数据，避免整个数组转成临时 bytes。

| 50000 点结果保存 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 原结果数值字节 | 2450000 | 2450000 |
| 编码快照字节 | 2450000 | 850000 |
| 新增跟踪分配峰值 | 6460223 | 1749841 |
| 压缩文件字节 | 1241391 | 1241391 |

已检查大几何、可写输出、只读视图和可写别名、非连续/大端输入、NaN 位模式及负零、
保存失败/发布冲突清理、非法几何拒绝，以及全部已有结果的恢复。
保存期间不能替换借用几何或修改其写保护；快照捕获时也不支持并发修改输入。
压缩分块不代表完整保存具有固定内存保证：快照、结构检查和压缩仍需要空间。
接口仍没有 `memory_limit`，大结果继续使用合适的分片。

## 6. 不是主要开销的封装，以及需要整理的使用规则

- **采样应用封装没有复制底层结果。** `app.sample` 保留原生采样返回的三个数组，
  实测确认共享同一存储。已有 PointSet 的 50000 点采样，本机中位数分别约为
  原生 1.426 ms、应用 1.541 ms；这组时间仅说明该小例的差异，不能证明稳定的固定比例开销。
- **几何对象需要空间。** 50000 点的坐标和 ID 合计 1600000 字节，PointSet 会复制输入坐标。
  这是保存独立几何的成本；应建立一次后复用。只要一次原始采样时可直接传数组。
- **电流没有额外的完整 curl 缓冲。** `current_density` 将 SI 缩放合入差分系数，
  这一实现应保留。无需为了“合并物理公式”另建通用执行框架。
- **重复小检查存在，但不是扫描完整场值。** 多层采样入口重复校验 halo 和选择器，
  主要处理描述对象和少量列名。应先处理上述大数组和 I/O 问题。
- **命名不一致增加误用。** `sample` 的 `components` 可用名称，`curl` 的分量选择目前只收整数，
  `app.los` 的 `component` 也只收整数；`app.trace` 用方向字符串，原生追踪用 ±1。
  这些差异已在接口参考中列明，后续可在保留数值语义的前提下统一。
- **保存类型并不通用。** `app` 结果多数可保存，原生追踪/切片/LOS 结果不直接注册，
  归约结果还需显式 JSON/NumPy。应先完善文档和少量必要适配，而不是让所有结果继承大基类。
- **高级执行选项不应成为入门负担。** 缓存、几何计划、有限容量池、线程调度属于特定需求；
  普通调用不应强制引入会话、任务图或全局缓存。

## 改进顺序与测量边界

四项已确认的资源问题已按两轮处理。选择器命名一致性不属于本轮资源修正。
基础 Source/Fields 边界、明确单位模型与逐项有效性信息继续保留。
MHD 的物理非法状态判定、字段独立所有权及可写别名的保存快照继续保留；
诊断统计范围与保存期间的几何借用规则已明确更新。

测量使用 Python 3.11.14、NumPy 2.4.6、当前 `0.2.0.dev0` 工作区，单工作者；
输入是 8 叶块、每块 `16³` 的解析均匀状态。准备过程不计入调用测量。
时间与分配分别测量，分配使用 `tracemalloc`，不是 RSS、硬件内存流量或所有原生分配的上界。
代码路径/数组大小结论来自源码和直接检查；时间只描述这台机器上的小例。

前期文档验证用合成三维快照执行了应用手册的 13 个 Python 代码块，并补充了
16 个种子的非空诊断、筛选、追踪、1040 行物理剖面及保存/恢复流程。
第二轮还运行了恢复状态示例，质量、温度、磁通断言通过，6 条流线、240 个有效剖面点及保存恢复完成。
源码包包含当前中文文档和检查数据，不包含历史文档目录。
