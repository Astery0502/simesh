# 根子树裁剪实现与效率测量

本报告面向开发协作。实现基于 `da53e25` 的原生 Source/Fields 架构，测试数据完全合成。

## 已固定的边界

- 内存中的区域 Fields 保留原 Mesh；只有导出的文件重建域范围与索引。
- 保留完整根子树、叶块层级与普通场内部位模式，不进行插值或重网格。
- 不保存原域外侧 halo。新文件边缘成为其域边缘，不保证边缘导数与原域一致。
- 支持现有非周期 Cartesian 3D v5 普通场输入；可跳过保存的 ghost 和已验证的 CT 尾部。
- 文件不保存单位标签与派生来源，不认证求解器重启。输出与输入必须是不同文件。

## 实际改动与成本

设原叶块/节点数为 N/T，选中叶块/节点/根块数为 n/t/r，每块单元数 C，选中场数 k，每批 B 块，D=8nCk。

| 阶段 | 实际工作 | 受控存储与限制 |
| --- | --- | --- |
| 打开 | 复用完整索引、森林绑定、几何与平衡验证 | 原 Mesh/index 常驻，随 N/T 增长，不能宣称整体内存仅依赖选区 |
| 选根 | 局部 Morton 遍历、对每个根定位节点和叶块连续跨度 | O(r) 跨度/映射；searchsorted 工作约 O(r log N)；全域直接取一个完整跨度 |
| 导出计划 | 拼接标志与原叶编号，平移整数坐标 | O(t+n) 数组；不建第二份分析 Mesh；不扫描原场值 |
| 公开选择 | 包装已有 Selection 并保留物理请求范围 | Selection 的通用去重校验可能排序，不能将其总成本简单写为线性 |
| 读取 | Source.read_into，批内原文件读取器检查、排序并合并连续场 | 场缓冲 O(BCk)，读入 D 量级载荷；保存 ghost 时可能有读取放大 |
| 已有 Fields 整理 | 按原叶编号查槽，逐块复制到批缓冲 | 已有 Fields 常驻；额外缓冲 O(BCk)，没有另一个完整 D 大小数组 |
| 写出 | 共享分批序列化；每块转磁盘排列 | 除计划外仅批缓冲和一个块的编码字节；树序列化临时数组在载荷前释放 |
| 发布 | 临时文件完成后原子 link/replace | 无整文件发布复制；失败保留原目标 |

文件一步路径不逐批调用 read_fields，因此不反复创建长度 N 的 Fields 目录。导出时只检查已有覆盖，不准备 halo 或隐式补读。Source 路径保留现有 read_footprint 的保守 scratch 预算；当前 AMRVAC Source 的下限约为 32 MiB，这不表示实际分配了该数量的额外数组。

默认批载荷上限 8 MiB，并限制每批最多 256 个叶块；至少容纳一个完整块。memory_limit 若不足默认批大小会缩批，不足一个块及固定成本则拒绝。预算按全局 Mesh/index、保守导出计划、批缓冲、读取 scratch 和单块序列化 bytes 合计，不是进程 RSS 上限。

## 测量方法

运行：

```bash
.venv/bin/python legacy/core-development/root-crop/measure.py --directory .benchmark-data/root-crop-measurement
```

输出目录必须新建。脚本生成一个 8×6×4 根网格、864 个叶块、每块 16³ 单元、8 个字段的 v5 输入，普通场载荷 216 MiB。输入在测量前生成；每个组合使用 3 个新 Python 子进程测量，列出各指标中位数。环境为 macOS 26.5.2 arm64、Python 3.11、NumPy 2.4.6；详细版本和原始样本见 [measurements.json](measurements.json)。

各阶段包装真实实现：打开、计划、Source 读取、Fields 布局整理、单块序列化和 stream.write；剩余包括索引编码、关闭缓冲、发布和其他 Python 工作。分阶段中位数不是同一次样本，不能要求逐列精确相加等于总时间。读取字节在普通场读取器的 pread 边界计数，写出字节在流边界计数。

Fields 路径的总计不含预加载，预加载单独记在 JSON；其 RSS 包含持有的场。全部样本在本机临时目录执行，没有清理系统页缓存，没有 fsync，测得的写出时间不是持久化介质吞吐。阶段包装有额外开销，结果不能外推到大型生产快照、网络存储或冷缓存。

## 从证据得到的结论

- 单叶单场样本约 32 KiB，打开索引约 9–10 ms，决定了约 11 ms 的总时间；此时优化子树拼接没有明显收益。
- 需要重排的 432 叶块、3 场选区载荷为 40.5 MiB。默认批下，读取与写出占主要时间，计划约 0.6 ms。实际载荷读取为 1,296 次、40.5 MiB，未读取未选普通字段或区域外块的载荷。
- 全域 8 场输出载荷 216 MiB，默认批缓冲 8 MiB，文件路径约 57 MiB 的进程峰值 RSS；受控数组预算约 40.7 MiB。两者差别包含 Python/NumPy 运行时和未纳入数组预算的分配，不等于预算失效。
- 需要重排的选区每批 1 块时约 86 ms；16/64 块约 55/53 ms；256 块约 62 ms，缓冲增长到 24 MiB。结果支持避免逐块读取调用与不受控的大缓冲，不足以证明某个批大小普遍最优；保留内部默认值，不增加公开调参接口或并行执行。
- 已有 Fields 整理是有实际占比的内存搬运。去掉逐叶重复窗口校验、保留每批借用有效性检查后，该选区整理中位数从约 17.5 ms 降至 9.2 ms；全域整理从约 79.8 ms 降至 59.3 ms。两轮写出波动明显，总时长不能用来单独归因这项变更。
- 本样本的根规划不是瓶颈，不修改 Cython、Morton 算法或数值内核。以后若生产样本显示全局索引或磁盘访问占主导，应独立测量对应层，再决定是否增加更复杂的索引/读取能力。

## 验证与简化

最终 `make test` 为 422 项通过、2 项跳过；跳过项需要可选 OpenMP 构建。本次没有修改编译源，隔离环境通过 editable 安装构建扩展。`make docs` 的 139 个接口检查与严格站点构建通过。新 `examples/root_crop.py` 验证 108→40 叶块裁剪与密度体积积分 1248；原 `examples/user_quickstart.py` 的磁场、质量和结果往返示例也通过。

验证覆盖单根、全域、非零起点、非二次幂区域、三级完整子树、Morton 重排、原域几何与层级、普通场位模式、场选择、派生列、非标准槽序、区域覆盖、源关闭/变化、失效借用、保存 ghost/CT、大小端、内存缩批与中途写失败保护。代表性分析比较原区域与输出的体积积分；不声称新边缘导数一致。

已执行本地 simplify skill 的三个并行审查。复用审查未要求额外抽象；质量审查指出尾部 NUL 场名不能往返，现已拒绝 NUL 并澄清字段选择顺序；效率审查删除了高级索引后多余的两个 copy，并提前释放树序列化临时数组。这些变化保留原 Mesh 和字段所有权边界。JSON 中样本在上述小型索引/名称简化前采集，场传输路径相同；不把省下的索引分配折算成未经测量的速度收益。
