# 应用接口与成熟度检查

日期：2026-09-09。检查基线：`2e101e0`。面向开发协作。

后续已增加[应用接口](../applications.md)，补充几何编号、结果关联和
筛选后独立追踪。本文保留检查当时的结论与数据；QSL/twist 仍不保存路径。

## 结论

四项能力均已有实际实现，可以组成应用。前三段数据处理之间的边界比较清楚：
一次准备后，均匀采样、微分、派生量和磁分析复用同一组独立 `Fields`。
最需要补齐的是“底面图选点 → 磁力线形态”的应用接口，而不是重新实现这些算法。
目前这条链需要使用者处理磁极性、种子编号、平面形状、轨迹长度和不同端点语义；
还不宜描述成无需了解细节的一键流程。

本轮只检查实现并新增可复现的检查脚本、结果和报告，没有修改运行接口。

## 四项产品的现状

| 产品 | 当前合适入口 | 实现与接口判断 | 成熟度判断 |
| --- | --- | --- | --- |
| 鬼点交换后生成均匀场 | `open_amrvac → prepare → iter_uniform`；单截面用 `sample_plane` | 准备与消费分离合理；按切片输出避免全体积峰值。用户需明确准备方案、坐标和输出布局 | 可直接作为主要能力；大输入与特殊边界需按支持范围宣传 |
| 微分及派生场组合 | `derivative`、`curl`、`derive` | 按名称/方向定义微分、独立拥有结果、显式有效支撑，适合组合。配方接口较新，但不需要另外建设通用执行框架 | 一阶微分与逐点组合可直接应用；长微分链和并行配方有明确限制 |
| 切面/底面的 QSL 与 twist | `qsl`、`iter_qsl` | 算法路径、失败状态和输出分批已有；平面到种子、图像形状及编号仍由应用维护 | 已有研究验证的可用功能；尚缺真实强 QSL/复杂长线的大规模验证 |
| 任意种子的磁力线积分 | `trace`、`iter_traces`、`retrace` | 原生追踪、线程与结果所有权可用；方向为整个调用共用，轨迹采用定长填充，边界结果为接受前缀 | 底层能力可用；接入底面交互选线前需要薄层接口 |

“均匀场”是已有重构的插值结果，不是保守重映射，也不意味着原 AMR 分辨率
被无损提升。原生准备仅采用当前连续物理边界方案；兼容 Dataset 的其他边界模式
不能自动视为原生分析也支持。

## 实际走通的组合流程

检查脚本生成含粗细交界的解析线性无力磁拱场，写成临时 AMRVAC 文件，再通过
原生入口读取，完成以下流程：

1. 全域准备并关闭文件；其后所有消费者继续使用独立场。
2. 输出 96³ 均匀场，共 884,736 个有效采样点。
3. 计算 curl、磁场模平方、其 x 方向导数及截面。
4. 在含正负磁极性的 32×24 底面上计算 QSL/twist。
5. 用 `Q ≥ 4` 或 `|Tw| ≥ 0.09` 筛选种子，再追踪其磁力线。

这些阈值仅用于该解析例子：闭合磁拱的背景 Q 为 10/3，不能把近似常量图上的
细小数值差异按分位数选成“高 Q”。真实数据的阈值由应用目标决定。

结果：

- 768 个底面种子全部完成，Q 映射全部有效。
- 752 条线的两端位于底面；其 Q 相对解析值的最大误差约 0.00142%。
- twist 与 `alpha * length / (4*pi)` 的最大绝对差异约为 6.05×10⁻⁵。
- 高 Q 条件选中 16 点，高 twist 条件选中 92 点，合并去重后为 96 点。
- 96 点中正负 `Bz` 各 48 点。直接使用默认 `trace(direction=1)` 时，
  48 条负极性线零步退出。按极性朝域内追踪后，96 条均得到非空轨迹并到达域边界。

## 组合接口中需要明确处理的问题

### 1. 底面选点必须处理方向

`qsl` 双向积分，`trace` 的 `direction` 则是一次调用共用的单个正负号。
在下边界，正 `Bz` 通常选 `direction=1`，负 `Bz` 选 `direction=-1`。
不能把两种极性的种子混在一起只用默认方向。
任意内部截面通常需要追踪两支，而不是直接套用底面向内规则。

建议补一个应用级“选择并追踪”入口，支持向内或双向追踪，保持原种子编号，
并汇总轨迹与终止状态。当前用两个 `trace` 调用分组也能完成，不需要重写积分算法。

### 2. QSL 结果不能直接交给 retrace

`QSLResult` 有 `seeds`，没有 `seed_ids`。`retrace` 针对 `TraceResult`；
实际传入 QSL 结果会得到缺少 `seed_ids` 的 `AttributeError`。
这不妨碍通过 `trace(fields, qsl_result.seeds[mask], seed_ids=...)` 继续工作，
但应用必须维护编号。分批 QSL 输出还需要维护累计偏移。

建议提供共同的种子标识或轻量选择对象，并让不适用的输入类型得到明确错误。

### 3. 平面到种子以及结果到图片仍需手工关联

`Plane` 可以用于采样，但没有公开的点坐标生成方法；`qsl` 接收 `(n,3)` 数组。
当前需要自己生成平面上的点、记住形状、展平、计算后再 reshape。
切片、QSL、选线容易因为像素中心、展平次序和图片转置采用不同约定。

最小补充是共享的平面种子生成入口，并让图产品保留平面几何、形状和种子编号。
不需要为此建立新的分析会话框架。

### 4. 两种积分的端点与步长语义不相同

QSL 对闭盒面定位脚点，使用局部网格限制的 RK4 步长。
普通 `trace` 使用指定的物理步长，越界试步被拒绝后保留最后接受点。
这次所选轨迹的端点与 QSL 脚点距离最多约 0.00351，低于所用步长 0.00390625。
因此可用于展示形态，但不应把它们当成同精度、逐点一致的脚点结果。

此外，QSL 接受上边界点；普通 `trace` 的半开域定位把同一点判为 `OUTSIDE_SEED`。
QSL 的自定义 `bounds` 或 `local_radius` 也不会自动传递给普通 `trace`。

若产品需要完全相同的两端定位、局部积分范围和轨迹，应让连接性积分路径支持
只对所选种子输出轨迹。这是有具体用途的小范围实现扩展，不能只靠改参数名达到。
不建议静默改变既有 `trace` 的语义。

### 5. 绘图要使用有效轨迹长度

轨迹存储形状为 `(n, max_steps+1, 3)`，未使用部分以 NaN 填充。
要按 `point_counts` 提取实际点数。筛选后的 96 条线、`max_steps=4000`，
结果轨迹数组约 9.22 MB，而真正接受的点约 1.19 MB；峰值还包括内部工作批次。
多种子配大上限会明显放大内存。

目前可用 `iter_traces` 分批消费。可变长路径或结果写出接口值得后续改善；
事后切成 NumPy 视图并不会释放其所引用的整块填充数组。

## 健壮性检查

这次实际检查确认：

- 文件关闭后，准备场仍可采样、求导与积分。
- 字段支撑层沿 `准备 → 逐点组合 → 一次微分 → 再次微分` 为 `2 → 2 → 1 → 0`。
  零有效支撑层的场不能直接继续插值，接口会拒绝；不能宣传成无限制的自动微分链。
- 过期的借用批次会报错。
- 区域外缺失场给出 `MISSING_COVERAGE`，没有被伪装成物理边界。
- 极小内存预算会明确拒绝。
- 本次检查的准备、均匀场、curl、QSL 和轨迹在 1/2/4 个工作者下输出一致。

应用中的高 Q 筛选应使用 `valid`；完整 twist 筛选应使用 `complete` 与有限值检查。
不能统一把“有数值”视为“完整有效”。

目前 QSL 的证据仍主要是解析场、小型混合 AMR 和上游小规模对照。
本例最大 Q 约 7.63，不是极端强 QSL、零点附近和复杂长闭合线的压力验证。
真实推广前应选一个代表性磁场快照，检查步长、扰动间距和输入分辨率的收敛，
以及截断/缺失/退化映射的比例。本仓库的 `reference/bw.dat` 是球坐标、无 B 分量，
不适合作为这项原生笛卡尔磁分析的真实数据验收样本。

## 并行能力与本机实测

环境为 macOS arm64 普通构建，没有启用 OpenMP。本例只有 9 个 AMR 叶块，
每块 16³ 单元，文件约 0.885 MB。每个项目预热一次后测量三次，以下为中位数，
包含 Python 编排。准备测量使用热文件缓存；QSL 测量复用了已计算的 curl。

| 操作 | 1 个工作者 | 2 个工作者 | 4 个工作者 | 4 个相对 1 个 |
| --- | ---: | ---: | ---: | ---: |
| 全域鬼点准备 | 1.20 ms | 1.29 ms | 1.25 ms | 此规模无收益 |
| 96³ 均匀场输出 | 43.30 ms | 38.44 ms | 34.84 ms | 1.24× |
| curl | 0.503 ms | 0.473 ms | 0.473 ms | 差别很小 |
| 768 点底面 QSL/twist | 548.09 ms | 380.05 ms | 265.10 ms | 2.07× |
| 96 个选中种子向内追踪 | 13.95 ms | 8.75 ms | 5.57 ms | 2.50× |

`derive` 的逐点公式目前串行，本例约 0.237 ms。区域 `exact-phase` 准备也仅支持
单工作者，传入 4 会明确报错；全域 `coordinate-phase` 才有当前并行准备路径。

QSL 的积分热点释放 GIL；扰动生成与 Q 结果组装仍有逐种子的 Python/NumPy 操作。
当前工作者按连续种子区间静态分配，复杂拓扑中线长不均可能影响负载均衡。
普通追踪有更丰富的调度/后端选项，QSL 当前没有同等选项。
这些是能力边界，不应把一个 `workers` 参数宣传成所有阶段都会线性加速。

这组结果只说明该工作量下的表现，没有大输入验收、持续高并发或通用吞吐承诺。

## 建议的推进顺序

1. 先补共同的平面种子/编号、阈值筛选、向内或双向追踪的薄层接口，交付完整示例。
2. 明确是否要求显示轨迹与 QSL 的定位端点一致；需要时复用连接性积分输出所选轨迹。
3. 用一份真实磁场做完整流程与数值收敛验证，再针对出现的内存或负载不均问题改进。

适合当前宣传的表述是：原生 AMR 准备与均匀采样、可组合的派生场和微分、
具有明确数值方法和有效性状态的磁连接性诊断、可分批的磁力线追踪。
“从底面诊断图直接选出磁力线形态”适合作为下一个应用示例目标，不能声称已经
有一个自动处理上述全部细节的公共入口。
