# 读取、字段选择与结果交付优化

日期：2026-09-09。面向开发协作；对照基线 `0bcbe2e`。
修改范围为独立 `analysis-core/`。父包原有未提交改动保持原样。

已完成最终存储直读、按字段限制 Source/缓存、有效支持入口检查、只计算所选分量的
采样、调用者输出，以及按种子分片的轨迹/剖面保存加载。没有更换插值、差分、RK4、
QSL、LOS 数值方法、float64 精度、覆盖定义或来源认证规则。
公开用法和逐入口最小 halo 要求见[调用说明](../selected-delivery.md)。

## 支持与来源

- 原生积分、均值、极值、直方图、面通量、逐点公式、MHD 恢复可以直接消费内部字段。
  热力学单位/温度转换和发射率也是逐点操作，改为继承共同有效支持，不再强制两层。
- 普通采样、追踪和标量/热 LOS 至少需要一层。差分消耗一层；变分 QSL 需要两层；
  自动 curl 的 twist 需要两层，保留 curl 则检查它自己的一层和原有来源证书。
- `storage_halo` 不证明有效性。派生、组合后的 `valid_halo` 继续由下游检查；
  错误包含当前层数、所需层数及显式准备原输入、重新派生的处理方式。
- 分类状态字段在有 halo 时也不能被当作连续量插值。检查只作用于实际选用的分量。
- 字段映射保留原始分量编号；等价的直接准备、嵌套映射和缓存准备仍有相同逻辑数值身份。
  显式 `select_fields` 继续独立复制、产生新值身份。

## 数组存活范围

| 路径 | 改动前 | 改动后 |
| --- | --- | --- |
| 内部读取 | 全域分量优先 R，与最终分量相邻 R 在转换时并存 | 最终 R 加块/记录读取缓冲，无第二份全域内部数组 |
| coordinate 准备 | 读取阶段 R；复制阶段 R+F；释放 R 后 F+C | 先分配 F，读取直接填内部；读取缓冲释放后才分配 C |
| exact 准备 | F 加有界支持工作区；整个目标块打包到 F | 原值先入 F，再绑定必要的有界支持工作区；只回写完成的 halo；仍保留必要工作区 |
| 几何计划准备 | F、带 halo 支持工作区和独立 raw 支持缓冲并存 | 删除独立 raw 支持缓冲；几何计划仍只保存几何 |
| 原始缓存 | 容量 × Source 全部分量 | 容量 × 所选 Source 分量；字段映射不复制数值 |
| 点/沿线采样 | 全分量批次，再选列/复制到最终结果 | 共享定位与权重，只求所选列；直接写最终结果区域 |
| 切片/体积 | 采样批次 → 切片 → 完整体积；选字段可能另复制全域场 | 直接写切片或体积目标；接受原场与分量索引，无全域子集副本 |
| 全域 curl | 每批导数数组再复制到全域目标 | 导数内核直接写对应目标区；独立文件任务也使用该路径 |
| 变长轨迹/剖面 | 所有种子的路径片段和完整打包结果并存 | 每个种子分片独立打包、采样、保存与加载；不强制拼接 |

R 是选择字段的内部数组，F 是最终带 halo 数组，C 是 coarse 工作区。Source 本身持有的
数组输入仍计入存活范围；仅加字段映射不能释放原数组未选部分。coordinate 无粗细邻接
时仍不分配 coarse 数值工作区。高级分量优先读取回调保留单叶转换缓冲。

## 实测内存

[复现脚本](../../../../scripts/benchmark_selected_delivery.py)分别在基线源码和修改后
源码的独立解释器进程运行。基线临时目录由 `git archive 0bcbe2e analysis-core` 导出，
使用修改前保留的已编译扩展；修改后执行独立目录的 `make build`。没有切换工作区或
覆盖父包环境。固定文件为 128 个 24³ 叶块、8 个字段，普通值约 108 MiB；单层均匀拓扑，
字段具有空间线性变化。另由测试覆盖粗细邻接和区域准备。

每项测量均覆盖该操作的完整阶段，而非仅测读取或最终数组。准备项包括读取、工作区、
halo 填充和发布；计划项复用事先构建的几何。采样/输出项事先保留全域准备场。
`tracemalloc` 包含操作内的 NumPy 分配及 Python 管理开销；第二列再加预先保留的输入
数组，得到受控活跃内存的近似峰值。RSS 是独立进程的高水位，包括导入、准备输入、
内存分配器和运行库，不能与操作分配峰值直接互换。所有数字为 MiB，箭头为基线到修改后。

| 流程 | 操作内新分配峰值 | 含既有输入的近似峰值 | 进程 RSS 高水位 |
| --- | --- | --- | --- |
| 内部读取（8 选 2） | 55.10 → 43.28 | 55.14 → 43.33 | 111.72 → 88.03 |
| 全域 coordinate 准备（8 选 3） | 106.05 → 80.74 | 106.09 → 80.78 | 166.64 → 126.88 |
| 全域 exact 准备（8 选 3） | 94.84 → 94.87 | 94.88 → 94.91 | 138.14 → 138.69 |
| 复用几何计划准备（8 选 3） | 112.11 → 94.11 | 113.52 → 95.52 | 159.16 → 141.16 |
| 64 块缓存并读取（8 选 2） | 82.21 → 41.62 | 82.25 → 41.66 | 86.42 → 85.77 |
| 100 万点采样（8 选 2） | 84.91 → 23.88 | 279.34 → 218.31 | 380.66 → 282.75 |
| 524288 点沿线剖面（8 选 2） | 24.24 → 20.24 | 207.83 → 203.83 | 367.62 → 254.64 |
| 128³ 体积（8 选 2） | 78.14 → 34.38 | 249.69 → 205.92 | 421.23 → 268.02 |
| 2000 种子双向轨迹交付 | 39.80 → 1.92 | 104.22 → 66.33 | 340.88 → 297.67 |

九项的数值摘要均逐位一致。点采样对照“全分量结果后选列”，体积对照“先复制紧凑字段组
再采样”；轨迹对照完整收集与 64 种子分片交付，按全局顺序累计路径摘要。沿线批次为
65536 点，其余参数见脚本。每行是一次独立进程测量，不将单次耗时差异作为稳定提速结论。
普通 exact 准备的峰值基本不变：主要存活量仍是最终场和必需支持工作区，不能宣称所有
准备路径均降低内存。完整原始记录及耗时在[测量数据](selected-delivery-memory.json)。

复现命令（分别使用相应源码目录作为 `PYTHONPATH`，基线运行加 `--baseline`）：

```bash
analysis-core/.venv/bin/python analysis-core/scripts/benchmark_selected_delivery.py /tmp/selected.dat --make-fixture
analysis-core/.venv/bin/python analysis-core/scripts/benchmark_selected_delivery.py /tmp/selected.dat --mode coordinate
```

## 验证与交付边界

- `make -C analysis-core build` 完成。独立核心测试 286 个通过、2 个因未启用 OpenMP 跳过。
- 新增覆盖大小端、保存 ghost/CT 尾部、NaN 位模式和负零、非顺序叶/字段、嵌套映射、
  缓存键重绑定、文件变化和父 Source 关闭失效。
- 支持检查覆盖无 halo、分配但无效的 halo、连续求导后耗尽支持、共同有效支持，
  以及巨大目标/极低预算时先报支持错误。分类量拒绝不影响同组合法物理量的选择。
- 输出验证覆盖跨步数组、memmap、切片/体积与原结果逐位一致，调用者目标在失败后
  保留部分写入但没有完整返回产品。
- 分片验证覆盖全局编号、种子范围、双支状态、逐片读取、剖面往返、失败后不完整清单，
  以及错误范围、虚假完整性和校验和不匹配。
- 现有联合示例完成：质量 2.4e-12 kg，质量加权温度 840000 K，48 条热射线完整，
  6 个种子与 240 个可用剖面采样，保存/恢复一致。另保留测试中的 QSL、twist、
  区域/全域、准备池借用和现有线程执行验证。

分片完整表示全部请求种子已经交付，科学终止状态另行保存。`save_result` 仍为每片
创建编码快照，并不保证超大单片低内存。失败的调用者输出不能标为完整产品。
本轮没有声称真实 10–20 GB 文件验收或 OpenMP 执行验收。原始叶块流式可合并归约、
热 LOS/QSL 恢复状态，以及拓扑目录与缓存调度优化仍保留为后续候选。


## simplify 复查

继续按 simplify 技能完成三路独立审查，分别检查复用、质量和效率，并统一实施修正：

- 所选列、向量和标量 LOS 共用三线性模板及单分量计算；乘加顺序、半开范围和非有限值
  处理保持原样。热力学支持窗口复用 `_layout`，仍允许温度覆盖密度的超集。
- 区域读取先检查叶块数量，不再为每个小批次构造全域 `arange`。采样批次复用入口已解析的
  分量索引；有界采样仍在有效借用边界检查 halo/分类含义，并直接写目标批次。
- 修正一次性字段选择迭代器被重复消费的问题，覆盖地图及跨分片剖面。
- 修正调用者输出与 bounds 别名导致几何和数值被写坏的问题：写入前拒绝该别名。
- 分片交付先独立快照请求种子编号，避免生产器修改原编号后发布无法加载的“完整”清单。
  保存结束复用已构建清单，删除不必要的重新读取；临时文件清理使用 `missing_ok`。
- 删除停用的全域读取闭包和属性；保留 Source 旧构造参数的兼容性。

没有把完整切片流程强塞进体积输出，也没有为此修改分片持久化格式。全局编号清单逐片
重写的扩展成本仍在，后续若真实交付规模证明有必要，再单独调整文件布局。

重建成功，完整测试 **290 个通过、2 个 OpenMP 条件跳过**。新增回归覆盖上述三个正确性
问题及温度超集覆盖。另以简化前源码与已编译扩展快照分别启动解释器，对非线性混合层级
AMR 的所选列采样、全分量采样、带 twist 轨迹、标量 LOS、热节点、热 LOS 和变分 QSL
进行比较，七组数值摘要全部逐位一致。

针对简化部分复测了点采样、沿线剖面和体积输出：操作新分配峰值分别约为 23.87、20.24、
34.38 MiB，前后保持同一水平，数值摘要一致。一次运行的耗时仅留作原始记录，不据此
宣称稳定提速；结果记录在测量 JSON 的 `simplify_check` 下。
