# 大数据流程：内存峰值与实现路径

日期：2026-09-09。面向开发协作；检查基线 `4f6fc30`。
本轮做源码分析及小规模内存探针，没有修改生产实现，也未启动通用执行框架。
以下保留当时的分析状态；后续实作与前后峰值对照见[交付优化记录](selected-delivery-optimization.md)。

结论：需要同时控制输入场、中间派生场和最终结果的存活范围。仅调小种子或射线批次，
无法解决全域 Fields 常驻的问题。现有 exact-phase 准备池已经解决部分输入工作集问题；
最先值得补的是原始叶块统计链和应用结果分片。QSL、热 LOS 的按需输入另有积分状态问题。

## 1. 主要峰值在哪里

设叶块数为 N，每块内部尺寸为 b³，读取分量数为 k，所有数值仍用 float64。
记内部数据 R = 8Nkb³，两层 halo 数据 F = 8Nk(b+4)³，
coordinate-phase 粗层工作区 C = 8Nk(b/2+4)³。
非立方块按三个方向尺寸分别相乘。

| 位置 | 当前分配与峰值来源 | 可用的控制 |
| --- | --- | --- |
| 输入建立 | `source_from_arrays` 默认复制输入；调用者仍持有原数组时两份并存。兼容 Dataset 路径也会整理全域数据 | 大文件直接 `open_amrvac`，只打开索引与 Mesh；已经存在的数组可在遵守不可变生命周期时显式借用 |
| 原始读取 | `read_fields` 先生成分量优先数组，再转为分量相邻布局；多分量通常约 2R，加文件读取缓冲 | 按叶块分批调用；单分量转换有时可共享 backing，不应一律声称必有两份 |
| 全域准备 | coordinate-phase 为 Source + Mesh + 几何 + `max(R+I/O临时量, F+R, F+C)` | 明确选必要字段；该方案目前只支持全域 |
| exact-phase 准备 | 普通 `prepare` 仍分配整个选区 F；支持块工作区有容量上限 | `iter_prepared` 或 `PreparedPool` 才把主场工作集限制在批次/池容量 |
| 派生组合 | 每个 `derive`、MHD、curl 等结果有独立数组；旧输入与新输出同时存在 | 按块派生后消费、及时释放；同一流程只保留实际需要的输出 |
| QSL | 有限差分通常保留 B；twist 默认开启，会生成或消费全覆盖 curl。变分法再生成单位场和九分量梯度 | 种子迭代器只控制种子与结果批次。关闭不需要的 twist 是显式输出选择；不同 Q 方法不能当作透明内存替换 |
| 轨迹 | 低层有 `(种子批次,max_steps+1,3)` 路径数组；应用追踪再复制实际路径，最后打包全部路径 | 先筛选再追踪；输出要逐批消费，不能只降低 seed_batch |
| 均匀网格、图像 | `uniform_grid` 收集完整三维输出；LOS 应用保存全部 RaySet 与结果数组 | `iter_uniform_bounded` 逐 z 层消费；大图还要分片几何与结果 |
| 文件保存恢复 | `save_result` 的编码器复制所有数组，再压缩；加载恢复完整对象 | 每片独立保存；当前 NPZ 格式不承诺流式或内存上限 |

coordinate-phase 已在分配 C 前释放 raw，且发布最终 Fields 不复制数值；这里不是 R+F+C
三者同时存在。`read_full_interiors` 的文件缓冲通常按 16 MiB 分段，
Source 保守预算为两倍 `max(最大记录,16 MiB)`；它不会读取整份文件字节到内存，
但返回的原始数值仍覆盖全域。

MHD 恢复和逐点 derive 的计算临时量主要局限于一个块，问题主要是结果仍覆盖完整选区。
现有归约虽然逐块计算，却接收已存在的 Fields，且保存每叶块求和与覆盖列表，仍有 O(N)
辅助内存；不能把它描述成从 Source 自动流式读取、严格常量内存。

## 2. 数量级

以下是数组容量估算，未含 Mesh、Source、目录、Python 对象与运行库；不是实测峰值。
MiB/GiB 分别按 2²⁰/2³⁰ 字节计算。

以 **100 万个 8³ 叶块、8 个物理分量**为例：

- 内部数据约 **30.52 GiB**；两层 halo 后约 **103.00 GiB**。
- coordinate-phase 的数值数组峰值约 **133.52 GiB**；文件大小不能直接用作准备后内存预算。
- 单独的三分量 B、三分量一层 halo curl、九分量一层 halo 单位场梯度，
  分别约 **38.62、22.35、67.06 GiB**。变分 QSL 加 twist 的常驻数值约 **128.03 GiB**；
  生成梯度时还会暂时保留约 38.62 GiB 单位场。
- 两层 halo 相对内部容量的倍率在 b=8、16、32 时约为 **3.375、1.953、1.424**。
  块尺寸是数据属性，这里仅解释放大量，不建议为内存问题改变已有 AMR 数据。

输出同样能超过内存：

- 10 万种子、双向、每支实际 10001 个点，仅路径坐标约 **44.71 GiB**。
  应用最后打包时旧路径片段与最终坐标并存，约两份坐标；其预算检查更保守，按三份预留。
- 1024³ 均匀网格，一分量 float64 加有效掩码约 **9 GiB**，三分量约 **25 GiB**。
- NPZ 保存完整结果时至少要考虑原结果和编码快照同时存在；压缩后文件小不表示保存时内存小。

## 3. 已经具备什么

| 接口 | 输入数值可受容量限制 | 输出可受批次限制 | 尚存边界 |
| --- | --- | --- | --- |
| `iter_prepared` | 是，exact-phase | 是，同步借用批次 | 下一次迭代或关闭后借用失效；不能把批次收集进列表 |
| `PreparedPool` / `CurlPool` | 是，exact-phase | 由消费者决定 | Source 必须打开且不变；不能在使用借用期间淘汰槽位 |
| `iter_traces_bounded` | 是 | 是 | 开启路径仍按每批 max_steps 预分配；收集版 `trace_bounded` 又保留全结果 |
| `integrate_los_bounded` | 是，标量 LOS | 工作射线分批，图像仍完整 | 大图应进一步按面片拆分 |
| `sample_plane_bounded` | 是 | 查询分块，二维结果完整 | 不是二维输出流 |
| `iter_uniform_bounded` | 是 | 逐 z 层 | 至少保留一整层，tile_rows 只细分该层计算 |
| `iter_qsl` / `applications.iter_connectivity` | 否，要求已有 Fields | 是 | B、curl、变分梯度仍常驻；输入 PointSet 也可能很大 |
| `applications.thermal_los` | 否 | 射线计算分批，返回全部结果 | thermodynamics-first 暂无对应的按需恢复协调器 |
| `global_curl` | 准备输入分批 | 默认全域输出 | 允许调用者提供 backing，但全输出仍计入容量预算 |

准备池支持块数存在下限：`min(max(57,support_capacity),N)`。
把 support_capacity 写成 1 并不会只保留一个支持块。

这些路径都保留 Mesh/森林、源索引和叶块目录。池和临时 Fields 包含长度 N 的目录，
发布/借用也有 O(N) 检查；减少主数组后，超大量小块可能使目录和拓扑成为下一个瓶颈。
当前应先测真实数据，不能承诺整个进程内存与 N 无关。

## 4. 小规模探针结果

使用本机独立环境，每个模式单独启动进程，文件输入为无细化的均匀叶块、8³ 单元、3 个常量字段。
所有模式检查读取的内部值等于 1。bounded 固定主批次 32、支持容量 57，**仅消费前两批共 64 块**；
其他模式完成全域读取或准备。包含数值断言产生的临时量。

| 模式 | 叶块数 | 保留 Fields / MiB | tracemalloc 峰值 / MiB | 进程峰值 RSS / MiB |
| --- | ---: | ---: | ---: | ---: |
| 原始全读 | 512 | 6.01 | 13.15 | 64.66 |
| 原始全读 | 4096 | 48.06 | 97.26 | 184.20 |
| coordinate 全域 | 512 | 20.26 | 27.71 | 80.00 |
| coordinate 全域 | 4096 | 162.06 | 213.50 | 289.97 |
| exact 全域 | 512 | 20.26 | 25.34 | 70.88 |
| exact 全域 | 4096 | 162.06 | 177.68 | 236.86 |
| exact 分批 | 512 | 1.27 | 7.31 | 50.95 |
| exact 分批 | 4096 | 1.30 | 7.36 | 52.33 |

同为 exact-phase，全域与分批的差别仍然明确：受控主数组从 O(N) 变为 O(批次)。
这些结果只验证存储结构的预期；不是复杂 AMR、真实大文件、完整分批扫描的吞吐或长期 RSS 验收。
RSS 含解释器、库及进程先前分配；tracemalloc 在打开 Source 后启动，不能覆盖所有原生分配。
API 的 controlled_upper_bytes 是独立的保守预算，不能与 RSS 混用。

## 5. 建议实现顺序

### A. 原始叶块流与可合并归约

先提供轻量 `iter_read_fields`：每批原始内部值，halo=0，保留全局叶块编号与真实选区边界。
可先组合现有 `read_fields(...,leaf_ids=...)`，不用为积分额外准备 halo。
接着按批运行 MHD、积分或直方图，然后释放本批输入与派生结果。

归约合并必须明确：积分求和；均值合并分子和分母，不能平均各批均值；
直方图使用共同 edges，累计溢出区与覆盖信息；极值保持既定相等值排序规则。
全局请求范围/域外测度只计算一次，不能把每个不完整批次重复算成整域缺失。
采用确定顺序的补偿或成对求和，明确分批改变求和顺序可能产生的浮点差异。

这样无需改变插值、积分或物理定义，即可完成质量、能量、温度分布等代表性大数据分析。
把在准备节点恢复物理量改成在原始节点恢复后再准备，会改变非线性重建，不能混同。

### B. 应用结果逐片交付

给带编号的轨迹、采样、连接性和射线结果补轻量迭代入口，几何本身也按批生成。
已有 `PointSet.iter_plane` 可复用。每片完成即保存，避免先构造全量 LineSet/UniformResult。

第一版可用现有 `save_result` 保存独立片，额外提供一份清单：全局编号/范围、形状、单位、
方法参数、来源说明及各片位置。全部成功后原子发布最终清单；中断留下的片不能冒充完整结果。
加载接口应能枚举/读取单片，不能最后无条件 concatenate 回整个结果。

每片保存仍有编码复制，但峰值受片大小限制。固定形状输出可后续增加 `.npy` 磁盘映射，
变长轨迹可采用分片坐标与 offsets；暂不预设新存储依赖。磁盘映射不等于 RSS 硬上限，
页驻留、文件缓存、刷盘与消费者复制仍需测量。

### C. 从准备池连接派生量和现有消费者

局部微分/热力学公式可在借用期间计算，用完即释放，或增加小型带槽位版本标识的派生池。
现有 CurlPool 可以作为局部派生缓存的参照，但不必先把所有算子统一成新框架。
原场被淘汰后，派生槽也必须失效，且保持 halo、scheme、value_identity 和公式配置的关联。

LOS 要保留用户选择的非线性顺序：

- emissivity-first 可以逐块生成发射率，再走标量 LOS 的按需协调方式；需接入派生池。
- thermodynamics-first 要在采样 n、T 后计算响应，保留当前细分与积分定义；
  不能为套用现有标量接口而默默换成 emissivity-first。
- 补齐缺块时的积分进度后，单条长射线才不必依赖全域热力学 Fields；也可以研究明确区间分段，
  但不能在分段边界重复累计或跳过部分求积节点。

### D. QSL 的可恢复积分状态

当前连接性内核一次完成双支积分，缺覆盖被作为结果状态返回。
需要把“请求块 → 退出内核 → 准备 → 恢复”接入其自己的状态，不能直接用普通 trace 替换。
必须保留已接受步、RK 中间阶段、局部步长、端点定位括区间、twist 累加；
变分法还要保留切向量与重标定，有限差分还要关联中心种子与四个扰动种子。

先用已有 exact-phase 主池及按块 curl/梯度缓存，再研究分组调度减少不同种子来回换块。
缓存容量可能小于一批请求块的并集，需要拆分活动积分组并保证每组有进展。
验收重点是混合细化、缺块重入、端点定位、弱场/长线及与全覆盖同方法结果的一致性。
QSL 仍不保存完整路径；筛选后独立追踪的既定流程保持不变。

### E. 真实瓶颈出现后再处理目录与 I/O

全量扫描优先顺序读取叶块；轨迹可按请求块组织活动组，但保留全局种子编号与结果排序。
记录实际准备块数、重复读取字节、填充时间与进度，判断是否发生缓存反复淘汰。
如果 Mesh/目录已占主要容量，再考虑稀疏目录或拓扑分区；这会触及核心边界，应有实际数据支持。
线程目前共享输入；改用多个进程可能重复 Source、Mesh、准备池和结果，不能视为免费并行。

## 6. 内存预算的边界

`memory_limit` 是单次操作的已知数组预算，不是进程硬限制，也不会自动退回其他 scheme。
调用者仍持有的 Source、其他 Fields、既有结果，以及 Python/分配器/文件缓存开销，
未必全被某次消费者计入。应用协调层应给存活对象预留容量，然后把剩余预算传给下一步。
没有显式预算的用户派生回调也可能自行分配很大数组。

下一步最有价值的代表性验证是：同一实际文件上的分批 MHD 加统计，以及筛选后的轨迹分片保存。
记录阶段 RSS、常驻数组、读取/重复准备量和输出大小，检查结果状态与覆盖；
先完成这两条具体流程，再决定是否需要实现 QSL/热 LOS 的可恢复内核。

## 7. 字段组合与剖面整合后的场景选择

后续已汇总字段组合与沿线诊断，并完成 simplify，见[整合记录](composition-profile-integration.md)。
它们改善表达与数据关联，但没有自动改变全域输入和完整结果的内存规模。

| 常见任务场景 | 容易膨胀的位置 | 值得保留的方法 |
| --- | --- | --- |
| 只要质量、能量、温度分布 | 为统计读取并准备全部物理量，随后又保存所有恢复量 | 原始 halo=0 叶块流、逐块 MHD、多输出配方、可合并归约 |
| 同一快照反复出图、诊断与追踪 | 每次重复准备或反复提取/合并同样的场，旧结果仍被引用 | 数据放得下时保留一次全域准备并复用；确定 B 组后复用其 curl |
| 少量种子却经过很大空间范围 | 因为线跨域而加载全部体数据 | 现有准备池与可恢复普通追踪；剖面按访问叶块协调采样是后续候选 |
| 密集 QSL 加 twist，特别是变分法 | B、curl、单位场与九分量梯度叠加 | 输入放得下时保留全域场加输出分片；放不下时再做 QSL 自身的恢复状态 |
| 很多长曲线同时采温度、密度、电流 | 完整 LineSet 加全体采样值/掩码；最后拼接或保存再次复制 | 筛选后追踪，按种子片完成追踪、剖面及保存；分片保持全局编号和分支偏移 |
| 高分辨率网格、大图或批量快照 | 全量结果收集、NPZ 编码快照、同时持有多个快照 | 分层/分片输出与最终清单；快照逐个处理并释放 |

**保留两种输入方式和一种混合方式**：
全域准备后复用、显式有容量上限的按需准备、全域输入加分片输出。
全域数据放得下且要反复访问时，保留直接消费方式有实际价值；
没有必要为每个小任务都引入池和持久化协调。

新接口的使用取舍：

- `select_fields` 和 `merge_fields` 明确复制到紧凑独立数组；这保证生命周期和连续布局，
  但不能当作“廉价视图”在大域上反复调用。对于后续逐点公式，直接向 `derive_many`
  传多个命名输入组，可避免先合并再计算的整域副本。
- `derive_many` 允许每块共享中间计算，输出仍按请求分量分配。
  需要限制整条流程时，把它放进叶块批次循环，消费后释放输出。
- `sample_line_profiles` 的 point_batch 只限制采样临时量，完整采样结果保留在内存。
  其每点新数组约 `18+9k` 字节，另共享每点 24 字节的曲线坐标；
  例如一亿个存储点、三个采样分量，两者合计约 6.43 GiB，还未计入输入场、种子和临时量。
  `usable` 和按线拼接展示也会创建额外数组，展示结果应按需使用。
- 目前原生剖面采样每批读取输入组全部分量再选列。
  一次性的少量剖面通常可直接传现有场；重复采样少量分量时，可以一次选择紧凑字段组后复用。
  不应为省掉小批次临时列，反而每次复制整个大域。

**优先保留为后续实现候选**：原始叶块读取迭代器、可合并归约、带清单的应用结果分片。
**待明确数据规模后再实现**：派生池、热 LOS 与 QSL 的恢复状态。
**暂不提前建设**：全套存储后端、自动调度框架、稀疏拓扑重构或多进程复制输入。
这些选择不更换精度、数值 scheme、非线性重建顺序或有效覆盖规则。
