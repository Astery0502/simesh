## 数据与依赖

| 对象或入口 | 固定职责 |
| --- | --- |
| `Mesh` | 共享整数拓扑与物理几何；不拥有字段、文件或积分状态 |
| `Source` | 文件/数组的字段定义和内部值读取；不绑定 ghost 准备方法 |
| `Selection` | 请求及原始叶覆盖；额外支撑不变成输出物理覆盖 |
| `prepare` | 根据显式 scheme 读取真实支撑、完成准备并发布独立 `Fields` |
| `Fields` | 数值、字段定义、覆盖、slot 映射及有效支撑；普通消费者只读已准备数据 |
| `bounded` | 明确选择的有限容量准备与消费协调；不成为普通消费者的隐式读取入口 |

保留原始 AMR 叶块作为当前计算块。内部数值采用 float64，存储为
`(slot, x, y, z, component)`，原始叶号与 slot 通过映射区分。
不采用合并同层块、新重构、通用任务图或统一表达式执行器。

`storage_halo` 描述内部区偏移，`valid_halo` 描述实际完成的支撑。
准备主场具有两层有效 halo，中心差分消耗一层。已分配但未完成的 padding
不能用于采样或差分。区域边缘不等于物理边界，缺失覆盖通过既有状态/校验表达。

最终值与准备工作区分开拥有；关闭 Source 或释放 coarse 工作区后，独立场
仍可消费。curl 等派生场独立保存，不依靠保留整份 B 来证明派生关系。
借用批次按作用域失效；独立结果和调用者保留的输出由其持有者负责生命周期。

## 数值与执行

- 区域/有界 `exact-phase` 与全域 `coordinate-phase` 保持为两个显式方案，
  不因覆盖或工作者数变化而互相切换。后者保留已验收的 v2 边界修正。
- 插值、中心差分、RK4 接受前缀、twist、标量 LOS 和热 LOS 保持当前定义。
  热模型、温度、单位及两种非线性重构次序必须明确，不自动推断物理标定。
- Python 负责边界和编排，NumPy 保存数组，热点计算主要在 Cython CPU 内核中。
  默认一个工作者，支持的原生路径可显式选择线程池/OpenMP。
- 几何计划只复用几何，数值和限制器按当前值重新计算；缓存为显式可选能力。
- `memory_limit` 是操作所计入的受控活跃数组预算，不是整个进程 RSS 上限；
  应用还需考虑自己同时保留的其他结果。

## 应用可直接消费的结果

现有接口提供采样、独立导数/curl、切片、磁力线/twist/重追踪、标量/热 LOS，
以及拥有结果的分批追踪和均匀网格切片。具体签名与用法以
[新包 README](../../../../README.md)为准。

`source_from_dataset` 显式复制已加载 Dataset 内部值；`write_amrvac` 导出
完整原始覆盖的普通字段。Dataset、普通读写、2D singleton-z、VTK 和数组工具
通过自包含兼容层保留，旧 AMRMesh 不进入原生 Source/Fields 的所有权。
兼容执行、周期/CT 写入、VTK 坐标约定及布局见
[MIGRATION.md](../../../../MIGRATION.md)。

原生文件入口仍限非周期 Cartesian 3D v5 普通字段，数组来源使用等价的 3D 网格。
N4 当时未交付脚点定位和 Q；后续独立 `qsl` 消费者已补上这部分，原有
`trace` 的接受前缀语义保持不变。详见[磁连接性](../connectivity.md)。
周期/CT/GPU 原生分析、有界非线性热 LOS 和真实超内存输入仍不属于已交付保证。

## 后续变化原则

应用开发优先组合现有接口，固定核心不意味着忽略实际缺陷。
若出现正确性问题或具体应用确实受阻，只针对该问题评估必要的核心变更并验证；
不因新建应用就重启核心性能探索、完整方案比较或历史阶段流程。
