# FND-001 Contract: Layout, Indices, Ownership, And Valid Regions

## Responsibility

FND-001 defines the M0 interchange conventions shared by Morton mappings,
topology, block storage, halos, sampling, and operators. It defines no mesh
connectivity or numerical operator behavior.

## Axes, Indices, And IDs

- M0 has three spatial axes in `(x, y, z)` order, numbered `(0, 1, 2)`.
- Rewrite coordinates, field positions, global block IDs, and buffer slots are
  zero-based.
- Contract-visible index arrays are native-endian signed `int64`, C-contiguous.
- A chunk-local slot is not a global block ID. For a `block_ids` vector,
  payload slot `s` represents global block `block_ids[s]`; consumers may not
  assume equality.
- ID zero is valid and is never an implicit missing-value sentinel.
- Conversion to AMRVAC one-based tree coordinates belongs at a file-adapter
  boundary.
- A contract-visible region bound, flattened offset, or spatial volume must fit
  in signed `int64`; orchestration rejects unrepresentable values with
  `OverflowError` before entering Cython.

`ravel_cell(index, shape)` maps `(i, j, k)` to the C-order spatial offset
`(i * shape[1] + j) * shape[2] + k`. `unravel_cell` is its exact inverse.
This storage offset is distinct from Morton coding, AMRVAC disk order, and any
topology-specific flattening.

## Payload Layout

Canonical field payloads are native-endian `float64`, C-contiguous arrays:

- unpadded chunks: `(nslot, nfield, bx, by, bz)`;
- padded chunks/workspaces: `(nslot, nfield, sx, sy, sz)`.

The exact element offset is
`((((slot * nfield + field) * sx + i) * sy + j) * sz + k)`.
The z coordinate is fastest varying. A later measured kernel may use another
scratch layout, but producer/consumer interchange uses this layout and any
conversion is explicit.

## Regions

A spatial region is a pair of signed triplets `[lower, upper)` in the storage
coordinates of one payload. It satisfies
`0 <= lower <= upper <= spatial_shape` componentwise. The extent is
`upper - lower`.

The interior of padded storage is
`[interior_lower, interior_lower + interior_shape)`. A declared valid region
contains the interior and may contain allocated halo cells. Cells outside the
valid region have unspecified values and must not be read as inputs or compared
as results. One payload argument has one common spatial valid region; fields
with different validity use separate payloads or their common intersection.

Allocated halo width and consumer-required halo width are separate concepts.
FND-001 permits zero, one, or more allocated cells on each side and does not
require symmetry.

## Ownership And Mutation

- Inputs are caller-owned, borrowed read-only for a call, and never retained.
- Outputs and scratch are caller-owned and exclusively borrowed for the call.
- Only a capability's declared output or workspace region may be mutated.
- Input/output overlap is forbidden unless a later contract explicitly permits
  in-place execution.
- The compiled boundary performs no silent dtype conversion, transpose,
  contiguity repair, or payload allocation.
- Validation occurs before hot loops.

`copy_region_into(source, source_lower, destination, destination_lower,
extent)` copies exactly between equal-slot, equal-field payloads. It mutates
only the selected destination box and preserves all destination values outside
that box. Source and destination may not overlap.

## Exactness And Evidence

All FND-001 index transformations, bounds, and payload copies are exact; no
floating-point tolerance applies. Correctness is established by:

- an independent Python/NumPy reference;
- axis-coded nonsymmetric arrays and the exact offset formula;
- asymmetric source and destination boxes;
- invalid-region sentinels and input/output mutation checks;
- exact comparison with the current field-major block surface.

The Cython copy path uses caller-provided storage and no payload-sized scratch.
Runtime and throughput are measured across increasing region sizes; parallel
scaling is not relevant to this serial foundation primitive.

## Immediate Composition

Current AMRVAC block arrays can feed this layout through an explicit contiguous
`float64` adapter. MOR-001 consumes the axis/index convention; STO-001 consumes
the slot/ID, payload, ownership, and valid-region conventions; FND-002 consumes
the region vocabulary for access requirements.
