# FCL-001 Contract: Deterministic Direct-Face Support Closure

## Responsibility

FCL-001 plans the maximal dense ascending primary prefix whose unique
nonrecursive direct-face support union fits explicit caller capacity, and
computes the exact capacity sufficient for one direct-face closure everywhere.
It defines no byte accounting, topology construction, full-halo/refined
closure, payload transfer, halo values, backend, or scheduling.

## Stable Operations

```text
plan_direct_face_closed_prefix(
    first_primary_id,
    face_neighbor_ids,
    selected_ids,
) -> (primary_count, selected_count)

minimum_direct_face_closed_slots(
    face_neighbor_ids,
) -> slot_count
```

`face_neighbor_ids` is borrowed read-only native-endian C-contiguous TOP-001
`int64[N,6]`.  TOP semantic validity is an unchanged upstream precondition;
FCL validates representation but does not rescan displacement, reciprocity, or
ID ranges per call.

`selected_ids` is caller-owned writable native-endian C-contiguous `int64[S]`;
its length is explicit capacity.  `first_primary_id` accepts Python/NumPy
integer scalars except booleans/rank-zero arrays, is signed-int64 representable,
and lies in `[0,N]`.

Inputs are unchanged and nothing is retained.  Outputs may not overlap the face
table.  Validation completes before ordinary mutation.

## Exact Closure Plan

Consider dense primary candidates from `first_primary_id` upward in PRI-001
order.  Accepted primaries always occupy

```text
selected_ids[:primary_count]
    = first_primary_id ... first_primary_id+primary_count-1.
```

Closure-only support occupies
`selected_ids[primary_count:selected_count]`.  For each candidate, form a trial:

1. remove the candidate from support if it was previously discovered, preserving
   the relative order of every other support ID;
2. append the candidate to the primary prefix;
3. scan face columns `0..5` and append each nonnegative ID not already a primary
   or support, in first-discovery order;
4. accept the trial exactly when its unique union fits capacity.

If the first candidate's closure does not fit, raise
`ValueError("chunk capacity cannot fit the first primary closure")` before any
write.  If a later trial does not fit, retain the already accepted plan and end
the chunk normally.  This is the maximal feasible contiguous primary interval
because the closure union is monotone.

On success, selected IDs are unique, every support ID is a direct nonphysical
face neighbor of an accepted primary, no support ID is primary, and

```text
0 < primary_count <= selected_count <= S
```

before end-of-stream.  The suffix `selected_ids[selected_count:]` is bitwise
preserved.  Successive calls from zero advancing by `primary_count` cover every
global ID exactly once as primary; support may recur.

At `first_primary_id == N`, return `(0,0)` without mutation for any capacity.
Before end, zero capacity raises `ValueError` before policy execution.

## Minimum Progress

For valid TOP-001 topology, one block's direct-face closure size is

```text
1 + count(face_neighbor_ids[block, face] >= 0 for face in 0..5).
```

`minimum_direct_face_closed_slots(...)` returns the maximum over rows, or zero
for an empty table.  For a nonempty nonperiodic Cartesian 3D table it is in
`[1,7]`.  Capacity at least this value guarantees every unfinished planner call
accepts at least one primary; a smaller capacity fails at an argmax block.

This helper intentionally counts raw nonphysical columns under the TOP-valid
precondition rather than repairing/uniquing arbitrary corrupted rows.

## Validation, Errors, And Atomicity

Canonical planner validation order is face table, selected output,
`first_primary_id`, range, overlap, and unfinished positive capacity.  Wrong
objects/dtypes or scalar kinds raise `TypeError`; invalid rank/layout/
writability/range/overlap/capacity raise `ValueError`; scalar overflow raises
`OverflowError`.  The minimum helper validates only the face-table
representation.

First-fit failure and all Python-boundary errors preserve the complete output.
A successful later-boundary stop is not an error and preserves only the suffix
after the returned selected count.

## STO-002 Compatibility

Existing `minimum_face_closed_slots(...)` delegates to the canonical helper.
Existing

```text
plan_level1_chunk(first, face_neighbor_ids, True, chunk_block_ids)
```

preserves its face-table, output, first/range, exact-Python-bool, overlap, and
capacity validation order before delegating, and returns the identical counts,
IDs, errors, and suffix.  Its `False` path remains PRI-001.  The full-halo
planner is unchanged and outside FCL-001.

## Independent Evidence

The independent reference uses Python primary/support lists and commits only
fitting trials.  Evidence covers empty/singleton/interior/clipped topologies;
all closure sizes; exact minimum/progress; promotion; overlapping support;
later-candidate boundary; first-fit atomicity; suffix; exhaustive/random full
traversal; scalar/array/overlap errors and precedence; arbitrary TOP-valid
shapes; old/new wrapper conformance; and explicit absence of diagonal support.

## Performance And Memory

FCL performs bounded linear support membership with no hash, bitmap, dense
marker, or size-dependent scratch.  Runtime depends on accepted candidates,
selected-prefix length, and six faces.  Measure primaries/s, selected IDs/s,
chunk count, load amplification, capacity utilization, capacity scaling,
minimum-helper throughput, wrapper overhead, fixed allocation, and small
reference ratio.  Payload/RSS/I/O and parallel scaling are not FCL kernel
metrics.

## Immediate Composition

PRI-001 supplies dense candidate identity and TOP-001 supplies direct relations.
No numerical direct-face consumer currently remains; the preserved public STO
wrapper and face-closure benchmark are the supported immediate consumer and
integration evidence.  HCL-001 later extracts full-halo closure, after which
STO-002 can become a compatibility-only wrapper capability.
