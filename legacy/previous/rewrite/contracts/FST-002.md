# FST-002 Contract: Refined Forest Artifact Conformance

## Responsibility

FST-002 proves that caller-supplied plain arrays are exactly one FST-001
Cartesian 3D flat forest artifact and returns its maximum level.  It defines no
construction, topology/contact relation, balance policy, geometry, storage,
payload, file conversion, cache, or scheduling behavior.

## Stable Operation

```text
validate_refined_forest_arrays(
    root_shape,
    coord_to_rank,
    rank_to_coord,
    root_node_ids,
    node_levels,
    node_coords,
    parent_node_ids,
    child_node_ids,
    node_leaf_ids,
    leaf_node_ids,
) -> max_level
```

Let `R=product(root_shape)`, `K=len(node_levels)`, and
`L=len(leaf_node_ids)`.

- `root_shape`, `coord_to_rank`, and `rank_to_coord` are borrowed read-only
  MOR-001 C-contiguous `int64` arrays with shapes `(3,)`, `root_shape`, and
  `(R,3)`.
- `root_node_ids` is borrowed read-only C-contiguous `int64[R]`.
- Node vectors `node_levels`, `parent_node_ids`, and `node_leaf_ids` are
  borrowed read-only C-contiguous `int64[K]`.
- `node_coords` is borrowed read-only C-contiguous `int64[K,3]` and
  `child_node_ids` is borrowed read-only C-contiguous `int64[K,8]`.
- `leaf_node_ids` is borrowed read-only C-contiguous `int64[L]`.

Read-only and writable inputs are both accepted.  Inputs may overlap when their
simultaneous values satisfy all semantics; FST-002 mutates and retains nothing.
On success it returns exact maximum level as a Python `int`.

MOR-001 mathematical key order is an upstream precondition and is not
recomputed.  FST-002 validates dense in-box inverse consistency and aligns
forest roots to the supplied rank rows.  A mutually consistent non-Morton
permutation is outside the input contract even though inverse validation alone
cannot distinguish it.

## Exact Conformance

FST-002 first validates the supplied MOR maps as dense in-box inverses.  It
then performs canonical preorder traversal.  Before root rank `r`, the next
unconsumed node must equal `root_node_ids[r]`; that root has parent `-1`, level
one, and coordinate `rank_to_coord[r]`.

For every visited node with expected `(level,coord,parent)`:

- stored level, coordinate, and parent equal the expected values exactly;
- if `node_leaf_ids[node] >= 0`, it equals the next dense leaf ID,
  `leaf_node_ids[leaf] == node`, and all eight child IDs are `-1`;
- otherwise `node_leaf_ids[node] == -1`, all eight child IDs are valid, and
  child column `c=xbit+2*ybit+4*zbit` equals the next preorder node before its
  subtree; its expected level/coordinate are
  `level+1` and `2*coord+(xbit,ybit,zbit)`.

Every non-root is therefore consumed exactly once under one parent.  After all
roots, exactly `K` nodes and `L` leaves must be consumed.  This also proves root
subtree intervals partition the stream and `K=R+8*P`, `L=R+7*P` for
`P=K-L` internal nodes.

Before descending, the complete logical grid extent
`root_shape*2**(level-1)` must fit signed `int64`; validation uses safe doubling
checks.  This bounds recursive C stack depth and proves expected coordinates
fit.  The returned maximum is the largest validated node level.

## Validation, Errors, And Atomicity

Exact ndarray type/dtype/rank/shape/C-contiguity and positive representable
root volume are validated before recursive access.  Invalid MOR maps, root
order, levels, coordinates, parents, children, leaf maps, sentinels, counts, or
trailing/unconsumed artifacts raise `ValueError` identifying the first root,
node, or leaf where practical.  Wrong types/dtypes raise `TypeError`.
Unrepresentable root volume or logical extent raises `OverflowError`.

Because the operation has no mutable output, every failure preserves all
inputs by construction.  No repair, conversion, visited set, hash, bitmap, or
selection-sized scratch is permitted.

Successful conformance applies only while every borrowed array remains
unchanged.  If a caller mutates any accepted writable input, that creates a new
artifact lifecycle and every unchecked consumer requires another successful
FST-002 call.  FST-002 does not retain arrays or attempt mutation tracking.

## Exactness, Evidence, And Performance

All results and invariants are discrete and exact.  Evidence includes valid
FST-001 and Python-reference artifacts; all-level-1, mixed-depth, maximum-depth,
and nonsymmetric roots; independent corruption of every array family; read-only
and overlapping input views; complete MOR corruption; and exact conformance of
the representative real refined AMRVAC tree.

The compiled pass is `O(R+K)` and uses only `O(max_level)` C stack.  Measure
nodes/s, fixed allocation, root/depth/size scaling, real-tree time, and
construction+conformance overhead.  FST-002 runs once per artifact lifecycle;
TOP-002/BAL/query/chunk loops must consume the established precondition rather
than invoke it repeatedly.

## Immediate Composition

FST-001 and future metadata adapters produce candidate arrays.  TOP-002 uses a
successful FST-002 result before raw contact queries; GEO-002 uses the same
conformance boundary before selected leaf geometry; native I/O uses it before
binding block offsets/payload order to leaf IDs.
