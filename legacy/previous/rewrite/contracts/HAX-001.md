# HAX-001 Contract: Apply A Level-1 Same-Level Halo Plan

## Responsibility

HAX-001 applies an explicit HPL-001 direction/source-slot plan to complete
same-level-dependent halo cells in a canonical level-1 workspace.  It owns no
topology discovery, global block mapping, closure planning, physical rule
meaning, allocation, chunk policy, refinement, periodicity, storage backend,
or scheduling.

## Stable Operation

```text
apply_level1_same_level_halo_plan(
    payload,
    interior_lower,
    interior_upper,
    source_slots,
    physical_masks,
    boundary_modes,
    normal_field_slots,
) -> None
```

- `payload` is caller-owned writable C-contiguous
  `float64[S,F,sx,sy,sz]`.
- `[interior_lower,interior_upper)` is a borrowed C-contiguous `int64[3]`
  nonempty box inside the spatial shape; every selected interior is valid.
- `source_slots` is borrowed HPL-001 C-contiguous `int64[P,27]` with `P<=S`.
- `physical_masks` is the aligned borrowed C-contiguous `uint8[P,27]` HPL plan.
- `boundary_modes` is borrowed C-contiguous `uint8[F,6]` with PBC/HAL codes.
- `normal_field_slots` is borrowed C-contiguous `int64[3]`, with entries `-1`
  or local field positions.

Payload may not overlap metadata.  Read-only metadata may overlap one another.
Nothing is retained or allocated.

## Planned Cell Application

For target storage coordinate `q`, derive the full outside direction
`d[a] in {-1,0,1}` from the interior box and use HPL's exact x-fast column:

```text
column = (d[z]+1)*9 + (d[y]+1)*3 + d[x]+1.
```

If `source_slots[p,column] == -1`, preserve the target.  This covers interiors,
center, and purely physical cells already owned by HAL-001.  Otherwise, for
each axis:

- `d[a]==0`: source coordinate is `q[a]`;
- `d[a]!=0` and physical mask bit `a` is clear: translate through the sibling
  block with exact overflow-safe offset arithmetic.  For
  `L=interior_lower[a]` and `U=interior_upper[a]`, lower sibling uses
  `U-(L-q[a])` and upper sibling uses `L+(q[a]-U)`.  The parenthesized positive
  layer/offset is evaluated first; the allocated-depth check proves the result
  lies in `[L,U)`;
- `d[a]!=0` and mask bit `a` is set: use PBC-001's physical source index for
  this field's face mode.

Read exactly one value from the planned source slot/interior coordinate, then
apply PBC-001 value transforms for set mask bits in ascending x, y, z order.
Write the result to `payload[p,field,q]`.

All nonnegative source slots must be in `[0,S)`.  Masks use only bits zero
through two.  HPL semantic validity is a precondition: center is `(-1,0)`, a
nonnegative source corresponds to at least one sibling axis, and every
direction/mask/source is the established selected relation.  HAX validates
safe ranges/bit shapes but does not reconstruct topology to prove that
precondition.

## Mutation, Validity, And Errors

Every allocated lower/upper halo width must be no larger than the corresponding
interior extent.  On success:

- every same-level-dependent cell of `payload[:P]` is defined;
- primary interiors and purely physical HAL-001 cells are bitwise preserved;
- all support slots `payload[P:]` are bitwise preserved;
- the complete allocated spatial box is valid for the primary prefix.

On entry, every purely physical primary halo cell (a direction whose HPL source
slot is `-1`) must already contain the valid HAL-001/PBC result.  HAX preserves
those cells.  Support halos remain unspecified and are never read.  The
ordinary composition is gather selected interiors, HAL-001 physical fill, then
HAX plan application.

Before mutation, validate exact ndarray types/dtypes/ranks/shapes/
C-contiguity, payload writability/nonoverlap, boxes/halo depths, plan slot
ranges/mask bits, boundary mode codes, and normal-slot ranges/requirements.
No-inflow anywhere on axis `a` requires `normal_field_slots[a]>=0`, matching
HAL-001/HAL-002 aggregate validation.  With `F=0`, every normal slot must be
`-1` because no local field position exists.

Type/dtype failures raise `TypeError`; invalid layout, overlap, region, depth,
plan, mode, or normal metadata raises `ValueError`; unrepresentable scalar
counts raise `OverflowError`.  Every invalid call leaves payload unchanged.
Zero primary or field axes are valid after ordinary metadata validation and
perform no writes.

## Exactness, Evidence, And Performance

Sibling reads are bitwise copies.  Physical coordinate/value behavior is
exactly PBC-001, including signed zeros, infinities, and NaN payloads.  Evidence
compares every payload bit with an independent plan consumer and the retained
HAL-002 fused wrapper across full and bounded closures, asymmetric halos,
reordered selected slots, mixed modes, empty prefixes, and invalid plans.

The Cython executor allocates no scratch or retained memory.  Measure written
values/s, apply-only and checked plan+apply time, field/halo/primary scaling, fixed allocation, and
gather/HAL-001/HPL/HAX composition against fused HAL-002.  HPL's `243*P` bytes
are caller-owned plan state and must be counted by any executor retaining them.

## Immediate Composition

STO-002/STO-001/HAL-001 establish selected interiors and pure physical cells;
HPL-001 establishes explicit sources/masks; PBC-001 supplies scalar rules.
HAX completes primary payloads for SAM-003 and OPR-002.  HAL-002 remains the
faster compatibility composition when explicit plan reuse is not selected.
