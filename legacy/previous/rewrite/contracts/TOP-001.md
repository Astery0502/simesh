# TOP-001 Contract: Validated Non-Periodic Level-1 Topology

## Responsibility

TOP-001 maps each Cartesian 3D level-1 block to its six face neighbors and
classifies physical faces. It consumes MOR-001 maps and defines no refinement,
periodicity, geometry, halo values/storage, field payload, or chunk policy.

## Face Table

The stable compiled operation is

```text
fill_level1_face_neighbors(
    root_shape,
    coord_to_rank,
    rank_to_coord,
    face_neighbor_ids,
) -> None
```

For `N = product(root_shape)`, `face_neighbor_ids` is caller-owned writable
native-endian C-contiguous signed `int64` with shape `(N, 6)`. Columns are:

| Column | Axis | Side | Coordinate displacement |
| ---: | --- | --- | --- |
| 0 | x | lower | `(-1, 0, 0)` |
| 1 | x | upper | `(+1, 0, 0)` |
| 2 | y | lower | `(0, -1, 0)` |
| 3 | y | upper | `(0, +1, 0)` |
| 4 | z | lower | `(0, 0, -1)` |
| 5 | z | upper | `(0, 0, +1)` |

Column is `2*axis + side`, where side zero is lower and side one is upper;
the opposite face is `column ^ 1`.

An in-domain entry is the zero-based global Morton block ID from
`coord_to_rank`. Exact value `-1` is the physical-boundary sentinel. Zero is a
valid block ID. No separate M0 kind, mask, center, edge, or corner table exists.

`level1_face_neighbors(...)` is an allocating helper returning a new table.

## Inputs, Validation, And Mutation

`root_shape`, `coord_to_rank`, and `rank_to_coord` are borrowed read-only and
must satisfy their MOR-001 dtype, layout, shape, and representability contract.
TOP-001 structurally validates the maps before output mutation:

1. every `rank_to_coord[r]` lies inside `root_shape`;
2. `coord_to_rank[tuple(rank_to_coord[r])] == r` for every rank.

With `N` rows in an `N`-cell box, these conditions prove unique coverage and
inverse consistency without scratch. Morton key order remains MOR-001's
responsibility and is not recomputed. The output may not overlap any input.
On success the whole output is overwritten, inputs are unchanged, and no array
or pointer is retained.

Type/dtype errors raise `TypeError`. Invalid shapes, nonpositive extents,
non-C-contiguity, read-only output, overlap, or inconsistent maps raise
`ValueError`. Volume overflow raises `OverflowError`. Invalid calls leave the
output unchanged.

## Exactness And Invariants

All results are discrete and exact; no tolerance applies.

- Sentinel occurs exactly when the source coordinate lies on that physical
  face.
- Every non-sentinel ID is in `[0, N)`, differs from the source, and has the
  declared coordinate displacement.
- Reciprocity is exact: if `n = neighbors[b, d]`, then
  `neighbors[n, d ^ 1] == b`.
- Both faces of a singleton axis are physical; they never self-reference.
- The total sentinel count is
  `2*(ny*nz + nx*nz + nx*ny)`.
- Valid face steps on distinct axes commute. Consequently any M0 edge/corner
  neighbor can be derived without a stored 27-direction table.

Current comparison extracts flat columns `(12, 14, 10, 16, 4, 22)`, converts
one-based indices to zero-based by subtracting one, and requires current type
one exactly where the rewrite uses `-1` and type three elsewhere.

## Performance And Memory

Construction performs one allocation-free `O(N)` map-validation pass and one
`O(N)` six-face fill. Required topology storage is `48*N` bytes with no heap
scratch. A full 27-entry `int64` table would require `216*N` bytes and is not
retained. Parallel scaling is not relevant unless composed construction becomes
material in later executor measurements.

## Immediate Composition

MOR-001 produces the validated IDs and coordinates. GEO-001 consumes block IDs
and coordinates. STO-002 uses face closure to identify adjacent chunks.
HAL-001 consumes sentinel faces; HAL-002 consumes same-level face IDs and may
derive diagonals or use ordered face sweeps without changing this contract.
