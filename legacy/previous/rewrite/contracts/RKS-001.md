# RKS-001 Contract: Fixed Classical RK4 Augmented-State Arithmetic

## Responsibility

RKS-001 constructs half/full classical RK4 stage states and final candidates
for explicit augmented `(x,y,z,I)` rows. It owns only the fixed binary64 stage
and weighted-sum operation trees. It defines no RHS meaning, sampling,
accept/reject, termination, cache, I/O, or seed scheduling.

## Stable Operations

```text
field_line_rk4_stage_into(
    base_states,
    previous_rhs,
    step_size,
    half_step,
    stage_states,
) -> None

field_line_rk4_finish_into(
    base_states,
    k1,
    k2,
    k3,
    k4,
    step_size,
    candidate_states,
) -> None
```

Every state/RHS/output is C-contiguous `float64[N,4]` in `(x,y,z,I)` order.
Inputs are borrowed read-only; outputs are caller-owned writable and may not
overlap any input or metadata. `half_step` is an exact `bool`. `step_size` is a
Python/NumPy real floating scalar whose binary64 value is finite, positive, and
normal. Slots may be empty. State/RHS components may carry arbitrary IEEE bits;
RKS performs its arithmetic and does not classify them.

## Exact Operation Trees

Stage construction first computes the shared scale once:

```text
half = 0.5 * step_size
scale = half if half_step else step_size
for each row/component:
    delta = scale * previous_rhs
    stage = base + delta
```

Finalization separately evaluates every row/component:

```text
two_k2 = 2.0 * k2
sum12 = k1 + two_k2
two_k3 = 2.0 * k3
sum123 = sum12 + two_k3
sum1234 = sum123 + k4
h6 = step_size / 6.0
delta = h6 * sum1234
candidate = base + delta
```

Each multiply/add/divide is separately rounded binary64; the production Cython
implementation prevents contraction. Half-stage uses exactly the same tree for
k1 and k2. Full-stage uses k3. The final operation is classical RK4
`base + h*(k1+2*k2+2*k3+k4)/6` with the ordering above.

## Validation, Mutation, And Errors

Before output mutation validate scalar kinds/values, exact ndarray types,
dtypes, ranks, equal shapes, C-contiguity, output writability, and output
nonoverlap with every input. Type/dtype/scalar-kind failures raise `TypeError`;
invalid shape/layout/step/writability/overlap raises `ValueError`. Integer or
byte overflow is not introduced by these fixed-shape borrowed arrays. Ordinary
failure preserves output bits. Inputs remain unchanged and no view is retained.

## Reference, Tests, And Performance

The independent scalar reference follows the written trees. Cover empty/single/
batch rows, half/full stages, translated signed-zero and cancellation cases,
subnormal/large finite values, each nonfinite input position, output sentinels,
invalid steps/layouts/aliases, and exact reference bits or required IEEE
classification. Compose constant and rotational analytic RHS fields to show
expected exactness/order and fourth-order global convergence where smooth.

RKS-001 is `hot-kernel`. Record checked/unchecked rows/s, fixed validation and
allocation, stage versus finish cost, and its SLE fraction. The same 10% review
and two-case 20% completion thresholds apply.

FLN-001 supplies the four RHS rows semantically; TRM-001 classifies generated
states; SLE-001 owns stage scheduling and candidate commit.
