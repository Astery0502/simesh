# DAT-003 Contract: Native Selective Non-Staggered AMRVAC Block Reader

## Responsibility

DAT-003 implements STO-003 block-read semantics directly over selected
non-staggered AMRVAC v5 record bytes. It owns selected record preflight,
block/field duplicate suppression, byte-range choice, saved-ghost translation,
endian conversion, and x-fast-to-canonical copying. It defines no metadata/FST
meaning, selection planning, fd/path ownership, persistent cache, geometry,
periodicity, topology, halos, sampling, dataset lifecycle, or parallel policy.

## Stable Factory And Lifecycle

```text
make_amrvac_v5_block_reader(file_descriptor, index, forest_binding) -> BlockReader
```

`file_descriptor` is an exact nonnegative Python `int` naming the same open
regular file read by DAT-001. `index` is its unchanged `AMRVACV5Index` and
`forest_binding` is the unchanged DAT-002 result created from that index. The
factory requires exact source-file-identity provenance equality before exposing
canonical leaf IDs. The file is non-staggered. The caller owns and closes the
descriptor only after all reader calls finish, and guarantees the file contents
remain unchanged.

The factory compares current `fstat` identity with DAT-001 and returns a frozen
STO-003 reader of shape

```text
(leaf_count, field_count, Bx, By, Bz).
```

Its private frozen state retains the borrowed fd, byte order, shape/identity,
and one owned read-only `int64[L]` copy of block offsets. This array is exposed
through `BlockReader.memory_arrays`; no other ndarray, file object, mmap, path,
payload, or selection is retained. Position-independent reads never change the
fd cursor and independent callbacks may safely read the immutable file
concurrently.

Exact v5 metadata in another geometry or with periodic flags remains readable;
those are downstream numerical-support decisions. A staggered index is rejected
before reader creation because its complete record meaning is outside DAT-003.

## STO-003 Request

The returned callback implements:

```text
read_blocks_into(
    reader,
    source_valid_lower,
    source_valid_upper,
    block_ids,
    field_ids,
    destination,
    destination_lower,
) -> None
```

Source coordinates are relative to the logical interior `[0,B)`, not the saved
record including ghosts. `block_ids int64[S]` and `field_ids int64[F]` may be
empty, arbitrary, reordered, and repeated. Destination is writable native
C-contiguous `float64[S,F,dx,dy,dz]`; its selected translated box has the exact
source extent. Successful execution writes

```text
destination[slot,field_position,destination_lower + q] =
    file_block[block_ids[slot],field_ids[field_position],q]
```

for every point in the requested half-open box and preserves all other
destination cells bitwise. Inputs and fd position are unchanged; no caller view
is retained.

An empty slot axis, field axis, or zero-volume source box performs no `fstat`,
record-header read, or payload read after ordinary ndarray validation and
preserves the destination.

## Selected Record Preflight And Addressing

Before any destination mutation, group selector positions by unique block and
field ID. Physical processing uses ascending unique IDs; all duplicate output
positions are filled from the same bytes. Check current file identity, then
read all unique selected six-int32 ghost headers. Decode them in the index byte
order as

```text
(lo_x, lo_y, lo_z, hi_x, hi_y, hi_z).
```

Ghost extents are nonnegative and
`stored_shape = block_cell_counts + lower_ghost + upper_ghost` is positive and
representable. Let `C=product(stored_shape)`. The exact ordinary record end is

```text
block_offset + 24 + field_count*C*8.
```

It must equal the next block offset or, for the final leaf, the DAT-001 file
size. Every requested interior coordinate translated by `lower_ghost` must lie
inside the stored shape. All selected headers are validated before the first
payload read/write, so a selected record-format error preserves the complete
destination.

For stored coordinate `(x,y,z)` and source field `f`, the byte address is

```text
block_offset + 24 + 8 * (x + Nx*(y + Ny*(z + Nz*f))).
```

Disk x is fastest; canonical destination z is fastest.

## Physical Read Plan And Copy

For a complete interior with zero saved ghosts, sorted consecutive unique field
IDs form maximal runs. One `pread` obtains exactly `run_length*C*8` bytes and a
`(run,z,y,x)` endian-aware view is transposed/copied to all matching canonical
destination slots/field positions. No unrequested field lies inside a run.

For a partial box or nonzero saved ghosts, each unique `(block,field)` uses one
minimal contiguous disk envelope. With stored inclusive/exclusive box
`[x0,x1)`, `[y0,y1)`, `[z0,z1)`:

```text
first = x0 + Nx*(y0 + Ny*z0)
last  = (x1-1) + Nx*((y1-1) + Ny*(z1-1)) + 1
```

Read exactly `8*(last-first)` bytes, then expose the selected `(x,y,z)` values
through strides `(8,8*Nx,8*Nx*Ny)` and copy to canonical destinations. Bytes
between selected x-runs are envelope overread and are reported separately from
useful bytes. A broader span across unrequested fields is forbidden.

Call scratch is `O(S+F)` Python/index metadata plus at most one consecutive
full-field run or one single-field envelope bytes object/view and an equally
bounded endian-conversion temporary when NumPy requires one. It never holds a
chunk/full-file payload and no scratch survives the callback.

## Validation, Errors, And Atomicity

Factory scalar/index/type/lifecycle failures raise `TypeError` or `ValueError`;
staggered input raises `ValueError`; address/byte overflow raises
`OverflowError`; invalid/closed/replaced fd operations raise `OSError`.

Each callback validates every request-derived STO-001 ndarray type/dtype/rank/
shape, C-contiguity, output writability, region, selector, translated
destination bound, and nonoverlap condition before file access. After reading
all unique selected ghost headers, it validates every record-derived stored
shape, exact record end, source translation, envelope, field address, and byte
bound before the first payload read or destination mutation. Both classes of
ordinary failure preserve the destination. An OS error, short payload read,
detectable file change, or resource/allocation failure after payload execution
begins may leave earlier ascending unique block/field destinations updated;
DAT-003 does not claim an external transaction.

Short header/payload reads raise `OSError` identifying the offset and expected/
actual byte counts. A final identity check may report concurrent external
mutation after partial output. Content mutation that preserves all recorded
identity fields is a caller lifecycle violation.

## Exactness And Evidence

Successful payload values compare by `uint64` bits. Endian conversion is a raw
representation swap/copy with no floating-point arithmetic and preserves all
finite bits, `+0`, `-0`, both infinities, and signed quiet/signaling NaN payloads.
Discrete selectors,
regions, ghost translations, call grouping, addresses, and untouched cells
compare exactly against an independent raw-byte address reference and the
STO-001 array reader.

Focused evidence includes little/big-endian files, asymmetric per-record saved
ghosts, partial/translated boxes, reordered/repeated block and field selectors,
empty axes/boxes, malformed later selected records, alias/short-read/file-
identity failures, tdm fields versus current eager reading, WENO staggered
factory rejection, and synthetic refined native-versus-array RHE/RPS capacity
invariance. A temporary streamed non-staggered WENO regular-field bridge adds
real refined field values without claiming staggered support.

## Performance And Immediate Consumer

DAT-003 is `milestone-workflow`. Record metadata/open separately from cold and
warm transfer/RHE/RPS time; first useful result; header/payload `pread` calls;
requested, useful, envelope, physical, support, and output bytes; duplicate
suppression; managed offset/scratch bytes; page faults; RSS; and array/current
comparisons. The current eager reader is a full-domain comparator, not the
selected algorithm.

RHE-001 and RPS-001 consume the returned reader unchanged. The next local-field
and streamline slices determine whether mmap, owned fd lifecycle, eager record
metadata, asynchronous/parallel reads, wider field spans, or persistent payload
cache should reopen. DAT-003 itself remains a cache-free storage substitution.
