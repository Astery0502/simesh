# HAL-001 Contract: Non-Periodic Physical-Boundary Halos

## Responsibility

HAL-001 fills every allocated halo cell determined solely by non-periodic
physical faces. It composes field-specific boundary rules over canonical padded
payloads. It defines no sibling exchange, refinement, periodicity, geometry
arithmetic, field-name inference, 2D behavior, or allocation policy.

## Stable Operation

```text
fill_physical_halos(
    payload,
    interior_lower,
    interior_upper,
    block_ids,
    face_neighbor_ids,
    boundary_modes,
    normal_field_slots,
) -> None
```

- `payload` is caller-owned writable C-contiguous
  `float64[nslot,nfield,sx,sy,sz]` and is mutated in place.
- `[interior_lower,interior_upper)` is a borrowed C-contiguous `int64[3]`
  nonempty box contained in the spatial shape and valid on entry.
- `block_ids` is borrowed C-contiguous `int64[nslot]`; order and repeats are
  allowed.
- `face_neighbor_ids` is the borrowed TOP-001 `int64[N,6]` table; exact `-1`
  identifies a physical face.
- `boundary_modes` is borrowed C-contiguous `uint8[nfield,6]`, aligned to
  payload fields and TOP face order.
- `normal_field_slots` is borrowed C-contiguous `int64[3]`; entries are local
  payload field positions or `-1`.

Payload may not overlap metadata. Read-only inputs may overlap one another.
Nothing is retained; validation/fill allocate no slot-, field-, or payload-sized
scratch (fixed triplet metadata temporaries are permitted). Complete validation
precedes mutation, so an invalid call leaves payload unchanged.

## Boundary Modes

| Code | Name | Coordinate mapping | Value transform |
| ---: | --- | --- | --- |
| 0 | continuous | nearest interior | identity |
| 1 | symmetric | reflected interior | identity |
| 2 | antisymmetric | reflected interior | unary minus |
| 3 | no-inflow | nearest interior | conditional clip |

Names and name-to-field inference belong in adapters. If any field row uses
no-inflow on either face of axis `a`, `normal_field_slots[a]` must be a valid
field position. No-inflow clips only when the current row equals that position;
on other rows it is continuous, matching current numerical behavior.

For the designated normal field:

- lower face: strictly positive values become exact `+0.0`;
- upper face: strictly negative values become exact `+0.0`;
- zero, NaN, and allowed-sign values retain their representation.

## Layer And Corner Mapping

Let `L=interior_lower`, `U=interior_upper`, and layer `ell=1` be nearest the
interior.

| Face | Target | Continuous/no-inflow source | Symmetric/antisymmetric source |
| --- | --- | --- | --- |
| lower axis `a` | `L[a]-ell` | `L[a]` | `L[a]+ell-1` |
| upper axis `a` | `U[a]+ell-1` | `U[a]-1` | `U[a]-ell` |

For any reflected row on a face, that side's allocated halo width must not
exceed the interior extent on its axis. HAL-001 fills all allocated physical
layers; operator-required reach remains an executor concern.

For a target cell, every axis outside the interior must correspond to a physical
face for that slot. Each incident axis independently supplies its clamp or
reflection coordinate, so the source cell is always inside the valid interior.
Then value transforms apply in ascending axis order:

```text
value = Tz(Ty(Tx(interior_value))).
```

This makes edges/corners compositions rather than face ownership and explicitly
resolves noncommuting clipping/sign cases. For example, x-low no-inflow followed
by y-low antisymmetry may produce negative zero.

## Produced Validity

For slot `s` with global block ID `b`, its exact physical envelope is

```text
slot_lower[a] = 0     if face_neighbor_ids[b,2*a]   == -1 else L[a]
slot_upper[a] = S[a]  if face_neighbor_ids[b,2*a+1] == -1 else U[a].
```

Every cell in this envelope is defined. The interior is preserved bitwise, and
every cell outside the envelope is preserved bitwise. The exact common FND-001
valid box is the componentwise intersection of all slot envelopes; for zero
slots it is the interior. Callers may compute that fixed-size metadata or
conservatively continue advertising only the interior. HAL-002 consumes the
stronger per-slot envelope while completing sibling-dependent cells.

## Validation And Exactness

Validate exact dtypes, ranks, shapes, C-contiguity, payload writability,
interior bounds, block-ID ranges, mode codes, normal-slot ranges/requirements,
reflection depths, and forbidden overlap before mutation. TOP semantic validity
is an upstream precondition.

Type/dtype failures raise `TypeError`; invalid shape, layout, bounds, selector,
mode, normal metadata, reflection depth, or overlap raises `ValueError`.

Continuous and symmetric outputs are bitwise copies. Antisymmetric negation and
no-inflow clipping are exact binary64 operations. Current/reference comparisons
use `uint64` views, including signed-zero cases; no tolerance applies.

## Performance And Memory

The direct implementation visits allocated cells, skips the interior and
nonphysical combinations, and writes each produced halo cell once. It allocates
no scratch. Measure runtime, produced-cell throughput, fixed allocation, halo
width scaling, and mixed versus all-physical blocks before considering fused
HAL-001/HAL-002 sweeps.

## Immediate Composition

STO-001 loads the valid interior into padded workspaces. TOP-001 classifies
physical faces. HAL-002 fills remaining same-level cells and applies the
physical post-composition required at mixed physical/sibling edges.
