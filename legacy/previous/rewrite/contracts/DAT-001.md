# DAT-001 Contract: Safe AMRVAC v5 3D Snapshot Index

## Responsibility

DAT-001 decodes one AMRVAC version-five 3D file header, forest
stream, leaf tree rows, and block-offset table into a checked canonical metadata
index. It defines no FST reconstruction, topology, supported geometry/periodic
policy, exact block ghost layout, payload transfer, cache, fd ownership,
dataset lifecycle, or numerical behavior.

## Stable Operation And Result

```text
read_amrvac_v5_index(file_descriptor) -> AMRVACV5Index
```

`file_descriptor` is an exact nonnegative Python `int` naming an open regular
file. The caller owns it, keeps it open for the call, and closes it. DAT-001
uses position-independent reads and does not change the descriptor's current
offset.

The frozen result contains these scalars/tuples and owned native arrays:

```text
byte_order                         "<" or ">"
file_identity                     device, inode, size, mtime_ns, ctime_ns
offset_tree, offset_blocks
field_count, direction_count, dimension_count (=3)
declared_max_level, leaf_count, parent_count, iteration, time
domain_lower, domain_upper         float64[3]
domain_cell_counts                int64[3]
block_cell_counts                 int64[3]
periodic                          bool[3]
geometry, staggered
field_names, physics_type
parameter_values                  float64[nparameter]
parameter_names
snapshot_next, slice_next, collapse_next
forest_flags                      bool[K]
block_levels                      int64[L]
block_coordinates                 int64[L,3], canonical zero-based
block_offsets                     int64[L]
```

Here `K=L+parent_count`. On disk, tree coordinates are one-based; conversion to
zero-based belongs to DAT-001. Arrays are C-contiguous, own their storage, and
do not overlap. A caller mutation creates a new artifact lifecycle and requires
DAT-001/DAT-002 again before unchecked consumers use it. The result retains no
fd, path, mmap, memoryview, or input buffer.

## Exact v5 Byte Layout And Endian Detection

There is no file endian marker. Read the first four bytes and interpret them as
both little- and big-endian signed int32. Exactly one interpretation must equal
`5`; otherwise the file version/representation is unsupported. All remaining
int32, int64, and float64 values use that detected order.

The unaligned v5 header is, without padding:

```text
version int32
9 * int32: offset_tree, offset_blocks, nw, ndir, ndim, levmax,
           nleafs, nparents, iteration
time float64
xmin[ndim], xmax[ndim] float64
domain_nx[ndim], block_nx[ndim] int32
periodic[ndim] int32 logical
geometry[16]
staggered int32 logical
field_names[nw][16]
physics_type[16]
nparameter int32
parameters[nparameter] float64
parameter_names[nparameter][16]
snapshot_next, slice_next, collapse_next int32
```

Fixed strings strip trailing spaces and NUL bytes and decode as UTF-8 strictly.
Logical zero is false and every nonzero representation is true. The decoded
header cursor must equal `offset_tree` exactly.

At `offset_tree`, decode contiguously:

```text
forest_flags[K]           int32 logical
block_levels[L]           int32
block_coordinates[L,3]    int32, disk one-based
block_offsets[L]           int64
```

The resulting cursor must equal `offset_blocks` exactly. Tree coordinate rows
follow file leaf order. DAT-002, not DAT-001, proves that order against FST.

## Structural Validation

Before allocating size-dependent arrays, validate positive `nw`, `ndir`,
`ndim==3`, `levmax`, `L`, nonnegative parent count, `K` and all byte counts/
offsets in signed int64, and header/tree ranges inside the file. Domain and
block counts are positive, exactly divisible, and have representable root
volume. Bounds are finite and strictly increasing. Parameter count is
nonnegative and representable.

After decoding, exactly `L` forest flags are true and exactly `parent_count`
are false. Block levels lie in `[1,declared_max_level]`. One-based coordinates
are positive and lie inside `root_shape * 2**(level-1)` under checked int64
arithmetic. Block offsets are positive, strictly increasing, the first equals
`offset_blocks`, and every offset interval/file tail can contain at least

```text
24 + nw * product(block_cell_counts) * 8
```

bytes for the six ghost integers plus regular values with zero saved ghosts.
DAT-001 deliberately does not touch separated block-record pages or infer exact
saved ghost/staggered record size. DAT-003 preflights exact selected ordinary
records; staggered payload remains unsupported there.

Geometry and periodic flags are reported rather than used as storage-policy
gates. M1 numerical composition separately requires nonperiodic
`Cartesian_3D`. Staggered v5 metadata is valid DAT-001 input so the real WENO
forest remains usable evidence.

## Errors, Atomicity, And File Lifecycle

Wrong fd scalar type raises `TypeError`. Unsupported version/dimension, invalid
UTF-8, malformed values, inconsistent counts/offsets, or truncated metadata
raises `ValueError`; unrepresentable integer/byte arithmetic raises
`OverflowError`. Operating-system `fstat`/`pread` failures propagate as
`OSError`. No partial artifact is returned.

DAT-001 records `(device,inode,size,mtime_ns,ctime_ns)` before parsing and
requires the same identity after parsing. Concurrent replacement/mutation is an
external lifecycle failure. DAT-003 requires the same unchanged identity for
every nonempty transfer. The format has no checksum; content mutation that
preserves all recorded identity fields is a caller contract violation.

## Evidence And Performance

Every discrete value, string, array, byte order, and offset compares exactly.
Binary64 header/parameter values compare by `uint64` bits. Independent
little-/big-endian byte fixtures cover empty strings, logical representations,
opposite-endian IEEE values, count/offset overflow, short sections, wrong
versions, malformed coordinates, forest counts, and cursor preservation.

Real evidence compares tdm and WENO v5 metadata/tree arrays with current raw
parsing and upstream layout. WENO is accepted as staggered metadata but rejected
by DAT-003. DAT-001 is `cold/control`: runtime is `O(header bytes + K + L)`;
owned variable bytes are `K + 40*L + 8*nparameter` plus strings/fixed metadata.
It reads no block record header or payload page. Record metadata is not eagerly
cached: a cold probe of only 542,736 separated WENO ghost-header bytes took
3.297 seconds, which is incompatible with sparse time to first result.

## Immediate Composition

DAT-002 consumes the index to construct/prove canonical FST leaf identity.
DAT-003 consumes its file identity, byte order, shape, and offsets after that
lifecycle is established. M5 may add correct v3/v4 parsers behind a versioned
metadata boundary without changing FST or selected transfer semantics.
