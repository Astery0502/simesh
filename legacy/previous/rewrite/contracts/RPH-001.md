# RPH-001 Contract: Refined Relation Child Phases

## Responsibility

RPH-001 derives exact ratio-two child-column phase codes for accepted REL/RSL
records.  It defines no relation/action classification, identity mapping,
target/source box, requested reach, PBC narrowing, RST/PRL value, workspace,
payload mutation, backend, scheduling, periodicity, or 2D behavior.

## Stable Operation

```text
fill_refined_relation_phase_codes(
    selected_leaf_ids,
    node_levels,
    node_coords,
    leaf_node_ids,
    directions,
    relation_kinds,
    physical_masks,
    source_counts,
    source_slots,
    fine_phase_codes,
) -> None
```

`selected_leaf_ids` is borrowed read-only native-endian C-contiguous
`int64[S]`, unique and in `[0,L)`.  `node_levels`, `node_coords`, and
`leaf_node_ids` are borrowed FST-002 native-endian C-contiguous `int64[K]`,
`int64[K,3]`, and `int64[L]`; selected IDs map to valid node rows.  Full FST
conformance remains an upstream unchanged-artifact precondition.

`directions` is borrowed read-only C-contiguous `int64[D,3]`, with components
in `{-1,0,1}` and no center row.  Rows may be reordered/repeated/subsetted.

`relation_kinds`, `physical_masks`, and `source_counts` are borrowed read-only
C-contiguous `uint8[P,D]`; `source_slots` is borrowed read-only C-contiguous
`int64[P,D,4]`.  They are accepted REL/RSL rows: `P<=S`, primary row `p`
corresponds to selected slot `p`, active slots are in `[0,S)`, and inactive
slots are exact `-1`.

`fine_phase_codes` is caller-owned writable C-contiguous `uint8[P,D,4]`, does
not overlap any input, and is fully overwritten on success.  Nothing is
retained.

## Exact Phase Codes

For a selected leaf's FST node coordinate, define

```text
phase = (coord_x & 1) + 2*(coord_y & 1) + 4*(coord_z & 1)
```

in `[0,7]`.  Exact sentinel `255` means no ratio-two phase.

- PHYSICAL (`1`): count zero; all columns `255`.
- SAME (`3`): one active source at the primary level; all columns `255`.
- COARSER (`2`): one active source exactly one level below the primary; column
  zero is the primary node phase; columns one through three are `255`.
- FINER (`4`): every active source is exactly one level above the primary; each
  active column is that source node phase; inactive columns are `255`.

For COARSER, form reduced direction `r` by replacing every physically masked
axis with zero.  The unique coarse source coordinate must satisfy mathematical
integer identity

```text
source_coord = floor((primary_coord + r) / 2)
```

componentwise at the source level.  COARSER always emits primary parity.  It
does not require the primary phase to match every direction sign: one coarse
cell spans both fine phases on tangential axes, and the current all-axis send
gate is non-owned scheduling/deduplication policy.

Physical masks use only bits zero through two and may mark only nonzero full
direction axes.  Masked axes are neutral for FINER phase compatibility and
admit both bits.  On each unmasked nonzero direction axis, FINER direction `-1`
requires source phase bit one and direction `+1` requires bit zero.

Zero direction axes admit either bit.  A PHYSICAL record masks every nonzero
direction axis.  A nonphysical record retains at least one unmasked nonzero
axis.

For FINER, the exact active count is

```text
2 ** number_of_axes(direction==0 or physical_mask_bit_set)
```

and is one, two, or four.  Active phase codes are strictly increasing, matching
REL canonical child-column order.  Mixed physical FINER records preserve every
neutralized-axis candidate; later PBC rules may narrow them.

## Validation, Errors, And Atomicity

Validate selected/FST representations, directions, paired relation/RSL tensor
representations, and output representation/shape/writability first.  Then
validate `P<=S`, selected uniqueness/range and node access, direction/mask
values, kind/count/active-slot/trailing representation, relative levels, exact
count/order, and phase compatibility.  Validate output/input nonoverlap before
mutation.  Complete preflight precedes fill.

Wrong object/dtype raises `TypeError`.  Invalid rank, shape, layout,
writability, selected ID/node, duplicate, direction, mask, kind, count, slot,
sentinel, relative level, phase/order, or overlap raises `ValueError`.  Every
failure preserves the complete output.  Inputs may be read-only/overlapping and
are never mutated or retained.  Empty `P` or `D` is valid after ordinary
validation with exact output shape `[P,D,4]`.

Valid singleton-axis rewrite FST/REL inputs remain supported.  Only unsafe
current singleton physical-status table behavior is excluded from parity.

## Independent Evidence

The independent reference uses Python selected/FST indexing, integer parity,
and explicit level/direction compatibility without production helpers.  It uses
no hash, dense map, sort, or bitmap.  Evidence covers all kinds, directions,
masks, eight phases, counts one/two/four, canonical order, mixed candidates,
random balanced forests/WENO, safe current phase facts, singleton inputs,
RST/PRL consumer probes, and complete malformed/atomic cases.

RAC-001 remains absent because REL kind/mask already determines base action;
TGT-001 independently owns target boxes.

## Performance And Memory

Output is exactly

```text
P*D*4 = 4*P*D bytes
```

or `104*P` bytes at `D=26`.  For `A` active sources, complete checked work is
`O(S^2 + D + P*D + A)` because directions are validated independently, selected
uniqueness is contract-owned, and no hash or scratch is used.  Upstream-validated
unchecked fill is `O(P*D + A)`, with no payload or size-dependent scratch.

Measure records/s, active phases/s, selected/primary/direction/depth/mask/count
scaling, fixed allocation, exact bytes, reference/current evidence, WENO bounded
capacities, and native materialize-once reuse versus repeated native derivation.
Exact codes/sentinels are hard gates; standard >10% investigation and reproduced
>20% blocking rules apply.

## Immediate Composition

Accepted FST/REL/RSL facts produce RPH.  A later PBC-aware workspace/value
application combines RPH with TGT boxes, source/workspace geometry, and
RST/PRL.  RPH consumes no box, payload, or numerical value.
