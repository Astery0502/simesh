# SAM-004 Contract: Refined Zero-Order Point-Group Sampling

## Responsibility

SAM-004 copies the canonical owner-level source cell for explicit groups of
refined Cartesian points. It owns cell-face selection and exact value copy, but
not leaf location, group planning, field selection, storage/cache policy,
halos, exterior fill, scheduling, or streamline behavior.

## Stable Operation

```text
sample_refined_zero_order_point_groups(
    payload,
    payload_valid_lower,
    payload_valid_upper,
    interior_lower,
    interior_upper,
    slot_leaf_ids,
    domain_lower,
    domain_upper,
    domain_cell_counts,
    block_cell_counts,
    node_levels,
    node_coords,
    leaf_node_ids,
    points,
    point_indices,
    slot_point_offsets,
    point_values,
) -> None
```

- `payload` is borrowed read-only native C-contiguous
  `float64[S,F,sx,sy,sz]`.
- Valid/interior boxes are borrowed C-contiguous `int64[3]`, half-open,
  contained in the payload, and the interior extent equals
  `block_cell_counts`. Zero-order reach is zero; cells outside the interior are
  ignored.
- `slot_leaf_ids` is borrowed C-contiguous `int64[S]`, in arbitrary order with
  repeats allowed, and names the canonical leaf stored in each payload slot.
- Domain/count and node/leaf arrays belong to the same unchanged FST-002 and
  whole-leaf GEO-002 lifecycle as LOC-001. `node_levels`, `node_coords`, and
  `leaf_node_ids` have their canonical C-contiguous `int64` representations.
- `points` is borrowed C-contiguous `float64[P,3]`.
- `point_indices` is borrowed C-contiguous `int64[Q]` and
  `slot_point_offsets` is borrowed C-contiguous `int64[S+1]`. Offsets start at
  zero, end at `Q`, and are nondecreasing. Slot `s` owns the indexed points in
  `point_indices[offsets[s]:offsets[s+1]]`.
- `point_values` is caller-owned writable C-contiguous `float64[P,F]`.

Every selected point index must be in range, finite, inside LOC-001's half-open
domain, and canonically owned by the corresponding slot leaf. Repeated point
indices are allowed. Slots and their group entries execute in ascending order,
so the last selected occurrence overwrites earlier ones. A point cannot
validate under groups naming distinct canonical leaf owners. Empty slots,
points, selections, and field axes are accepted.

Inputs may overlap one another when their simultaneous values satisfy the
contract. The output may not overlap any input. All validation completes before
mutation. Success writes every selected point/field cell, preserves every
unselected result row bitwise, changes no input, and retains nothing.

## Canonical Owner-Level Cell

For slot leaf level `ell`, coordinate `c`, and axis `a`, construct the
level-specific spacing, global cell count, and canonical faces exactly as
LOC-001/GEO-002. Let

```text
g0 = c[a] * block_cell_counts[a]
g  = max { k in [g0, g0 + block_cell_counts[a] - 1]
          : face(k) <= point[a] }
local[a] = g - g0
```

The implementation may find the owner on the complete level lattice and
subtract `g0`, but it must verify the same interval. It may use a quotient only
as a candidate bracket; a naked `floor((point-leaf_lower)/h)` is not equivalent
on all accepted binary64 geometry. Exact equality with any representable cell
face chooses the greatest face index, including coincident faces. At a leaf's
internal lower boundary this reduces to local cell zero; exact global upper is
not an input because LOC-001 classifies it as exterior.

For every field `f`, the exact write is

```text
point_values[point_index,f] =
    payload[slot,f,interior_lower + local].
```

No floating-point arithmetic is performed on payload values, so all binary64
patterns, including signed zero, NaN payloads, and infinities, are preserved.

## Validation, Errors, And Atomicity

The checked boundary validates exact ndarray type/dtype/rank/shape/
C-contiguity, output writability/nonoverlap, valid/interior boxes, valid leaf
IDs, group offsets and point indices, domain/count integer
and numerical representability, safe leaf-node access, canonical leaf ownership,
and every local cell index before output mutation. Type/dtype failures raise
`TypeError`; invalid layouts, mappings, points, ownership, or boxes raise
`ValueError`; integer volume/index overflow raises `OverflowError`.

FST/GEO semantic corruption after their established lifecycle is a caller
contract violation. RPS-001 preflights the complete group map before its first
nonempty reader call and uses only the unchecked fill in execution.

## Exactness And Evidence

Point indices, leaf/cell owners, and copied values compare exactly; values use
`uint64` views. The independent scalar reference scans canonical owner-level
faces and indexes one cell without production hierarchy or candidate logic.
Coverage includes every local cell/face, refined leaf and coarse/fine face/
edge/corner ties, large origins and coincident representable cell faces,
repeated coordinates/indices/fields, empty groups, unselected-row preservation,
and ordinary late errors.

On an all-level-one forest, points constructed with SAM-002's exact output-
center operation order and grouped by LOC-001 must be bitwise identical to the
retained fused SAM-002 wrapper for native, upsampled, downsampled, and subdomain
requests. Exact global-upper and finite exterior behavior is new point-query
classification and is not compared with SAM-002, whose centers are strictly
inside.

## Performance And Memory

The compiled kernel computes slot geometry once per slot and one three-axis
cell owner per selected point, then copies `F` contiguous logical field values.
Its cost is `O(S + Q*(log B + F))`, normally using verified constant-time cell
candidates with binary-search fallback. It allocates no payload-, point-,
field-, group-, or output-sized scratch.

SAM-004 is `hot-kernel`. Measure single/batch point and field-value throughput,
owner reuse, fields, block extent, depth/geometry, fixed allocation, retained
SAM-002 ratio, and the direct-reader RPS-001 composition. Shared inline
extraction must not materially regress SAM-002 under PERFORMANCE.md.

## Immediate Composition

LOC-001 plus an explicit stable owner-group plan supplies the slot mapping.
Resident canonical blocks are the simple comparator. RPS-001 reads each bounded
unique-owner batch through STO-003 and calls SAM-004 without requesting halo
support.
