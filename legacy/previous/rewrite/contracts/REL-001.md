# REL-001 Contract: Balanced Refined Direction Relations

## Responsibility

REL-001 materializes the complete balanced, non-periodic Cartesian 3D relation
fact for selected canonical leaf IDs and explicit noncenter directions.  It
defines the physical-component mask and reduced direction, relation kind, and
the exact touching source leaf set.  It defines no forest conformance, balance
policy, global cache, geometry, PBC coordinate/value transform or multi-axis
transform order, transfer phase/weights/values, support union/capacity,
selected-slot mapping, payload, storage, scheduling, or periodicity.

## Stable Operation

```text
fill_balanced_refined_relations(
    root_shape,
    coord_to_rank,
    root_node_ids,
    node_levels,
    node_coords,
    child_node_ids,
    node_leaf_ids,
    leaf_node_ids,
    leaf_ids,
    directions,
    relation_kinds,
    physical_masks,
    source_counts,
    source_leaf_ids,
) -> None
```

Let `P=len(leaf_ids)` and `D=len(directions)`.

- The first eight arrays have the exact borrowed read-only C-contiguous
  `int64` representations used by TOP-002 and belong to one unchanged FST-002
  and BAL-001 lifecycle.
- `leaf_ids` is borrowed read-only C-contiguous `int64[P]`; repeated,
  arbitrarily ordered, and empty selections are allowed.
- `directions` is one shared borrowed read-only C-contiguous `int64[D,3]`.
  Every row contains only `-1`, `0`, and `+1` and is not center.  Rows may be
  repeated, reordered, or empty.  The canonical full set is the 26 noncenter
  rows in x-fast cube-column order; face-only consumers may pass six rows.
- `relation_kinds`, `physical_masks`, and `source_counts` are caller-owned
  writable C-contiguous `uint8[P,D]`.
- `source_leaf_ids` is caller-owned writable C-contiguous `int64[P,D,4]`.

Outputs may not overlap any input or one another.  All shapes, selectors,
directions, writability, and overlap are validated before output mutation.
Successful execution overwrites every output element, changes no input, and
retains nothing.  An allocating `balanced_refined_relations(...)` helper
returns the same four arrays.

## Physical Reduction

For selected source node level `ell`, coordinate `c`, and full direction `d`,
the source-level logical extent is

```text
extent = root_shape * 2**(ell-1).
```

Physical mask bit `a` is set exactly when component `d[a]` is nonzero and
`c[a]+d[a]` lies outside `[0,extent[a])`.  Bits zero, one, and two represent x,
y, and z.  Bits three through seven are zero.  Define reduced direction `r` by
replacing every physical component with zero.

If `r` is center, the record is pure physical.  Otherwise exact TOP-002 lookup
with `r` is in-domain.  Mixed records preserve both their nonzero physical mask
and their in-domain relation/source; unlike current raw connectivity, one
physical component does not erase the others.

## Kinds And Sources

Kind codes match the established current semantic classes:

| Value | Name | Exact meaning |
| ---: | --- | --- |
| 1 | `PHYSICAL` | every nonzero direction component is physical |
| 2 | `COARSER` | reduced contact is one leaf one level coarser |
| 3 | `SAME` | reduced contact is one leaf at the source level |
| 4 | `FINER` | reduced contact is an internal node at the source level whose touching children are leaves |

FST-002 and BAL-001 are lifecycle preconditions rather than repeated work, so
all nonphysical classifications and immediate fine children already satisfy
these exact level relations.

- `PHYSICAL` has source count zero and four `-1` source IDs.
- `COARSER` and `SAME` have source count one, the target's canonical leaf ID in
  source column zero, and `-1` in columns one through three.
- `FINER` filters target child columns `0..7` in increasing
  `xbit+2*ybit+4*zbit` order.  For each axis, reduced direction negative admits
  child bit one, positive admits bit zero, and zero admits both.  Every selected
  child contributes its canonical leaf ID.  Count is one, two, or four for a
  reduced corner, edge, or face contact; unused trailing columns are `-1`.

Physical-neutralized axes therefore admit both child bits.  The source list is
the complete topological contact region independent of halo width or boundary
mode.  A later transfer plan may select a narrower cell/child phase after
combining access reach and physical value rules; REL-001 does not make that
independently variable decision.

## Lifecycle, Validation, And Errors

REL-001 validates exact ndarray type/dtype/rank/shape/C-contiguity, positive
representable root volume, selected leaf ranges, direction codes, output
writability, and all overlap before unchecked traversal.  It does not repeat
recursive FST conformance or global balance.

Wrong types/dtypes raise `TypeError`; invalid shapes, layouts, selectors,
directions, outputs, or overlap raise `ValueError`; root-volume overflow raises
`OverflowError`.  All ordinary failures preserve every output.  Semantic
artifact corruption after FST-002/BAL-001 is a caller contract violation.  Any
mutation begins a new lifecycle and requires both validations before REL-001.

## Independent Evidence

The independent reference lifts every leaf to a common maximum-level integer
box.  It detects physical components, reduces the direction, and selects every
leaf whose box touches on each reduced-nonzero axis and has positive overlap on
each reduced-zero axis.  It does not call TOP-002, use MOR maps, or follow child
pointers.  Source IDs are sorted by derived canonical child column.

Evidence includes all kinds; all 26 directions and fine child phases; pure and
mixed physical masks; faces/edges/corners; singleton/nonsymmetric roots and
root crossings; randomized balanced forests; reciprocity; repeated/reordered/
empty selections; maximum level 63; atomic validation errors; level-1 HPL
reduction; current comparison; and representative real refined metadata.
Unmasked and pure-physical supported records compare directly with current;
mixed physical/source records intentionally preserve information current loses.

## Performance And Memory

Production fuses TOP-002 lookup, kind classification, and child expansion and
uses no target-query array or selection-sized scratch.  Complexity is
`O(P*D*max_level)` worst-case.  Caller output is exactly `35*P*D` bytes.
Measure records/s, emitted source IDs/s, validation/fill/allocation, fixed
allocation, selection/depth/kind/mask/direction scaling, bounded traversal,
FST-to-BAL-to-REL lifecycle, current comparison, and face/all-direction cache
alternatives.

Optional TOP-003 is not a dependency.  Its six faces cover only a subset of
REL queries and cost `54*L` retained bytes plus construction.  It remains
deferred unless repeated composed face use demonstrates material benefit after
including cache build, lookup, and memory.

## Immediate Composition

FST-002 and BAL-001 establish the admitted artifact lifecycle, while TOP-002
supplies raw target semantics.  STO-004 consumes global source leaf IDs to
derive support under a separate union/order/capacity policy.  Restriction,
prolongation, physical transforms, and refined halo execution consume relation
kinds/masks/sources through their own numerical and execution contracts.
