## Incremental STO-002 Refinement

The STO-002 Yellow trigger is active before refined support planning.  WSP-001
extracts only canonical payload-plus-ID workspace accounting; primary traversal,
direct-face closure, full-halo closure, support ordering, and progress policy
remain unchanged for later incremental boundaries.

The implementation moved the existing pure arithmetic intact to
`simesh_rewrite.workspace`.  Package-root exports now use the canonical owner,
while both `simesh_rewrite.chunking` entrypoints are compatibility wrappers.
Validation order, result bits, error types, and messages are frozen.  The STO
benchmark's duplicated inverse calculation now calls WSP-001.  INT-001's
payload-plus-output-plus-state equation remains explicitly separate.

Thirty-two parameter-expanded WSP tests, all 12 retained STO-002 tests, and all
348 accumulated rewrite tests pass.  Coverage includes exact formula and
linearity; inverse maximality and block clamp; zero inputs with mandatory
descriptor validation; Python and NumPy scalar kinds; exact multi-invalid
precedence/messages; shape dtype/rank/layout/positivity; read-only inputs; every
signed-int64 overflow stage; actual NumPy allocation equality; 250 randomized
canonical/wrapper/package/reference cases; old/new error conformance; and the
separate INT formula.

An independent arbitrary-integer reference agrees with 10,000 additional
randomized valid cases and continues beyond signed int64 where production

## Exact Composition

For two fields and a `16^3` workspace under a 2 MiB budget, WSP returns 31
slots.  The allocated payload plus ID vector is exactly 2,031,864 bytes, equal
to the formula and below the 2,097,152-byte budget.  The mapped payload remains
134,217,728 bytes and outside the managed count.

The retained STO composition still reports exact capacity/bytes and completes
the warm mapped traversal in 22.31 ms at 6.02 GB/s.  Its planner chunk counts,
amplification, and utilization are unchanged; those measurements remain owned
by later traversal/closure capabilities rather than WSP.

## Fixed-Cost Measurement

Final Apple arm64 measurements use 10,000 calls per sample and 15 repetitions:

| Operation | Time/call |
| --- | ---: |
| canonical forward bytes | 2.60 us |
| compatibility forward bytes | 2.62 us |
| canonical inverse capacity | 2.75 us |
| compatibility inverse capacity | 2.82 us |

The pre-extraction baseline was 2.60 us forward and 2.70 us inverse.  Wrapper
overhead is immaterial at this once-per-allocation boundary.  One forward plus
inverse pair retains zero traced bytes and has a fixed 1,053-byte traced peak.

WSP is fixed-rank integer arithmetic, so payload throughput, parallel scaling,
and RSS are not isolated optimization gates.  Exact actual-array composition
and preserved wrapper behavior are the meaningful result.  No further variant
can improve the semantic/runtime trade-off without adding the generic workspace
machinery deliberately excluded from this capability.
