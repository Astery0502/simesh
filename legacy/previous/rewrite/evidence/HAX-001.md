# HAX-001 Evidence

## Correctness, Substitution, And HAL-002 Resolution

HAX-001 completes the incremental decomposition of the Red HAL-002 aggregate.
It owns only value application over caller-supplied HPL relations and PBC
rules; it receives no topology or global block IDs.  HAL-002 remains the faster
fused compatibility path over the same separately frozen semantics.

Thirteen focused tests and all 202 accumulated rewrite tests pass.  HAX agrees
bitwise with an independent direct-cell plan consumer and fused HAL-002 on full
and bounded closures, reordered selected slots, asymmetric halos, every
boundary mode, normal-field clipping, mixed physical/sibling faces/edges/
corners, signed zero, infinities, and NaN payloads.  Read-only plans are
accepted.  Primary interiors, pure HAL-001 cells, and every support slot are
preserved exactly.

Validation covers source ranges, mask bits/direction alignment, center/pure
physical structure, source/mask shape, modes, normal fields, zero primary and
zero field calls, depth, aliasing, and payload writability before mutation.  A
separate test deliberately changes one source to another range-safe slot: HAX
accepts the structurally safe input and produces a different result, explicitly
freezing exact source identity as the HPL semantic precondition rather than
silently rebuilding topology.

The completed boundaries are now independently replaceable:

- HPL-001 owns relation/source-slot planning;
- PBC-001 owns one physical face/mode's coordinate and value meaning;
- HAX-001 owns planned same-level value application;
- HAL-002 is retained as a measured fused implementation and compatibility
  wrapper.

HAL-002 is therefore reclassified from Red to **Fused**.  No current consumer
must migrate to a slower composition merely for conceptual purity; new refined
work builds on the explicit boundaries and never adds modes to HAL-002.

## Runtime, Memory, And Strategy Choice

The retained benchmark uses the established `(12,10,8)` topology, `8^3`
interiors, capacities 64/256, one/four fields, halo widths one/two/four, and 21
repetitions.  All 12 explicit and fused outputs are bitwise equal.

| Capacity/fields/halo | Primary / selected | Fused | HAX only | Checked HPL+HAX / fused | Explicit composed / fused | Plan bytes |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| `64/1/1` | 6 / 60 | 88.6 us | 37.2 us | 0.54x | 0.89x | 1,458 |
| `64/4/4` | 6 / 60 | 0.437 ms | 0.441 ms | 1.02x | 1.00x | 1,458 |
| `256/1/4` | 90 / 255 | 1.428 ms | 1.597 ms | 1.28x | 1.12x | 21,870 |
| `256/4/4` | 90 / 255 | 5.178 ms | 6.623 ms | 1.31x | 1.10x | 21,870 |

Across all cases, total checked HPL+HAX is 0.49--1.31x fused, below the 1.35x
alternative-strategy gate.  Gather+HAL-001+plan+HAX composition is
0.89--1.12x the fused composition.  The explicit path can be faster for small
chunks because its precomputed plan removes repeated topology/slot work, while
large broad halos favor HAL-002's tighter one-pass cell logic.

HAX retains zero traced bytes and has the same 1,584-byte fixed traced peak as
HAL-002.  Caller-owned plan bytes are exactly `243*P` and remain external to
HAX; an executor retaining them must budget them.  The measured Pareto choice
is to keep both strategies: explicit HPL/PBC/HAX for substitution and future
composition, fused HAL-002 for the current fast M0 path.

