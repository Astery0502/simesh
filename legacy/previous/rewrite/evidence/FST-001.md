# FST-001 Evidence

## Correctness And Conformance

Eleven focused tests and all 174 accumulated rewrite tests pass.  The compiled
flat reconstruction agrees exactly with an independent recursive Python
reference for shallow, nonsymmetric-root, mixed-depth, and depth-limit cases.
Tests freeze stream-position node IDs, dense preorder leaf IDs, MOR-ordered
roots, `x + 2*y + 4*z` child order, levels, logical coordinates, reciprocal
parent/child relations, node/leaf inverses, complete output overwrite, and
finest-level domain tiling.

The nested synthetic comparison agrees with the current `AMRForest` flag
roundtrip, leaf/parent counts, maximum level, and recovered root node offsets.
Malformed truncation and trailing nodes, corrupted MOR maps, wrong layouts,
read-only or overlapping outputs, and refined logical-grid overflow all fail
before any caller output changes.  Read-only inputs are accepted and
preserved.  Independent review found no remaining ordering, pointer-safety,
atomicity, memory-formula, or immediate-consumer defect; it confirmed that
two-to-one balance belongs to refined topology rather than FST-001.

The representative deep metadata check used the available real Cartesian 3D
snapshot `data/weno509_sub_0000.dat`.  Its header is staggered, so this is
forest/tree evidence only and does not claim staggered payload support.  The
snapshot has root shape `(2,2,1)`, 25,844 nodes, 22,614 leaves, 3,230 parents,
and maximum level six.  Reconstructed leaf levels equal stored `block_lvls`
exactly, reconstructed coordinates plus one equal stored AMRVAC `block_ixs`
exactly, and root node IDs are `(0,6433,12890,19355)`.  Current forest
serialization reproduces every input flag.

## Runtime, Scaling, And Memory

Final measurements ran on Apple arm64 with macOS 26.5.2, Python 3.11.14,
NumPy 2.4.4, and Cython 3.2.4.  Each synthetic result uses 15 repetitions of
the validated caller-owned fill.  The workload is 32 roots in a `(4,4,2)`
grid, with every node refined through the stated number of internal levels.

| Max level | Nodes | Leaves | Median fill | Mnode/s | Output bytes |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 2 | 288 | 256 | 21.7 us | 13.3 | 34,560 |
| 3 | 2,336 | 2,048 | 36.3 us | 64.3 | 278,272 |
| 4 | 18,720 | 16,384 | 167.4 us | 111.8 | 2,227,968 |
| 5 | 149,792 | 131,072 | 1.341 ms | 111.7 | 17,825,536 |

Throughput stabilizes near 112 million nodes/s once fixed validation and alias
checks are amortized.  Independent-reference allocation takes 0.331 ms for
288 nodes, 4.85 ms for 2,336 nodes, and 120.6 ms for 18,720 nodes; it is a
semantic comparator rather than a production variant.  The compiled path is
linear and no alternate representation was credible enough to justify losing
direct child and leaf maps needed by refined topology.

Measured output bytes equal `112*K + 8*L + 8*R` for every profile.  Repeated
fill retains zero bytes at useful sizes under `tracemalloc` and has a fixed
1,928--1,992-byte traced peak from Python validation/view bookkeeping.  The C
traversals allocate no heap or per-node scratch and use at most the
representable refinement depth on the C stack.

On the real 25,844-node tree, 31 allocating rewrite repetitions have a
0.302-ms median and produce exactly 3,075,472 output bytes.  Five current
`AMRForest` constructions have a 17.88-ms median.  The latter eagerly builds
27-direction connectivity in addition to pointer forest reconstruction, so
the roughly 59x ratio is descriptive and is not used as a direct performance
gate.  TOP-002 will provide the fair immediate-composition comparison.

