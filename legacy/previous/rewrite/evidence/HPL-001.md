# HPL-001 Evidence

## Decomposition And Correctness

HPL-001 is the first incremental HAL-002 Red refinement.  It owns only the
mapping from a primary's 27 full outside directions to selected source slots
and physical-axis masks.  Cell coordinates, fields, boundary modes, values,
payload mutation, capacity, and scheduling remain outside the plan.
Independent review agreed that all five decomposition questions pass and
required full target-direction columns, including physical axes.

Eight focused tests and all 182 accumulated rewrite tests pass.  The compiled
planner agrees exactly with an independent Python walk across 100 randomized
root shapes, selected-slot permutations, and primary prefixes.  Golden cases
freeze center, pure physical, sibling, mixed physical/sibling, and three-axis
directions.  Singleton axes, STO-002 bounded closure, zero primaries, shuffled
slots, exact full overwrite, output/input aliasing, duplicate/range/layout
errors, missing closure, and invalid face ranges are covered atomically.

An independent direct-cell consumer uses only the HPL arrays, interior bounds,
and explicit boundary metadata.  Its complete payload is bitwise equal to the
retained optimized `fill_same_level_halos(...)` path for asymmetric halos,
three fields, reordered blocks, every boundary mode, normal-field clipping,
and mixed physical/sibling edges and corners.  This proves plan sufficiency
without making value semantics part of HPL-001.

## Runtime, Allocation, And Retained Variant

Final Apple arm64 measurements use the `(12,10,8)` root grid and 31 planner
repetitions.  The selected IDs come from STO-002 full-halo chunks.

| Capacity | Primary / selected | Directions | Median | Mdirection/s | Output bytes | Python speedup |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 27 | 1 / 27 | 27 | 3.67 us | 7.37 | 243 | 6.13x |
| 64 | 6 / 60 | 162 | 8.42 us | 19.25 | 1,458 | 11.11x |
| 128 | 22 / 124 | 594 | 36.63 us | 16.22 | 5,346 | 9.50x |
| 256 | 90 / 255 | 2,430 | 244.46 us | 9.94 | 21,870 | 5.81x |

Every output size equals `243*primary_count`.  Repeated caller-buffered fill
retains zero traced bytes and has a fixed 832-byte traced peak.  Any future
executor retaining these public arrays must count them in its managed budget;
the existing HAL-002 wrapper does not retain or allocate them.

An independently reviewed first boundary scanned all `6*N` topology entries on
every checked call.  Fixed `P=1,S=27` measurements grew from 5.17 us at `8^3`
blocks to 91.2 us at `32^3`, an unacceptable `O(chunks*N)` composition.  The
retained boundary range-checks only face relations actually traversed by the
selected plan.  The same fixed-primary profile is 3.50 us at each of `8^3`,
`16^3`, and `32^3`; unrelated topology size no longer affects bounded plan
cost.

A production experiment replaced HAL-002's sibling-only fixed lookup with the
full-direction plan inside the cell loop.  It remained bitwise correct, but the
extra mask-dependent axis pass materially regressed multiple broad-halo
kernels: capacity-256/one-field/halo-four rose from 1.418 ms to 1.761 ms
(24.2%), and capacity-256/four-field/halo-four rose from 5.174 ms to 6.342 ms
(22.6%).  The latter composed path rose by 7.9%.  The small named control stayed
within noise.  Per the declared gate, that variant was rejected.

After retaining the original optimized loop, the same small control is
85.2 us kernel / 0.305 ms composed and the heavy case is 5.198 ms kernel /
14.491 ms composed, matching the frozen baseline within noise.  HPL remains an
additive semantic/planning boundary and HAL-002 remains the fast aggregate
comparator.  HAX-001 now provides the explicit production plan-consuming
transfer boundary and preserves this plan contract unchanged.
