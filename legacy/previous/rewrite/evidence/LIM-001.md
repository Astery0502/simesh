# LIM-001 Evidence

## Boundary And Correctness

LIM-001 owns only the exact current scalar three-point limited-slope rule.  It
owns separate one-sided differences, centered-average operation order,
comparison-based sign/minimum branches, clipping, positive-zero fallback, and
scalar validation.  Axis/index/reach, eta, reconstruction, regions, slope
storage/cache, workspace, relations, payload mutation, and execution remain
outside the capability.  The five-question result is Green, and the scalar-only
contract passed independent review before implementation.

The production entry point validates exact Python `float`/NumPy `float64`
inputs; PRL can later call the shared `inline noexcept nogil` rule without a
Python callback or slope array.  The independent reference uses explicit
NumPy-scalar subtractions, addition, multiplication, comparisons, and branches,
not generic sign/minimum/minmod helpers.

Twenty-seven focused tests cover positive/negative monotone branches and ties;
plateaus, extrema, one-sided zero, and large-offset rounding; centered-sum
overflow with finite clipping; all eight signed-zero triples; smallest signed
subnormals; signed quiet/signaling NaN payloads in every position; infinity
combinations; 10,000 random finite triples; exact scalar-type precedence and
return type; and RST-produced constant, affine, step, and quadratic profiles.
Every zero result is exact positive zero, and every production/reference result
matches bitwise or by the contracted IEEE class.

Independent implementation review approved the generated inline arithmetic,
validation/IEEE behavior, reference independence, scalar-only composition, and
performance boundary after one branch-count label was corrected.  Final runs
pass 27 focused tests, 35 RST/LIM integration tests, and all 500 accumulated
rewrite tests.

## Scalar Boundary Measurement

The fixed one-million-call workload cycles equal counts of positive/negative
monotone, extremum, plateau, NaN, infinity, centered-overflow, and subnormal
cases.  Validated, unchecked, and manual-reference loops rotate timing order and
write separate complete 8,000,000-byte result arrays.  The full arrays match
bitwise before and after timing.

| Path | Runtime s | Million calls/s |
| --- | ---: | ---: |
| Validated public scalar | 0.396 | 2.525 |
| Unchecked Cython scalar | 0.183 | 5.471 |
| Manual scalar reference | 1.514 | 0.660 |

The validated wrapper is 3.8x faster than the manual reference but 2.16x the
unchecked Python/Cython adapter because three exact-type checks dominate this
tiny scalar call.  This is deliberately descriptive: production PRL will call
the allocation-free inline rule inside its loop, so optimizing or weakening the
public scalar boundary cannot improve the composed hot path.  One validated
call retains zero traced bytes and peaks at 48 bytes for its ordinary scalar
return.

The centered-slope decision takes 625,000 positive, 125,000 negative, and
250,000 fallback branches.  The positive branch includes the extremum case
that later clamps to zero.  Output classes are 375,000 positive finite, 125,000
negative finite, 125,000 positive infinity, and 375,000 positive zero; there
are no negative zeros, negative infinities, or NaNs.

## Immediate Composition And Stop Point

RST produces one canonical four-field coarse profile with explicit triples
`[5,5,5]`, `[1,3,5]`, `[0,0,10]`, and `[1.25,9.25,25.25]`.  Validated,
unchecked, and reference LIM results are bitwise-identical slopes `[0,2,0,8]`.
The test also uses explicit `eta=+/-0.25` scalar reconstruction only as
non-stable consumer evidence; PRL retains all indexing/reach/eta/summation and
output decisions.

Current `_limited_slope` is internal and not callable independently, so exact
source arithmetic and aggregate RST/profile behavior are the present current
evidence.  PRL will provide the meaningful generated-code comparison with
complete current prolongation outputs and inline-versus-cache throughput.

The scalar rule has no credible numerical alternative after exactness, and an
array slope kernel would introduce independently variable materialization,
axis, region, and cache policy without a demonstrated benefit.  Optimization
therefore stops at the shared inline rule; the normal >10%/>20% gates resume on
the composed PRL path.
