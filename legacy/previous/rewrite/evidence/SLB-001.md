# SLB-001 Evidence

## Boundary And Correctness

The proposed combined RSG-001 boundary failed the five-question gate before
implementation.  Same-level affine translation, FINER restriction placement,
COARSER workspace placement/reach, and physical widening have independently
variable inputs, outputs, consumers, measurements, and reasons to change.
SLB-001 is the extracted Green function and owns only exact equal-level source
translation `S = U - r*B` for explicit target rows and reduced nonphysical
directions.  REL/action/mask/slot, reach, refinement, PBC, payload, storage,
scheduling, and dimensional policy remain separate.

The independent Python-integer reference and Cython fill agree for every
direction; asymmetric, partial, and zero widths; repeated/reordered rows;
empty row sets; singleton, empty, and near-`int64` interior axes; read-only and
overlapping inputs; and all representation, box, direction, writable-output,
and alias failures.  Complete direction validation precedes target semantics,
and every failure preserves both outputs.

Canonical current `AMRForest`/`AMRMesh` behavior matches all 768 cells in the
26 unmasked same-level source slices of the central leaf in a `3x3x3` forest.
TGT -> SLB -> FND composition copies 26 disjoint target boxes from one
two-field source slot exactly while preserving the interior and all cells
outside the targets.  Degenerate axes use independent rewrite/reference
evidence because they are outside the safe current parity scope.

Independent stable-contract and implementation reviews approved the amended
formal side rules, reachable error set, two-pass validation precedence,
near-limit arithmetic, alias safety, current evidence, and benchmark.  Final
runs pass 21 focused tests, 61 immediate FND/TGT integration tests, and all 591
accumulated rewrite tests.

## Kernel, Scaling, And Memory

The standard asymmetric canonical-26 case has 3,765 target cells per field and
writes exact `48*26 = 1,248` bytes:

| Path | Runtime us | Million rows/s |
| --- | ---: | ---: |
| Checked | 55.500 | 0.468 |
| Unchecked | 1.000 | 26.000 |
| Allocating Python reference | 34.291 | 0.758 |

The reference establishes semantics but omits the checked boundary's complete
representation, direction, side, containment, and alias preflight.  The
allocation-free unchecked kernel is the hot-loop surface.  The checked call
retains zero traced bytes and peaks at 1,360 bytes; the same exact peak holds
for `R=0/1/6/26/52`, while caller-owned output remains exactly `48*R` bytes.

`R=0/1/6/26/52` checked runtimes are
5.208/7.125/17.083/55.500/104.375 us and unchecked runtimes are
0.833/0.833/0.833/1.000/1.041 us.  Zero-width, unit-face, full-width, reversed,
singleton, and empty-axis cases remain exactly equal to the reference.  Width
does not affect the affine kernel cost; row count governs work.

## Reuse, Current Comparison, And Immediate Consumer

One unchecked materialization takes 7.459 us.  One materialization plus
100,000 native complete-array copies takes 36.837 ms versus 77.109 ms for
100,000 repeated unchecked derivations.  All 1,248-byte consumer outputs are
equal, so reuse is 2.09x faster including artifact creation.

The one-slot TGT -> SLB -> FND composition copies 7,530 field-cells per pass at
20.574 million cells/s and 0.329 effective GB/s, with exact full destination,
unchanged source, and a 2,496-byte four-box-array artifact.  Current canonical
unmasked same-level values and independent source boxes are exact.  Full
action tables, refinement geometry, PBC widening, payload fusion, dynamic
dispatch, and parallelism would broaden ownership without evidence;
optimization stops at the bounded affine artifact and unchecked fill.
