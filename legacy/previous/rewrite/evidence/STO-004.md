# STO-004 Evidence

## Boundary And Correctness

STO-004 owns one decision: the maximal dense refined primary prefix whose
ordered unique union of REL-001 source leaves fits caller capacity.  It owns
candidate-window sufficiency, first-discovery support order, promotion,
first-fit atomicity, maximality, and the exact one-primary progress maximum.
Forest/contact/balance/relation meaning, transfer slots, geometry, numerical
restriction/prolongation, scratch reach, payload, and execution scheduling
remain outside the capability.  The five-question decomposition result is
Green.

The independent Python-list reference and the Cython implementation agree on
duplicates, direction/source order, future-primary promotion, first and later
nonfit, suffix preservation, zero/end behavior, exact bounded/global maxima,
20 randomized balanced refined forests, and a plain valid representation with
more than the canonical 56-source bound.  A complete 209-leaf balanced refined
traversal gives identical naive and sliding selected arrays at every chunk.
Validation covers scalar ranges/overflow, array kinds, dtype/rank/layout/
writability, paired shapes, exact candidate-window length, overlap, counts,
active source ranges, trailing sentinels, precedence, read-only inputs, and
complete output atomicity including the fallback first-fit path.

The balanced `3x3x3` bound construction attains 57 selected slots for all 26
directions and 25 for faces.  On `data/weno509_sub_0000.dat`, the exact all-26
maximum is 53.  Every one of its 22,614 leaves has the same ordered all-26
support union as the current retained implementation.  This equality is
evidence for the currently supported complete direction set; REL-001 remains
the authority for mixed-contact meaning and direction subsets.

The independent stable-contract review approved the boundary before
implementation.  A separate implementation/evidence review rejected the first
checkpoint, then approved after bounded-memory isolation, exact trace
comparison, fallback-complexity correction, and focused validation additions.
The final runs pass 26 STO-focused tests, 146 producer/consumer integration
tests, and all 465 accumulated rewrite tests.

## Kernel And Memory

Correctness was frozen before replacing a repeated semantic rescan with a
fixed 56-ID stack fast path.  Inputs outside the balanced bound retain an exact
allocation-free repeated-scan fallback that is quadratic in active source
occurrences.  The canonical balanced path uses the fixed bound.  The planner
uses no hash, bitmap, global marker, or size-dependent internal scratch.  A
checked call retained 72 traced Python bytes and peaked at 1,136--1,232 bytes
across the measured capacities.

table only to isolate the planner kernel:

The exact maximum scan takes 4.74 ms.  A whole-tree REL materialization takes

implementation's retained connectivity, so it is rejected as the bounded
execution strategy.  The kernel-only precomputed planner table is 19,402,812
bytes of counts and source IDs and is reported separately from bounded memory.

## Immediate Composition And Scaling

The bounded sliding composition generates each REL row once, plans with the
producer-guaranteed unchecked kernel, compacts unaccepted lookahead, and
gathers every selected interior through STO-001.  The naive comparator performs
the same planning and gather but regenerates its complete candidate window per
chunk.  Exact chunks, selected totals, and primary/gather coverage are hard
gates.  Outside the timed loops, exact selected prefixes and all accepted
kind/mask/count/source arrays match for a 512-leaf trace at every measured
capacity; no digest or aggregate integrity proxy is used.

| 1,024 | 940,032 B | 1,630,592 B | 42,485 / 22,614 | 63.91 | 56.95 | -10.9% |

Sliding row amplification is exactly 1.0, while naive amplification falls from
11.275 to 1.879 as capacity grows.  The global comparator arrays are released
before every bounded trace/timing/allocation run.  PRI-001 fills candidate IDs
directly in the selected vector, so no `8*C` candidate temporary exists.  The
traced peak includes bounded REL/selected/gather arrays, the 180,912-byte
benchmark source, fixed controls, and overlap-safe compaction temporaries; only
168--384 bytes remain traced after a call.  At capacity 57 the sliding executor
moves 211 MB while compacting lookahead; at 1,024 it moves 18 MB.  A ring would need
either noncontiguous planner contracts or doubled relation storage, while a
fused REL/planner would recouple semantic owners and still has to preserve
accepted relation records for transfer.  Those are executor choices deferred
until the immediate numerical consumer exists.  The fixed-stack kernel and
bounded sliding composition materially improve the retained alternatives
without broadening STO-004, so optimization stops here.
