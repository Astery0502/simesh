# STO-004 Design: Balanced Refined Support Planning

## Problem

REL-001 supplies exact per-direction source leaf IDs, but bounded refined
consumers need a deterministic unique union for a maximal dense primary prefix.
This union cannot be inferred from current physical kinds, and restriction/
prolongation phases, weights, scratch, and values must remain downstream.

## Alternatives

A global `L*D` relation cache is retained state and costs 20.6 MB on the real
tree.  A fused forest/contact/relation/support kernel avoids relation arrays but
recouples FST/TOP/REL semantics and forces later transfer to recompute or re-emit
the accepted records.  Splitting union from greedy packing would require a
second materialized union/state boundary because overlap and promotion directly
determine how many primaries fit.

Use a pure planner over a bounded dense REL candidate window.  For selected
capacity `S`, exactly `min(S, remaining)` rows are sufficient to prove global
maximality: a rejection occurs in the window, all remaining rows reach stream
end, or accepting `S` primaries fills capacity by primary IDs alone.

A naive executor may regenerate rejected lookahead rows.  The retained composed
strategy is a sliding bounded REL window: drop accepted rows, keep lookahead,
and refill the same number at the tail.  Every relation row is then computed
once without changing the planner boundary or fusing REL.

## Decomposition Record

Responsibility: greedily plan the maximal dense refined primary prefix whose
unique union of REL-provided source leaves fits explicit selected capacity.

Owned semantic decisions: candidate-window length; dense PRI candidate order;
candidate/direction/source first-discovery order; unique union; primary prefix;
support promotion/order; greedy maximality/first-fit; suffix/end/atomicity; and
exact bounded-window one-primary maximum.

Explicitly non-owned decisions: FST/TOP contact discovery, balance, REL kinds/
masks/source meaning, relation cache policy, byte capacity choice, source-slot
mapping, geometry, physical transforms, transfer phase/weights/order/values,
coarse scratch/reach, payload/backend/cache/scheduling, periodicity, or 2D.

Inputs and outputs: first/leaf-count scalars; borrowed REL `uint8[C,D]` counts
and `int64[C,D,4]` sources; caller-owned writable `int64[S]` selected IDs; exact
primary/selected counts.  A helper returns one exact bounded-window maximum.
`D` may be zero/subset/repeated/reordered, but one complete traversal uses one
fixed REL direction order so discovery and its progress maximum remain coherent.

Mutation and ownership: relation inputs remain unchanged; all representation/
active-ID validation precedes selected mutation; first-fit errors are atomic;
success preserves suffix; nothing retained and no size-dependent scratch.

Access pattern / halo reach: metadata source union only.  It does not claim
that source interiors alone satisfy prolongation slope reach.

Independent reference or invariant: Python primary/support lists; exact union,
order, promotion, maximality, window proof, progress maximum, exactly-once
coverage; REL/common-lattice composition; current union comparison; real data.

Immediate producer and consumer: PRI supplies dense candidates, REL supplies
bounded source rows, and STO-001/003 gathers selected interiors.  Later transfer
planning consumes accepted REL rows and selected IDs but owns slot mapping and
all numerical decisions.

Kernel and composed measurement boundary: planner records/s, source scans/
insertions, chunks, amplification/utilization, window/output bytes, minimum
helper, fixed allocation, REL generation, naive versus sliding row
amplification, compaction/refill bytes, and selected gather composition.
REL metadata is additional to WSP payload/ID accounting; candidate IDs may
reuse the selected vector sequentially, otherwise their extra `8*C` is reported.

Five-question result: yes/yes/yes/yes/yes.  Union and prefix packing remain one
capacity-constrained policy; relation and transfer semantics stay separate.

## Performance Gate

Measure the pure planner against the list reference and a sliding REL+planner
composition on synthetic bound-achieving and WENO metadata.  Exact rows/IDs/
order and bounded bytes are hard gates.  Compare naive one-shot regeneration
with sliding reuse; investigate >10% composed regression and block reproduced
>20% regression absent a documented memory trade-off.  A fused on-demand REL
variant is considered only later if it materially beats sliding composition
while preserving accepted relation records needed downstream.
