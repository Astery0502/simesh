# MOR-001 Design: Dense Level-1 Morton Mapping

## Problem

Level-1 topology needs a stable global block order for every positive Cartesian
3D root-grid shape. The current implementation gets the right dense order for
supported sizes, but scans an enclosing power-of-two cube, allocates per cube
point, repeatedly compacts suffixes, and truncates coordinates to ten bits.

## Choices Considered

Sorting valid coordinates by arbitrary-precision Morton key is the clearest
independent reference, but costs `O(N log N)` time and `O(N)` scratch. Scanning
and decoding every key in an enclosing cube can be fast for full cubes but is
arbitrarily poor for slabs and lines. Computing each coordinate's dense rank
independently adds a logarithmic factor.

A recursive traversal of coordinate bits from most to least significant visits
children in Morton order and skips child origins outside the rectangular box.
It is proportional to valid leaves plus occupied prefixes, needs only bounded
C stack depth, and never constructs raw Morton codes or enclosing-cube scratch.

## Selected Direction

Keep sort-by-raw-key as the Python reference and use clipped recursive traversal
for Cython production. Expose only caller-owned dense forward and inverse
`int64` maps. Do not expose raw keys or preserve the current ten-bit limit.

Morton mapping is built once per level-1 grid. A raw-code scan measured modestly
faster for a full power-of-two cube but degraded sharply immediately above a
power-of-two boundary and on anisotropic grids, so a second production strategy
does not improve the runtime-memory-complexity trade-off.
