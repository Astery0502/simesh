# HAX-001 Design: Apply A Level-1 Same-Level Halo Plan

## Problem

HPL-001 separates direction/source-slot discovery and PBC-001 separates
physical coordinate/value rules, but HAL-002 still provides the only production
value application.  Its optimized kernel accepts topology and selected global
IDs, so relation planning and transfer cannot yet be substituted independently.

## Alternatives

Replacing HAL-002 outright with a caller-plan path would satisfy conceptual
decomposition but discard a measured faster fused loop.  Adding callbacks for
coordinate/value rules would violate the Cython hot-loop boundary.  A
payload-sized per-cell plan would make application branch-light but scale with
fields and halo volume.

Add a simple Cython executor over HPL's fixed `(primary,27)` plan.  It derives a
target's full direction from its storage coordinate, reads the planned source
slot, maps sibling axes directly, maps physical axes through PBC-001, loads one
source value, and applies physical transforms in x/y/z order.  It receives no
topology or global IDs.

Sibling mapping uses positive layer/offset arithmetic—lower `U-(L-q)`, upper
`L+(q-U)`—so valid coordinates near signed limits do not overflow an
intermediate.  Purely physical cells are valid HAL-001 results on entry and are
preserved when HPL supplies source `-1`.

Keep `fill_same_level_halos(...)` unchanged as the optimized aggregate wrapper.
Conformance tests compare HAX, the independent direct-cell reference, and the
fused wrapper.  Consumers may select the explicit path when plan reuse,
substitution, or refined composition matters; M0 keeps the faster path.

## Decomposition Record

Responsibility: apply an already established level-1 direction/source plan to
copy same-level values and compose explicit per-axis physical transforms.

Owned semantic decisions: direction-to-target cell mapping, sibling source
coordinate translation, source-slot read, primary-only mutation, support/
interior/pure-physical preservation, and fixed x/y/z application of PBC rules.

Explicitly non-owned decisions: topology/contact discovery, selected block
mapping, closure, plan construction, boundary mode meaning, chunk capacity,
field selection, allocation, refinement, periodicity, storage backend, and
scheduling.

Inputs and outputs: one caller-owned padded payload, interior triplets, HPL
source-slot/mask arrays, boundary modes, and normal slots; payload is mutated in
place only in planned same-level-dependent primary halo cells.

Mutation and ownership: payload exclusively borrowed writable; metadata
borrowed; no arrays retained or allocated; complete validation precedes writes.

Access pattern / halo reach: one-block same-level translation; allocated lower
and upper widths may not exceed the interior extent.  Operator-required reach
is external.

Independent reference or invariant: direct Python plan consumer; bitwise
comparison with fused HAL-002; preservation masks; special values and atomic
invalid-plan cases.

Immediate producer and consumer: HPL/PBC produce plan/rules; SAM-003 and
OPR-002 can consume completed primary payloads.  Existing INT-001 remains on
the fused wrapper until a planned executor is selected explicitly.

Kernel and composed measurement boundary: HAX values/s; HPL+HAX versus fused
HAL-002 kernel; gather+HAL-001+plan+HAX versus existing composed path; plan
bytes and allocation reported separately.

Five-question result: yes/yes/yes/yes/yes.  HAX owns value application only;
planning, numerical boundary meaning, storage, and scheduling are explicit
dependencies.

## Performance Gate

The simple planned path is not required to replace the fused default.  Measure
the existing 12 HAL-002 cases and named small/heavy controls.  A planned kernel
overhead up to 35% for total checked HPL+HAX versus fused HAL-002 is acceptable
when bitwise conformance, independent
substitution, and unchanged fused performance are demonstrated; larger stable
overhead is investigated before completion.  Report HAX apply-only separately.
Any default/fused median
regression above 10% is investigated and above 20% in two cases blocks.  HAX
must retain zero allocation; retained `243*P` plan bytes are external inputs.
