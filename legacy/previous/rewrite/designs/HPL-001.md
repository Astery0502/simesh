# HPL-001 Design: Level-1 Halo Relation Plan

## Problem

HAL-002 currently discovers diagonal source blocks, checks selected-slot
closure, maps blocks to slots, chooses physical axes, and transfers values in
one fused kernel.  Relation/source-slot planning can vary independently from
cell coordinate and value rules, and refined work must not add more relation
kinds to that dispatcher.

## Alternatives

A per-cell plan would make execution trivial but scales with payload volume and
duplicates the uniform block relation for every field/cell.  Six faces are too
small: M0 halo cells can cross edges and corners.  A retained global table for
all blocks ignores bounded selected-slot mappings and makes each chunk rebuild
global-to-local state.

A `(primary,27)` direction plan is the smallest complete level-1 artifact.
Each direction records one selected source slot and a three-bit physical-axis
mask.  It is independent of fields, halo widths, boundary modes, and payload
values.  The selected IDs supplied by STO-002 already bound its size.

## Selected Direction

Use the existing x-fast `3x3x3` direction index.  Walk crossed axes x, y, z.
A physical face contributes a mask bit and leaves the current block unchanged;
a sibling face advances the block.  If at least one sibling axis exists, map
the final block to its unique selected slot.  Center and purely physical
directions use source slot `-1` because HAL-001 already owns those cells.
The plan column is always the target cell's full outside direction, including
physical axes; it is not the reduced sibling-only displacement used inside the
pre-refinement HAL-002 implementation.

Expose a caller-buffered plan operation.  A tested variant also made the
optimized HAL-002 cell loop consume one fixed per-primary plan, but broad-halo
kernels regressed materially because the full-direction mask required an extra
axis pass.  Retain HAL-002's existing sibling-only stack lookup as the optimized
compatibility path and prove effective source/mask equivalence against the
explicit plan consumer.  The next production transfer boundary consumes the
caller-owned plan without changing HPL semantics.

## Decomposition Record

Responsibility: map each selected level-1 primary direction to an explicit
source slot and physical-axis mask.

Owned semantic decisions: direction indexing/order, non-periodic sibling walk,
physical mask bits, selected block-to-slot mapping, closure/uniqueness failure,
and plan output representation.

Explicitly non-owned decisions: target/source cell coordinates, boundary mode
or value transform, payload mutation, chunk capacity/selection, field choice,
refinement, periodicity, and execution scheduling.

Inputs and outputs: selected/global IDs, primary prefix, TOP-001 faces, and
caller-owned `(P,27)` slot/mask outputs.

Mutation and ownership: inputs borrowed; both outputs fully overwritten only
after validation; no state retained.

Access pattern / halo reach: metadata-only one-block `3x3x3` directions; no
field payload or numerical halo reach.

Independent reference or invariant: Python direction walk; exact mask/source
tables; closure failure; equivalence with the source relations used by the
existing direct-cell HAL-002 reference.

Immediate producer and consumer: STO-002/TOP-001 produce selected closure and
faces; an independent direct-cell consumer proves the plan is sufficient and
the next explicit production transfer boundary consumes it.  Retained HAL-002
is the optimized aggregate conformance comparator.

Kernel and composed measurement boundary: primary-directions/s and fixed
allocation; compare the refactored HAL-002 kernel and gather/physical/HAL
composition against the frozen baseline.

Five-question result: yes/yes/yes/yes/yes.  The planner owns topology/slot
planning only and has no storage, numerical, or scheduling policy.

## Performance Gate

Measure the existing 12-case HAL-002 standard profile before and after a
plan-consuming compatibility variant.  The hypothesis was neutral or improved
runtime from removing face-table branches inside the cell loop.  A reproducible
median regression above 10% is investigated; above 20% in two representative
kernel cases blocks retention absent a material complexity/memory benefit.  The
named regression cases include the small capacity-64/one-field/one-halo control
and heavy capacity-256/four-field/four-halo composition.  The tested variant
crossed the blocking kernel threshold on multiple broad-halo cases and was not
retained.  The public plan reports exact `243*P` retained bytes; the unchanged
compatibility wrapper continues to allocate nothing.
