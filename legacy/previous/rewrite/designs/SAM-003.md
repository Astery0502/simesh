# SAM-003 Design: Trilinear Level-1 Sampling

## Problem

SAM-003 must interpolate arbitrary Cartesian output centers from completed
HAL-002 primary workspaces while bounded chunks retain unique output ownership.
It needs an exact stencil/weight rule, one proven halo requirement, and a fixed
floating arithmetic tree without inheriting current block-window races.

## Alternatives

Selecting the two nearest global canonical centers by binary search is robust
but differs from the current center-relative arithmetic and can make required
reach harder to state on unusual rounded grids. Precomputing output-axis
indices and weights would accelerate repeated chunks but adds resolution-sized
scratch. Reusing current block windows preserves familiar arithmetic but gives
two blocks ownership at exact faces.

The selected design separates ownership from interpolation. SAM-002's canonical
highest-face rule chooses exactly one primary block. Within that block, the
current-style normalized coordinate uses the canonical GEO block lower face and
native spacing; floor gives two adjacent storage indices and a fractional
weight. Endpoint validation proves those indices lie in the interior plus one
lower/upper halo layer. This keeps tight FND reach `(1,1,1)` on both sides and
preserves current arithmetic on ordinary geometry while removing overlapping
writes.

Every call evaluates all eight values through a fixed z/y/x blend tree, even
when a weight is zero. This preserves IEEE NaN/infinity behavior and prevents an
optimizer from silently weakening halo requirements. The simple reference is
scalar and block-centric; the first Cython path reuses SAM-002 range and owner
helpers with no coordinate arrays or other resolution-sized state.

## Optimization Result

The retained loop inherits SAM-002's verified arithmetic owner candidate,
disables bounds checks only after full prevalidation, computes each axis
stencil outside the field loop, and keeps the required separately rounded blend
tree. Skipping zero-weight corners or contracting blends would change IEEE
behavior; cached axis arrays add resolution-sized state; block parallelism needs
an explicit unique-ID execution policy; and fusing halo fill would duplicate
already validated responsibilities. None improves the present runtime-memory-
complexity trade-off without weakening a contract, so those variants are
deferred to INT-001 composition evidence.
