# RSL-001 Design: Accepted Refined Relation Source-Slot Resolution

## Problem

REL-001 records global source leaf IDs, while bounded numerical buffers are
addressed by local STO-004 selected slots.  Later transfer planning needs one
exact identity conversion but must independently decide which relation kinds,
directions, target boxes, and numerical actions matter.

## Alternatives

A generic query-vector mapper would force the only consumer to flatten and
rebuild REL active/trailing structure.  A compact active-only output needs
offsets and naturally couples to kind/action extraction.  In-place conversion
would destroy REL evidence used by other consumers.  A retained leaf-sized
inverse map or hash violates the bounded/no-hash design.

Use one caller-buffered operation over accepted REL rows.  It maps every active
global source to the unique selected slot and writes exact `-1` for inactive
columns.  It does not receive or interpret kinds/masks.  A later action planner
may compare a compact representation after it owns the filtering decision.

## Decomposition Record

Responsibility: convert active accepted-REL global source leaf IDs to exact
positions in one unique STO-selected vector while preserving tensor shape and
inactive sentinels.

Owned decisions: selected uniqueness/range; active/trailing REL representation;
first matching local slot; missing-source failure; exact `[P,D,4]` output;
validation, atomicity, and ownership.

Explicitly non-owned decisions: relation kind or physical mask; direction
meaning; action filtering/extraction; primary target box or child phase;
same-level/restriction/prolongation choice; geometry/reach; RST/PRL values;
workspace/payload; boundary rules; backend; scheduling; periodicity; or 2D.

Inputs and output: `leaf_count`, selected `int64[S]`, accepted REL
`uint8[P,D]` counts and `int64[P,D,4]` sources, and caller-owned
`int64[P,D,4]` slots.  Accepted row `p` corresponds upstream to primary
selected slot `p`, so `P <= S` even when `D` is zero; RSL does not otherwise
interpret that provenance.

Mutation and ownership: all representation/membership checks precede output
mutation; only the complete slot tensor is overwritten; inputs are unchanged;
nothing is retained; the kernel uses no heap or size-dependent scratch.

Access pattern: deterministic row/direction/source order and linear selected
lookup.  Repeated source IDs map repeatedly to the same slot.  No source query
occurs for inactive columns.

Independent reference and invariants: Python list uniqueness and `.index`;
exact roundtrip `selected[source_slots] == source_leaf_ids` on active columns;
exact trailing sentinels; arbitrary selected permutations; missing/duplicate/
range atomicity; random balanced REL/STO windows; HPL reduction; WENO bounded
traversal; FINER and COARSER consumer probes without action policy.

Immediate producer and consumer: STO-004 supplies selected IDs and accepted
REL rows.  The next refined transfer action planner consumes kinds, masks,
counts, and RSL slots while independently choosing actions/targets/workspace.

Kernel and composed measurement boundary: active lookups/s, tensor entries/s,
linear comparisons, selected/primary/direction/count scaling, checked/unchecked
time, fixed allocation, exact output bytes, list-reference ratio, WENO bounded
capacities, and one-plan versus repeated lookup in an immediate action scan.

Five-question result: yes/yes/yes/yes/yes.  The shaped mapper owns one identity
decision, is independently substitutable/measurable, mutates one explicit
artifact, and contains no numerical, storage, framework, or scheduling policy.

## Performance Gate

Use synthetic worst/mixed lookup positions and real WENO accepted windows at
capacities 57/64/128/256/512/1024.  Exact mappings, first missing-source
failure, input preservation, and `32*P*D` output bytes are hard gates.

Compare allocation-free linear production with the list reference and with a
consumer that otherwise repeats slot lookup.  Investigate >10% and block a
reproduced >20% composed regression absent a documented memory/complexity
benefit.  Do not introduce hashes, dense inverse maps, sorting, compact offsets,
or parallelism before the next action planner demonstrates a material need.
