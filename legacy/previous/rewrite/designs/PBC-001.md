# PBC-001 Design: Per-Axis Physical Boundary Rules

## Problem

HAL-001 and HAL-002 independently implement the same per-axis physical source
coordinate and value transformations.  HAL-002 is Red partly because mixed
physical/sibling cells rediscover semantics already owned by HAL-001.  The rule
must be independently available without inserting Python calls into hot loops
or changing the optimized aggregate entrypoints.

## Alternatives

A full-cell physical plan would also decide which axes are physical and in what
order they compose, coupling the rule back to topology and the executor.  A
runtime callable would be substitutable but unacceptable inside cell loops.
Keeping only prose/reference formulas leaves production kernels free to drift.

Use two scalar operations under one per-axis boundary-rule capability: one maps
an outside target index to an interior source index, and one transforms the
loaded binary64 value.  Their Cython inline forms are shared by HAL-001 and
HAL-002; validated Python entrypoints and an independent Python reference make
the semantics directly testable.  Face eligibility and multi-axis order remain
caller decisions.

Reflection is expressed through a positive layer/offset, never direct
`2*face-target` arithmetic, so valid mappings adjacent to `INT64_MAX` cannot
overflow an intermediate.  Public validation uses Python integer arithmetic;
the shared C inline receives only validated or aggregate-array-safe values.

## Decomposition Record

Responsibility: define the coordinate and value meaning of one explicit
Cartesian physical boundary face/mode.

Owned semantic decisions: continuous/symmetric/antisymmetric/no-inflow source
mapping and value behavior, face side, reflected-depth validity, exact `+0.0`
clipping, and scalar type/error rules.

Explicitly non-owned decisions: whether a face is physical, topology, selected
source block/slot, multi-axis composition order, field-name/normal inference,
payload traversal/mutation, allocation, scheduling, refinement, 2D, and
periodicity.

Inputs and outputs: scalar target/face/mode/value/field metadata plus FND
interior triplets; one source index or one binary64 value is returned.

Mutation and ownership: all inputs borrowed and unchanged; no output buffer or
retained state.

Access pattern / halo reach: one already identified outside coordinate; no
payload access and no decision about allocated or required halo width.

Independent reference or invariant: direct formulas for every face/mode/layer,
bitwise IEEE value cases, randomized scalar comparison, and unchanged HAL-001/
HAL-002 aggregate references.

Immediate producer and consumer: explicit topology/adapter metadata supplies a
physical face and mode; HAL-001 and HAL-002 consume the inline rules, while the
next plan-consuming transfer boundary uses the public semantics as its
reference.

Kernel and composed measurement boundary: isolated Python scalar timing is
descriptive only; meaningful cost is the HAL-001 kernel and HAL-002 mixed
composition before/after inline extraction.

Five-question result: yes/yes/yes/composed/yes.  Coordinate and value phases are
separate functions of one boundary mode meaning; topology and execution remain
outside.

## Performance Gate

Freeze HAL-001 `8/1/64` all/mixed and `16/4/32` all-physical cases plus the
HAL-002 capacity-256/four-field/halo-four case.  Cython helpers must inline.  A
same-runner median regression above 10% is investigated; above 20% in two
representative cases blocks completion.  No allocation or retained memory may
be added to either aggregate path.  Record both the HAL-002 direct kernel and
its gather/physical/same-level composed median so composition cannot hide a
cell-loop regression.
