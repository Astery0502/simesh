# GEO-001 Design: Level-1 Cartesian Geometry

## Problem

Level-1 consumers need block bounds and cell spacing without carrying the
current mesh object's repeated nine-column `rnode` state. Geometry must also
work for bounded selections whose slot order differs from global block IDs.

## Choices Considered

A full-N bounds table is simple but forces `48*N` bytes resident when a chunk
needs only a few rows. Selected `block_ids` with slot-aligned output subsume the
full case and preserve the FND-001 slot/ID distinction. Repeating the identical
spacing per block adds another `24*N` bytes without information.

Current block arithmetic computes each lower face and then adds a rounded block
width. Adjacent blocks can therefore disagree at their shared face by a few
ulps, and reconstructing a global cell center from block-local lower bounds can
depend on the chosen block partition. Preserving this operation order enables
bitwise comparison but weakens composition.

## Selected Direction

Compute one global spacing triplet. Define every block face from its global
integer cell-face index, snapping index zero and the final domain index to the
supplied bounds. The same integer face always produces the same binary64 value,
so sibling faces are bit-identical across chunks. Define centers from global
cell indices rather than from accumulated block-local coordinates.

Expose only selected block bounds `(slot, lower/upper, x/y/z)` and global
spacing. Do not materialize cell-center arrays. Exact integer placement remains
available from block coordinate times block cell count and is consumed directly
by SAM-001.
