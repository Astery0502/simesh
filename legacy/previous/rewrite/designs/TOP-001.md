# TOP-001 Design: Level-1 Face Topology

## Problem

M0 consumers need exact non-periodic block adjacency and physical-face
classification. The current forest stores a 27-direction cube with separate
type and one-based index tables because its halo routine copies faces, edges,
and corners in one pass. That storage also contains a redundant center and
refinement relations that M0 cannot produce.

## Choices Considered

A full 27-entry ID table makes diagonal lookup direct but costs `216*N` bytes
with rewrite `int64` IDs and embeds halo strategy into topology. An on-demand
coordinate lookup stores no adjacency but repeats the six most common relations
and gives physical-face consumers no compact surface. Six face IDs cost `48*N`
bytes and reconstruct every M0 edge/corner through commuting orthogonal steps.

A separate kind or boundary table is also redundant at level 1: an in-domain
entry is always same-level and `-1` can unambiguously identify a physical face.

## Selected Direction

Store six columns in low-before-high axis order
`(xlo, xhi, ylo, yhi, zlo, zhi)`. Use zero-based global Morton IDs and exact
sentinel `-1`. Validate the supplied MOR-001 maps with an allocation-free
inverse-consistency pass before mutating caller-owned output.

Refined relation kinds, periodic wrapping, diagonal materialization, geometry,
and halo-copy order remain outside TOP-001. HAL-002 will measure staged face
exchange or derived diagonal lookup when payload movement exists.
